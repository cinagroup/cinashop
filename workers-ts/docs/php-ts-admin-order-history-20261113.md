# 管理员订单操作记录：PHP → TypeScript（2026-11-13）

本批基于 `f326a3a3142c36b72e2effb5908fc3d7db0f77fe`，补齐 PHP 订单记录读取与现代后台详情入口。整项迁移仍未完成。

## PHP 合同与新流程

固定 PHP 参考仍为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。路由、共同 Order 控制器、StoreOrderStatus service/DAO/model、时区配置、旧记录组件及 order API 共八份源文件逐字节与固定 Git 对象一致。

- `GET /adminapi/order/status/:id` 和 `/api/admin/order/status/:id` 返回原五字段数组：`id,oid,change_type,change_message,change_time`。原 PHP service 并未使用 DAO 的可选分页参数，旧页面的分页控件也已注释；兼容接口因此忽略分页查询，不静默改为第一页。
- 记录按 `change_time ASC` 排列，同秒增加 `id ASC` 的稳定次序。保留未知／空操作类型、原始消息和空白；不会因不能识别类型而丢弃记录。命名 `Asia/Shanghai` 格式化时间，保留 epoch 0、负秒以及历史夏令时。
- `:id` 是规范内部主键。数字订单号不会回退为主键，前导零、指数、越界或对象身份拒绝。兼容接口按精确 oid 保留已删除、孤儿历史的读取；没有记录的 oid 返回空数组，不复活订单。
- 现代 `GET /adminapi/order/history/:id` 及 `/api/admin/order/history/:id` 另返回分页数据。内部主键与 `order_id` 必须同时匹配现有订单；不拼接支付父单、履约子单、兄弟或其他用户的记录，不重解释财务代际。
- 新版默认每页 20 条，上限 100；页码允许到 10000，因此选择每页 1 条也能遍历完整的 10000 条准入记录；后续页必须带服务端版本。版本以 HMAC 绑定完整 JWT 主体、精确订单身份、所有记录的字段指纹及页大小。记录插入（包括迟到的早期记录）、更新、删除或主体／页大小替换都会拒绝旧版本，并要求刷新；不会在变化中的列表上继续翻页而漏项或重复。
- 兼容完整数组上限为 2000 条／2 MiB，新版完整记录集上限为 10000 条／8 MiB。超过边界明确报错，不返回截断前缀；兼容边界内不可一次返回的记录可在新版分页查看。更大的历史仍须单独核对，不能把这些有界读取解释成无限制 PHP 运行时等价。

## 权限与读取一致性

四条路由在鉴权之前设置 private/no-store。沿现有独立 Admin LOGIN 和实际 JWT 入口，service 还在真实只读、可重复读事务内核对完整平台管理员、密码版本、有效角色、历史角色来源和 `order.view`；只读角色可查看，匿名、Supplier、停用、已撤权和密码变更拒绝。事务遵从调用方更短的 statement timeout，不把只读授权用于写入。

记录总数、完整版本和当前页使用同一数据库快照。并发 peer 在指纹查询后插入时，当次仍返回原完整快照，下一次刷新才看到新状态。真实 SELECT-only LOGIN 也可读取，事务结束恢复原只读及超时设置。现代查询只选少量订单身份字段，不下载历史购买 JSON、大字段或金融凭据；没有新 DDL、引导、权限计划扩张或外部服务调用。

## 后台详情

订单详情展示操作记录、原类型和上海时间，增加完整分页及刷新。消息以转义文本展示并保留换行，不执行历史 HTML。切换订单或会话会终止旧读取；记录变化、读取失败或撤权时清除旧结果，仅显式刷新重载。分页不自动拼接新状态，不自动重发写请求。
