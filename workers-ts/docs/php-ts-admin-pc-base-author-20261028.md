# PC 基础配置与真实商城消费者迁移

日期：2026-10-28。固定 PHP 提交：`8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。

本轮在已验收的微信开放平台切片之后，迁移 PC 基础配置的 13 个字段，并接通实际 PC 首页、品牌、页脚和手机购买界面。旧开放平台 AppID/Secret 仍由独立领域管理。全局 PHP→TypeScript 迁移继续进行。

## 字段与兼容行为

| 字段 | 写入与消费 |
| --- | --- |
| `pc_logo` | 安全 HTTP、HTTPS、站内图片或平台素材引用；实际商城品牌读取独立安全投影。 |
| `bast_number`、`first_number` | 正安全整数；保留并实际呈现超过 100 的数量，使用成熟商品资格、会员价格和促销装饰。 |
| `product_phone_buy_url` | 1 为公众号 H5，2 为小程序；读取最新配置选择既有代码生成分支。 |
| `contact_number` | 保留固定 PHP 的可选电话规则与原字符串。 |
| `company_address`、`copyright` | 保留原文，实际页脚使用最新配置。 |
| `seo_title` | 固定 PHP 中仅存储；替换必填，不赋予新的页面标题优先级。 |
| `site_keywords`、`site_description` | 保留原文与换行；PC 元信息使用 DOM 节点及内容的比较恢复，保护商品页元信息。 |
| `links_open`、`links_list` | 开关不删除存储列表；名称与地址必填，小数排序值和提交行顺序保留。 |
| `filing_list` | 图标、名称、地址可空；保留小数排序及历史 JSON 键顺序。 |

每项提交完整的 `keep` 或 `replace` 意图。`keep` 不返送历史原始值，不重新验证或改写缺失、无效、私有历史原值；公开渲染另外检查其安全性。替换后的序列化值遵守原数据库字符容量，HTTP 保存为受限 UTF-8 和重复键拒绝的完整信封。预览签名不能成为新的素材引用。

页脚遵守固定 PHP 的排序方向：排序数值降序、URL 字节升序，再按原始键顺序进行 PHP 数组比较。为处理历史不对称比较，使用明确标注来源的 PHP 8.0.5 Zend 排序调用顺序；平台素材先排序、后签名。仓库 Docker 标签不作为实测 PHP 引擎版本回执，没有声称执行过 PHP CLI 差分测试。

## 权限、保存与恢复

`pc_base.view` 绑定原菜单 1361 的完整身份；`pc_base.manage` 同时要求原共享保存菜单 315。活跃管理员、会话版本、角色与菜单在事务内重新核实，复制菜单或直接声明权限不能代替原身份。Base、Open 与 PC 的共享历史保存 URL 只接受恰好一个完整的领域信封，并由选中的服务重新授权。

专用接口在 `/adminapi` 和 `/api/admin` 两个挂载点提供：

- `GET/POST /config/pc`；历史 `GET /setting/config/edit_new_build/pc` 仍可进入。
- `GET /config/pc/operations/:operationId` 与 `POST .../resolve`，供本人读取回执及明确封存未受理请求。
- `GET /config/pc/attachment-categories`、`GET /config/pc/attachment-options`，只返回平台范围的栅格素材。

独立的 `admin_pc_base_operation` 升级检查精确目录、约束、不可变回执和运行权限。写事务按现有管理员/权限协议取得锁，再核对最新修订、固定配置行集合和所有规范素材 ID。替换只对选中的值执行带行版本条件的更新，缺失项按固定 PHP 元数据插入；完整回读和回执同事务提交。提交后失去响应不会触发自动重发。本人恢复仍检查活跃身份和期限，权限撤销不重新授予写权限。

通用配置批处理和通用 CRUD 提前隔离这 13 个键；混合批次整批拒绝。图库只读使用 PC 管理权限，未放宽通用附件权限。浏览器待核对记录仅含版本、领域、管理员和请求 UUID，不保存草稿、修订、签名预览或凭证。

## 实际消费者

PC 首页改为消费真实 `/index` 精品与新品数组。数据库读取在一个只读可重复读事务内，100 条分块保留既有资格、会员价格、商品图片签名及促销装饰。整个首页共用 5 秒单调时钟和 8 MiB 中间结果 UTF-8 预算，最终响应也受限；超限整次失败，不返回成功前缀，不改写配置数量。并行读取退场后再结束事务。普通商品分页保持既有边界。

公司信息、商品手机码和会员码直接读取新的数据库快照。历史安全 HTTP 图片保持原 URL；相对 LOGO 使用经过路径匹配的服务端 `logoUrl`，支持与手机站不同源。管理页提供完整列表和专用素材选择器。PC 页眉、页脚、首页、元信息和商品详情手机购买均已接入实际组件，路由、身份变化及卸载会退休在途读取和旧回调。

商品详情中的手机购买入口使用固定 PHP 的 `/pages/goods_details/index?id=...` 路径；小程序分支继续由既有提供者生成二维码。普通购物车、结算和支付流程保持原接口。
