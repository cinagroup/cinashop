## 用户操作与接口

`/assets` 当前页可选择1至50张图片，移动至合法子分类或根目录，单张图片可修改显示名称。分类读取使用现有 `GET /adminapi/file/category?all=1&file_type=1`，子分类显示完整祖先路径，`pid=0`明确表示根目录。

- `PUT /adminapi/file/file/do_move` 提交冻结的 `{ids,pid}`，响应必须匹配全部选定 ID 和目标分类。
- `PUT /adminapi/file/file/update/:id` 仅提交 `{real_name}`，响应必须匹配原 ID 和名称。
- 页面读取要求 `attachment.view`，写入同时要求 `attachment.manage`；服务端继续使用真实 Admin 身份中间件和管理权限。
- 写入时冻结选择和名称；失败或不完整回执保留草稿，先重新读取核对再允许重试。重命名弹窗内提供可访问的重新读取按钮。
- 切换账号、分类、页码、查询或离开页面会清空原范围并废弃迟到响应。取消 HTTP 请求不代表已经提交的服务端事务被撤销。

数据库移动先取得分类创建／删除使用的同一范围事务锁，再按 ID 顺序锁定全部附件，核对原分类和目标分类，并验证完整 `UPDATE RETURNING` 身份和目标。任一缺失或不匹配均整批回滚。重命名锁定选定附件并核对名称回执。两种操作保留 canonical URL 和 R2 对象，不发送对象清理队列。
