# 买家逐商品评价与图片发布迁移验收

本批把 PC 订单详情和 UniApp 订单评价页接入同一份买家评价协议。用户分别选择商品、给总体及商品/服务/物流评分、填写独立文字、上传最多8张图片，再提交当前商品。另一件商品未提交的草稿在订单与商品版本未变化时保留。赠品只读，不参与评价完成条件；最后一件必评商品成功后才完成订单评价。

## 身份与事务

新增 `/api/order/reviews/:uni` 返回当前用户指定公开订单号的版本化只读结果；`/api/reply/submit?view=buyer` 与 `/api/order/comment?view=buyer` 严格绑定账号、订单主键/公开号、商品行主键/unique及凭据修订。旧请求不带 `view=buyer` 时保留原协议。没有以订单主键猜测公开订单号的回退。

提交复用现有订单/商品评价事务、产品星级刷新、非赠品完成判断和评价抽奖资格授予。加锁后重新核对有效账号与密码版本，事务结束前复核订单、商品快照和图片资料。新增账号、素材及父订单锁使用 NOWAIT，避免把新的等待边加入原订单/产品锁图。已证明的真实订单行锁等待中，账号撤销和快照变化均被拒绝。触发器修改订单快照或素材元数据时，评价、完成记录和星级变更一起回滚。

评价读取使用有界快照：最多200条商品与评价，限制商品快照/文字/图片资料字节容量，批量读取和签名图片元数据。归属冲突、多个评价关联、损坏数据和响应身份不符均停止显示并要求重新读取。

## 图片及异常结果

图片通过现有买家 `/api/upload/image` 上传。草稿预览使用本机地址，写入评价只允许规范 `/api/assets/:id`，禁止把带签名的预览地址作为持久权限。私有图片必须属于当前评价者，并符合普通图片的类型、模块、文件路径和 MIME 元数据。公开评价读取基于持久评价者 UID 和公开状态核验图片；隐藏、外人素材和错误元数据不产生新的公开签名。旧 HTTP/static 图片及 UID0 虚拟评价语义保留。

页面离开、隐藏、路由或账号变化均清除旧私有草稿。提交回执丢失后不会自动再次 POST；用户刷新评价状态，以实际数据库中已保存的评价恢复其余商品。待处理标记可在同会话页面重建时继续阻止重发，保存内容只包括必要标识。图片上传失败须重新选择或明确忽略后才能提交文字。

小程序/App 的评价图片显示和预览仅为签名 API 素材补上 API 来源地址；本机上传预览和持久化素材编号保持原样。链接与图片凭据解析不依赖浏览器 URL 构造器，已通过不提供 URL/URLSearchParams 的跨平台适配层用例。

UniApp 注册真实 PHP 原始入口 `/pages/goods/goods_comment_con/index?uni=...&unique=...`，严格转换为新页面的公开订单号和已验证商品选择。拒绝重复、未知或冲突参数。已完成订单可查看已保存评价。
