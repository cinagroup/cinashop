# Membership provider admission and historical proof continuation

Closing SQL membership admission prevents new purchases and card redemption.
It does not invalidate an existing order or an authentic provider receipt.
The owner-session configuration suite now treats an arbitrary transaction
string passed to the local settlement helper as unverified: both providers
must leave the order, rights, wallet and status unchanged. The original wrong
amount assertion remains. The original eighteen-case source and its two failed
positive assertions remain archived with immutable source and outcome hashes.

The positive obligation is exercised through the registered HTTP signature
verifiers and actual callback Queue on independently commissioned PG16 LOGINs.
After a real membership order is created, the native WeChat and Alipay cases
close the SQL flag and supply the contradictory cached enabled flag. Fresh
purchase UUIDs and valid unused cards must be refused without writes. Authentic
signed callbacks must still settle the saved order once, retain wallet and
rights accounting, and author the existing four notification channels. The
same signed HTTP message, Queue delivery and paid-order request must replay
without a second grant or notice. Configuration and the local KV adapter are
restored even when a precondition fails. Provider I/O uses test-owned local
transports and keys; these cases do not certify a production payment.

Historical source proofs are separate from current runtime execution. Their
original fixtures, failed reports and assertions remain evidence of the old
versions. The new closed view must verify complete current source identities,
reverse only explicit literal edits, and verify the complete predecessor.
Current route sets and the freshly generated Admin AST report also require
complete identities. The source envelope freezes all TypeScript and Vue files
under both Admin API and page directories:321 actual builder inputs plus eight
supplemental page models. Those eight files are additional raw-source guards;
they are not claimed to affect the AST report. Unknown edits, substituted
historical live files and unreviewed report or route changes must fail. Source projections never wrap
the service or callback execution used by the native acceptance tests.

Validation results belong to the specific frozen candidate recorded under
`.cache/php-ts-member-contract-repair`. Earlier passing groups or secret scans
are not relabelled as proof of this changed candidate. This work does not upload
the legacy PHP repository, commission production roles, invoke real providers,
change the cloud source-supply architecture or deploy anything. Full migration
and cloud CI completion remain independent requirements.
