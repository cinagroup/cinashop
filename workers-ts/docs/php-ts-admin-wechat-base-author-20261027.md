本批提供公众号基础设置的完整本地编辑和实际运行时消费。整体迁移继续处于 active。

## 已实现的边界

- `wechat_base.view/manage` 独立权限；PHP 页面种子 1362 精确元组仅授予查看，只有同时选中精确的通用保存种子 315 才推导管理。精确 315 保留原有普通配置管理权限，但它单独不产生公众号基础设置写权限；复制行、元数据漂移和未登记的 GET 不产生本域权限。
- 两套管理 API 前缀及原 GET/POST 入口均落到同一九键契约。请求必须带当前完整来源版本、UUIDv4、完整公开值、三个明确密钥意图和确认。禁止借旧通用保存入口写其他键；通用配置列表、单项读取及批量写入对本九键和回调权威标志全部关闭，包括通用配置管理和零层级管理员，防止绕过专用状态回显及版本契约。
- 密钥只回显已配置/格式状态；保留、替换、清空分别处理。浏览器持久记录仅含版本、操作者和请求 UUID。保存同事务写不可变签名回执；相同请求重放不二次写入。404 仍视为未知，只能显式封存未受理 UUID，迟到保存随后被拒绝。
- 撤销角色授权后，活跃原账号仍能读取本人回执及封存本人缺失请求；禁用账号、密码轮换、过期会话和其他账号不能恢复。
- 官方凭据每次从平台配置新鲜读取；同一快照的 AppID/Secret 使用 HMAC 命名缓存。一般配置缓存不读取或回填这两项凭据。保存后的普通配置缓存清理失败单独报告并支持原回执重试。
- 官方通知在发出 HTTP 前遇到已确认的凭据缺失、运行时签名缺失或配置容量错误，恢复为 `WechatProviderConfigurationError`，投递账本进入 `DEAD`。SQL/连接故障仍保留 `UNKNOWN`；提供商明确拒绝 invalid-token 后再读到密钥清空时，不再次发送并进入 `DEAD`。配置新鲜读取和故障分类同时保留。
- 公众号数据库回调必须明确启用。任何非空部署回调绑定仍优先采用安全模式，局部/错误绑定不降级。数据库明文、兼容、安全三模式进入原持久事件/发件箱/回复流水线；兼容模式密文严格验证 `msg_signature` 和 AppID。小程序保持独立部署绑定。
- 永久二维码结果在短事务中与此作者通过专用共享/独占 advisory 锁协调，提交前重新比对完整凭据快照，二维码与频道图片同事务落库。该协议只协调已审查的业务写入口，不宣称约束维护 SQL。App 对配置仍只有 SELECT。
- 旧永久码没有生成账号证据。已存在该类 ticket/url 时拒绝改变 AppID，保留历史；跨账号显式重建仍是后继工作，不能把缓存隔离当作整个账号迁移完成。
