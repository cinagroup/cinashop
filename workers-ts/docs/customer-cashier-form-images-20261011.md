# 普通 customer 次卡收银图片表单（2026-10-11，本地候选）

本批在现有单商品、单规格次卡收银流程中接入图片字段。普通 UserJWT 经营账号先选择真实次卡与会员或游客，再建立绑定原创建编号的表单准备；图片上传核对后，固定引用随完整下单内容冻结。下单及现金／零元付款仍分别确认，实际原订单可回读已消费的表单和私有图片预览。

本文件记录实现合同和实际验证，详细执行结果以同批 [审计报告](../audit/customer-cashier-form-images-20261011.json) 为准。没有执行生产 DDL、GRANT、部署、提交或推送。

## 合同与原 PHP 范围

旧普通购买页 `view/uniapp/pages/goods/order_confirm/index.vue` 的图片字段、必填校验及 `custom_form` 提交可作为表单行为参考；旧 `StoreOrderCreateServices.php` 保存表单 JSON。旧手机收银 `CreateOrder.php` 和 `CashierOrderServices.php` 没有完整图片会话、字节摘要或上传结果恢复合同。新增接口承接普通 customer 次卡流程，不能据此关闭旧完整五页代客、其他商品或支付渠道迁移。

以下六个接口均在 `/api/mobile/work/cashier/second-card` 下使用普通 UserJWT，不借 Admin token 或泛素材上传接口：

| 方法与路径 | 实际合同 |
| --- | --- |
| POST `/form-sessions` | 原未来创建 UUID、购买人、选品、数量、经营范围、真实表单准备 |
| GET `/form-sessions/:key` | 当前登录原账号核对原准备、取消、冻结、消费状态 |
| POST `/form-sessions/:key/cancel` | 明确确认后的创建前取消；与草稿冻结共用原创建锁 |
| POST `/form-sessions/:key/images` | 独立原上传 UUID；一个文件及一个 metadata；实际字节 SHA-256／size／字段归属 |
| GET `/form-images/:key` | 原上传预约或真实已保存元数据；缺回执保持未确认 |
| POST `/form-sessions/:key/previews` | 核对原会话固定引用后，生成内存中的短期签名预览 |

原准备和每张图片请求在网络提交前分别耐久保存编号及完整摘要内容。结果不明先查询原编号；恢复上传须重选同一字节内容，仍使用原 UUID。不同文件不能替换原请求。已经核对的创建前准备可以明确取消；完整金融意图已经保存或服务器已冻结后，使用原收银创建恢复流程，不能靠取消图片换一个下单编号。

## 数据与事务边界

两张新持久表 `cashier_second_card_form_session_v1`、`cashier_second_card_form_upload_v1` 保存会话及上传证明。身份、原意图和作用域不可更新；会话只允许 active→cancelled／frozen→consumed，上传只允许 reserved→stored。JSON 字节摘要、状态所需列、唯一原编号及附件、原会话外键均由固定 PG16 协议约束。

上传先短事务预约，再在 SQL 事务外写确定的私有 R2 对象，最后短事务重验账号、经营资格、选品、模板和原会话状态，原子写入附件及已保存证明。未知 COMMIT 回复和并发同编号恢复保留对象；只有确认不可逆取消的会话，晚到上传才尝试对象补偿，删除失败可进入现有对象清理队列。没有增加自动过期清理，也不声称所有孤立对象已清理。

冻结与取消使用同一原创建 advisory lock。创建只接受该会话、该字段、该经营账号保存的 canonical `/api/assets/:id` 引用。业务创建事务核对实际表单收集行，在原创建来源之后记录 consumed 订单及原 snapshot／collection 字节证明，最后再次按数据库时钟检查固定有效期。晚写入等待跨过截止时间时，全单回滚。

详情回读重新核对 genuine 创建来源、原订单身份、实际表单收集和附件，再剥离服务端保留证明，返回原组件值及单独预览。Admin ID 与 customer UID 数值相同不形成授权：旧 Admin 代客读取和付款排除真实 customer 收银来源，普通买家／旧代客图片读取不能签署新 module 6 图片。

## 数据库就绪与平台边界

安装器只供显式维护连接使用，运行请求只读固定 catalog 与权限，不自动安装或修复。新权限计划继承原收银必需能力，仅增加两表 SELECT／INSERT、列级状态 UPDATE、固定函数 EXECUTE；禁止 PUBLIC、可转授、更宽 UPDATE／DELETE／TRUNCATE、可达 owner／超级角色等权限。当前独立 PG16.15 固定 catalog 指纹为 `434908c11ec8e19c848e3558aca2cb78641ab86dff82bd0fa0e68265d69eda5d`。

两表未安装时，无图旧收银仍可用。安装后需最小 SELECT 才能核对原取消／冻结事实；缺读权限明确撤回原收银写就绪，不能跳过证明。表可读而图片写权限尚未验收时，没有图片会话的无图旧链仍可用，图片新写入关闭。已有图片会话和图片订单始终要求完整原证明。

前端区分图片写就绪与原收银能力，可选图片为空时仍可走无图流程。一次文件最多 10 MiB，仅 JPEG／PNG／WebP／GIF；当前本机图片待核对队列总计最多 100 条（包括会话），达到上限时提交前阻断。签名 URL、临时文件路径、图片字节和 base64 不进入持久记录。系统原字段及答案受现有表单与请求容量限制。

原生选图采用显式、最多 60 秒且绑定当前账号／会话／经营范围的单次暂离许可，选图返回可见页面后才上传。普通隐藏、卸载、二次隐藏、超时或账号切换清除当前资料和预览，保留原耐久请求；隐藏调用不能取得新的写权限或卡住恢复状态。

H5 读取当前同源 blob，微信读取所选本机文件并前置大小核对；App 使用 HTML5+ FileReader 的有界 data URL 解码，再统一按真实字节识别图片及摘要。官方 [Uni 文件系统文档](https://uniapp.dcloud.net.cn/api/file/getFileSystemManager.html) 与 [HTML5+ IO 文档](https://www.html5plus.org/doc/zh_cn/io.html) 支持这个平台分支选择。App 编译和模拟事件不能替代真机上传验收；浏览器的合成接口也不能替代实际 Worker／Hyperdrive／R2 联调。
