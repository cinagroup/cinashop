# 普通商品短 SKU 的 PostgreSQL 报价兼容

基于 `69d0a77f53b7e4efb74c7f6e7332972b640152bb`，分支 `codex/ordinary-short-sku-quote`。真实 PostgreSQL `char(8)` 会把 `short7` 读为带两位尾空格的值。既有权威促销报价按去填充身份索引，购物车与统一建单却传入带填充值，导致普通商品报价被拒绝；旧购物车复合索引也可能遗漏真实 SKU，显示不同的商品基准价。本批修复普通商品这一缺口，整体 PHP→TS 迁移保持 active。

## 合同

只有数据库已选中并核对归属、类型和未退役状态的普通 SKU，进入促销/赠品报价时使用去尾空格身份。旧购物车复合键仍绑定基础商品，保留购物车键带尾空格或不带尾空格的兼容。真实 SKU 单价 10 元与商品基准价 17 元故意不同，防止回退价掩盖错误。新普通订单行与冻结快照使用同一数据库所选 SKU 身份，使原收费凭据与最终实物凭据继续严格一致；原始目录值、库存比较和活动商品快照规则不改。

没有放宽购物车预算仅接受 `isNew=0` 可复用篮子的规则。直接购买独立验证加购、列表、报价、确认及下单，预算仍拒绝该作用域且无写入。确认的版本绑定、促销与赠品锁等待后的重算、改价拒绝和事务回滚保持。成功订单按原收据重放直接返回同一订单，SQL/KV、发号调用不增加，也不会重写历史根。旧原购、最终实物原购、取消补偿 SQL 与 DAO 均逐字保留，无新增迁移或运行期权限。

## 验证

最终 631 项独立用例通过，包含 574 项单位、56 项原生 PostgreSQL、1 项 Browser；22 项新增。成熟预算 HTTP 在两种执行环境重复通过的 48 项不重复计数；单位命令内 269 项原生条件跳过与所有早期失败聚合均排除。两套完整 Worker 类型项目和最终源指纹见[同名审计账本](../audit/php-ts-ordinary-short-sku-20261020.json)。所有重型验证经过共享串行锁，Vitest 单 worker。

新增 13 项原生用例覆盖可复用篮子与直接购买、旧篮子的有/无尾空格键、8 位 SKU 对照、错归属/错活动类型/已退役拒绝、确认后实际改价回滚、真实折扣及赠品、真实行锁等待后的有效重算或拒绝。成功路径验证实际幂等重放、原购及实物凭据、财务分摊、库存和积分。8 项 runner 边界扩展验证只允许明确的原生路径与单一浏览器别名，拒绝混用和过滤方式。

Browser 使用 Cua 内置浏览器后台模式和固定 `127.0.0.1:40751`，复用逐字不变的 344 份实际 H5 构建。明确标注的本机合成会话连接真实 App/JWT 与专属完整 PG16 数据库；实际详情、SKU 数量选择、加购和结算完成 20 元→一次 503 后清空禁用→生产「重新获取报价」恢复 20 元→专属维护夹具将真实 SKU 改为 12.50 后重新报价 25 元四阶段。28 次业务请求中，26 次读取/确认逐次核对全 283 表、229 序列不变；商品访问统计和一次实际加购分列。无实际创建订单、付款、provider 或 R2 写入，库存和积分保持。页面控制台 0 error、三条既有 router 导入弃用 warning；确认请求 0，临时标签已关闭，用户标签保留，全局安全设置未改。当前可连接通道为内置浏览器，外部扩展没有出现在本轮连接清单。

浏览器 v1 在捕获有效阶段前主动结束，短暂加购处理中提示随后已转入真实 20 元确认页，不能据此声称业务失败；v2 暴露本机外壳账号变量插值遗漏，零有效阶段，修正后 v3 完整通过。原生初轮确实复现生产拒绝；后续两轮为金额字符串测试预期及直接意图预算作用域的测试修正，不修改生产合同。失败轮、通过数、源码漂移限定及所有自有集群清理分别列入账本。

## 仍待迁移

本批限定普通 `type=0` 商品，不声称全部活动/预售短 SKU 已逐类验收。没有启用终身累计限购，`PurchaseQuotaHistory.incomplete` 保持 true；可信账户历史起点、导入/删除与 UID 再用、无界历史计量和统一并发额度占用/释放仍开放。实际 provider、生产角色权限、部署和真实设备也不在本机验收范围。

保留用户选定的已恢复 PHP `/api/get_script` 兼容行为和修订退役审计。原 88/404 复选行逐字保持。本批仅发布 GitHub 草稿，不执行合并或部署；CI 按自身提交状态记录。
