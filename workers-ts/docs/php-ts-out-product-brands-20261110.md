# Out 商品品牌路径迁移

本批接通已有平台实物商品 Out 保存入口的品牌路径，以及商品详情的品牌回读。固定 PHP `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 Out `Product::productSave` 接受 `brand_id` 数组；`StoreProductServices` 把完整路径保存为 `brand_com`，末级保存为 `brand_id`；`StoreProductRelationServices::saveRelation` 为品牌建立 type=2、status=1 的关系行。来源仅记录文件、行范围及 Git blob/SHA256，不上传旧 PHP 原文。

保存仍须提交原有完整实物商品正文与 UUID-v4 `Idempotency-Key`。品牌字段的合同如下：

| 输入 | 行为 |
| --- | --- |
| 省略 `brand_id` | 保留当前品牌标量与关系，不读取品牌目录；保留旧请求的归一化摘要形状。 |
| `brand_id: [30,31]` 或规范数字字符串路径 | 完整根到末级路径，最多16级、序列化不超过64字符；每级须为当前未删除、显示且 store_id=0 的平台品牌。 |
| `brand_id: []` | 显式清除品牌两列及该商品 type=2 关系，其余非分类关联保留。 |
| 空值、标量、重复编号、缺父级、逆序、跨门店、隐藏或删除品牌 | 拒绝，不写业务结果或回执。 |

省略不等同于清除，是沿用现有 TS/Supplier 保存合同的明确兼容边界；固定 PHP 控制器会把省略默认化为空数组。客户端只修改其他字段时应省略品牌。显式空数组现在具有新的写入语义并进入摘要，不能复用升级前曾被忽略的空数组请求或其它品牌意图的幂等键。

品牌意图绑定已有 Out 账号、操作、商品和归一化请求摘要。已提交的相同请求先重放原回执，即使后来品牌隐藏，也不重新执行目录准入或重写商品；不同路径不能借用同一键。新请求按数字 ID 顺序锁定所选品牌，使用 SHARE NOWAIT，继承已有 Out 商品、SKU、购物车及回执锁顺序。品牌标量、精确 type=2 行和原回执同事务提交；在品牌作者及最终回执 INSERT 之后分别强制约束并核对标量、关系和其他历史关联的 xmin。最后再核对所选品牌；干扰或后续失败整笔回滚。

商品详情在一个 REPEATABLE READ、READ ONLY 事务内读取。HTTP `brand_id` 恢复为路径数组，`brand_com` 保留存储值；`brand_selection.brand_id/brand_com` 保留物理标量及原串，`consistent/available` 分别表示存储关联一致性和当前目录可选性。坏历史不会从当前目录猜测修复，亦不阻断省略品牌的普通保存。Out 原有上下架会同步关系状态，详情接受其合法0/1历史状态。

不新增 schema、迁移或运行权限。原 App 计划的品牌 SELECT 与仅 id 列 UPDATE 足以锁行，品牌目录实质改写仍不允许。原有 SKU 身份、已扣库存、销量、订单/账单和非分类/品牌关系保留；其它尚未支持的 Out 商品能力继续独立拒绝。

验收采用完整既有 Out/checkout 文件，包含真实下单后的品牌更新、同键双连接创建、真实受限 LOGIN、跨主体拒绝、锁竞争、最终回执失败/成功触发器干扰、只读回读及并发替换下的真实可重复读快照。Out HTTP 测试主体为合成账号，SQL 会话和数据库是真实独立 PG16；不把它外推为生产账号授权或完整角色安装验收。完整兼容、两套类型与秘密扫描结果记录于同名机器记录和本轮完成回执；未部署，未调用实际提供方，整体迁移及远端旧 PHP 检出仍单列开放。
