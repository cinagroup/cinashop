## 管理规则

双 Admin 前缀各注册10项操作：GET 列表、详情、商品/品牌/商品标签/用户标签选项；POST创建、PUT更新、PATCH启停、DELETE软删除。独立 `nth_discount.view/manage` 仅承接配对的旧1397（`marketing-discount-pieces_discount` + 列表路径）、1401（`marketing-discount-add_pieces` + 创建路径）；邻近折扣和通用活动不代授。

材料固定平台 `type=1,store_id=0,pid=0,promotions_type=2`，单根规则，`promotions_cate=1,threshold_type=2,discount_type=2`。`n_piece_n_discount=1` 第二件半价固定门槛2、百分比50；`2` 买一送一固定2、0；`3` 自定义正整数门槛1..99999999、整数百分比0..100。旧UI自定义输入最低1%，PHP校验容许0%，新页完整回显并明确支持0%的材料，不悄悄修改历史定义。

列表恢复名称、启停、三种规则类型筛选、15条分页、商品数、规则与支付订单/客户/实付/优惠统计。表单按上海整日选择（00:00:00至23:59:59），编辑既有活动保留原秒级时刻直到重新选日期；支持付后用户标签（最多100个）、叠加1/3/5、全部/具体父商品及SKU/品牌/商品标签范围，跨页选品确认与取消。排除SKU为旧UI隐藏合同的明确扩展。第N件页面没有每人限购控件，现有type2报价不消费限购；该管理接口不接受新增限购字段，写入固定0，历史非零保留问题提示并拒绝启用。

只有可见、已审核、未删除平台根商品及未退役唯一SKU可选；失效身份保持问题提示并阻断保存/启用，不自动降级为空范围。UUID请求键与revision保护写入和未知结果防重复，命名按nth_discount隔离；软删除同type2一层派生，保留异类型及历史关系。

## 实际消费

PHP消费者汇总所有参与商品/SKU的件数，达到门槛后取参与商品当前价格最便宜的一件，只优惠一次。第二件半价按最便宜单价的节省截断到分；买一送一是这同一单件价格优惠，不新增赠品库存，更多件不会循环赠送或打折。普通购物车、确认、创建复用同一真实报价规则，会员价与双向促销叠加沿已有竞争合同，优惠券仅对允许范围叠加。

三种普通促销管理共用现有 `time_discount_catalog/platform_type_1` advisory锁，管理独占、建单共享；等待后以数据库时钟重新报价，规则/状态改变使旧确认失效。门店派生和旧type2子行不成为额外优惠层级。精确行分段、活动分配及台账进入建单，付后才授予仍有效的平台标签；履约拆单、逐次退款报价/补偿/物化使用精确剩余分段并保持分币守恒。

销售统计按原始已支付根pid=0/-1计一次，履约子单不重复。优先活动台账，新版快照回退经完整校验再按匹配活动精确归属，旧无版本证据沿历史边界；数据库聚合与32行小批快照避免在Worker加载全部订单/用户。
