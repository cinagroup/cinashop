# Out 次卡商品

固定来源为 PHP `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 `Product::productSave` 与 `StoreProductServices::saveData/syncStock`。本批接通平台次卡 `product_type=4` 的创建、编辑、上下架、详情和库存同步，沿用 Out 请求幂等、SKU 身份和既有商品关联规则。次卡仅允许单规格单 SKU，复用后台对核销次数和永久、购买后天数、固定区间三种有效期的校验；兼容旧编辑器的 `days`、`section_time`，日期按上海时区解释。次卡统一到店核销，禁用邮费、运费模板和预售；拒绝卡密、跨履约类型修改以及存在履约类型冲突或退役 SKU 的编辑。编辑保留库存，不增删 SKU。

库存按条码匹配平台实物、手工虚拟和次卡 SKU，跨类型重复条码拒绝猜测；次卡库存、规则、流水和幂等回执在事务末尾校验。商品作者还校验规格、核销规则、快照、关联和回执，并在约束导致状态变化时回滚。普通次卡结算确认绑定核销有效期，在库存更新时再次检查规则，防止确认后或等待 SKU 锁期间变更有效期；收银次卡沿用原有确认摘要。已有未完成的普通次卡确认凭据因摘要变更需要重新确认。

本批不调用真实支付、短信或第三方服务，不部署、不上传旧 PHP。卡密和优惠券商品的 Out 作者仍待迁移。

上批 GitHub CI 的两个 Worker 分片在测试前无法检出固定旧 PHP 提交，远端返回 `not our ref`；本地验收使用同一已核对提交，不能代替该 CI 结果。

固定源码验收：221项单元测试、276项真实 PostgreSQL 测试全部通过，无跳过。数据库覆盖stock 19项、author 57项、fulfillment 43项、cashier 17项、checkout 71项、associations 69项；受限 App LOGIN 使用既有权限计划创建并同步次卡，隔离数据库均零残留并停止。两组类型检查覆盖原配置全部4340个根文件，编译选项相同；独立运行时类型检查通过。单次完整项目检查在此前两次达到既定8 GiB堆上限，因此保持上限并采用完整覆盖的分组。

独立的既有私有 schema 核销成熟场景在基线和本批均有2项失败（通知合同校验无法通过）；它不是本批通过项，日志摘要与哈希保留在验收记录中。普通应用完整 schema 的履约和收银回归另行执行。
