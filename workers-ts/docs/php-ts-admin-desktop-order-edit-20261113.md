# 管理员桌面六字段订单编辑：PHP → TypeScript（2026-11-13）

本批在 `519260a51eb3a7aeeb23308a8477db58a59252d8` 上补齐管理员桌面订单编辑。整项 PHP → TypeScript 迁移仍未完成。

## 已实现的合同

- 固定 PHP 参考为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。核对 `app/common/controller/Order.php`、`app/services/order/StoreOrderServices.php::updateForm/updateOrder` 、管理员订单验证器和 `crmeb/services/FormBuilder.php`；四份本地文件与固定参考逐字节相同，未修改或上传 PHP 仓库。
- `GET /adminapi/order/edit/:id` 返回“修改订单”的六条 FormBuilder 规则（数字控件值为 number，保留原有最大值）、独立的精确字符串原值、`PUT /order/update/:id` 和版本摘要；`PUT /adminapi/order/update/:id` 保存。`/api/admin/order/edit/:id`、`/api/admin/order/update/:id` 使用同一处理器。`:id` 始终是内部主键；数字订单号不会被当成另一个主键。
- 旧客户端只提交 `order_id,total_price,total_postage,pay_postage,pay_price,gain_integral` 即可。四个禁用字段必须与当前 SQL 原值一致，服务端不会据其改写订单号、原价或邮费。数值控件可直接提交合法大金额（包含 `1234567890.12`）；按十进制表示校验后以整数分计算，保留“当前实付 + 累计改价差额”的原始基准，支持降价、加价及零金额。
- 赠送积分改变时按原购买赠分权重分配；原赠分全部为零则按非赠品数量分配，最后一个有效 SQL 行承接整数余数。修改后的积分为有界非负整数，与 PHP 表单的 `precision(0)` 一致；原始购买字段、商品单位赠分、财务版本及其他 SQL 行字段保持不变。
- 只改金额时，未修改的历史负数/小数赠分和邮费按原值保留。大字段历史订单不必为改价改写购买 JSON。七个订单大字段及完整 cart SQL 状态用长度、NULL 和 SHA256 证明；无变化重试不写业务表、回执、日志或通知，也不推进序列。
- GET 使用真实只读可重复读事务授权。共用授权新增只读入口，明确拒绝在普通读写事务使用；原写入入口保持权限决策锁。PUT 在同一事务内验证完整 JWT 身份、平台域和实时 `order.manage`，锁定权限与业务边界，并在尾部复查。
- 新 UI 在未付款根订单详情提供“修改订单”，只允许编辑实付金额、赠送积分；会提交读出的版本。保存结果未知、版本过期或权限变化后阻止再次提交旧表单，要求重新载入当前订单；不会自动重发保存请求。关闭或成功保存后刷新订单详情，切换账号/退出/离开页面使旧请求失效。

## 财务与持久来源

- 新增可选 `admin_order_edit_operation_v1`（管理员六字段回执）和 `admin_order_gain_partition_v1`（旧 PHP 已编辑积分的子代来源），分别使用 `admin-unpaid-gain-edit-v1` 与 `admin-order-gain-partition-v1`。既有 Supplier 与管理员移动改价的不可变 v1 合同不变；新增表允许真实平台订单的 `supplier_id=0`。
- 原生 PG16 规范约束指纹分别为 `7813617eaded298688743c7091a195cf0901f47cf0c08dfa8f8d10204960ab7f`、`3231f485dbbe2eac7b17672eedc55244c336d174adc35483a341b8e813cd6708`。完整目录检查覆盖列、约束、索引、触发器、函数、所有者和 ACL。UPDATE/DELETE/TRUNCATE 均保持不可变保护。
- `installAdminOrderEditRuntime` 仅供现有 PG16 owner 维护事务显式调用，须指定独立受限 Admin 和全部财务 LOGIN。只有 Admin 可追加根编辑回执，其他角色只能读；命名财务角色可读、追加子代凭据。已存在但不完整的对象或缺失权限会拒绝，不自动修复。没有加入默认引导、ORM 表组或 HTTP 安装；基础权限计划保持原字节。
- 共用解析器同时检查 Supplier、移动管理员改价、桌面管理员编辑三套受保护账本；UUID 跨域冲突拒绝，不让可变 outbox 选择权限来源。收银编辑链逐代反推金额、积分、状态和购买行哈希，支持角色交替编辑，且从不重写原始收银购买来源。
- 旧 PHP 积分标记只能由对应版本的不可变回执或完整子代凭据授权；JSON 标记、声称的金额上限或序列化的证明对象不构成授权。平台零供应商编号亦须通过实际付款与退款物化后的来源证明。
- 付款发起证据与编辑共用边界；有付款发起记录时拒绝编辑。积分修改拒绝已支付、取消、已拆分、已有售后或不完整财务快照。写入行积分、根金额、PHP `order_edit` 状态、引用式通知和完整回执在同一事务完成，触发延迟约束后逐字节复查，任何晚到 SQL 变化都会回滚。
- 通知保留 PHP 的短信意图和用户站内信，未增加微信推送。旧事件即使金额后来相同也不会重新成为有效通知；消费与重放依赖实际最新状态和受保护回执。
