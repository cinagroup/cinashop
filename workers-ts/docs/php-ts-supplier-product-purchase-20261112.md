# Supplier 付费会员购买资格与全款预售

本批接通供应商商品的付费会员专属限制、预售起止时间和结束后发货天数。付费会员购买限制独立于会员价格开关；没有配置会员折扣的有效会员仍可按原价购买。覆盖当前 Supplier 编辑器既有的实物、卡密/固定内容、手工虚拟三类商品（0、1、3），不把预售作者限制为仅实物。

## 旧版依据

固定 PHP 提交为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。`supplier/product/StoreProduct::save` 接收 `is_vip_product`、`is_presale_product`、`presale_time`、`presale_day`，经 `StoreProductServices::saveData` 写入供应商商品。公共服务将预售时间转换为整数秒，并检查新开始时间。`StoreCartServices` 的普通商品分支检查登录买家的付费会员资格和预售时段，未据商品类型将预售限制为仅实物。旧 `StoreOrderDeliveryServices` 保留预售结束前不得发货的规则。

旧 Supplier 页面部分配置为注释状态，本批依据实际启用的保存 API 和购买/履约服务完成现代作者入口，不声称旧页面已启用这些注释控件。五份固定旧文件的完整身份与 SHA256 见同名审计清单。

## 作者合同

- `is_vip_product` 明确 0/1 时关闭/开启专属限制；兼容数字、字符串及布尔回显。省略保留原值，新建省略使用默认值。与 `is_sub` 中的会员价选项分别处理。
- 预售沿用现有实际运行的时间规范化与计划函数，接受合法北京时间、明确 UTC 或整数秒，保持原 Out 模块字节不变。显式开启或修改时段要求完整有序的起止时间；锁定商品后及所有后续等待结束后，以 PostgreSQL 墙上时钟再次检查新开始时间。
- 已开始或已结束的历史时段在省略时保留。只修改发货天数不重新提交时段、不要求旧开始时间重新进入未来。显式关闭清空起止时间；发货天数只在明确提供时修改。
- 显式购买/预售意图要求当前 Supplier 管理权限，复用分类范围锁、产品写锁、既定超时和保存后待审下架规则。全部作者和延迟约束执行后，重新核对当前作者、实际所有权、商品类型、审核状态和全部购买/预售字段；篡改或等待后时间过期时整体回滚。
- 详情增加闭合版本化 `purchase_selection`。前端分别维护读取状态及四类修改意图；缺失旧读取状态时禁用配置且省略写入。保存剔除读取元数据及旧版顶层回显字段，再只加入明确修改的字段，避免自动重发过期时段或将回显当作关闭意图。
- 复制继续使用原可信完整复制协议，保留来源的隐藏购买/预售条件，复制页不发送新普通作者意图。共用 Supplier 规范化及物理包装函数、复制三模块、Out 商品服务/预售函数、结算/付款/交付消费者、数据库架构、权限计划、CI 和原生运行器均未改动。

## 原生业务验收

新增用例完整追加在已有允许的 Supplier 推荐图原生文件末尾，保留上一批包含 54 项用例的完整文件原始字节前缀，不增加运行器准入或扩大 600 秒文件预算。作者覆盖三个履约类型的启用、读取、省略保留和关闭，既有时段的天数修改，权限/所有权/格式拒绝，延迟触发器修改会员标志/时段/归属/当前作者的整体回滚，以及作者延迟后以最终数据库时钟拒绝过期开始时间。

四个完整生命周期使用全部 185 项迁移、283 张表的隔离架构，以及现有 commissioning 和支付安装器配置的真实独立非所有者 APP/ADMIN LOGIN。真实当前 App 的 Supplier、平台审核、买家 JWT 中间件均参与。JWT 在本地依实际合成账号密码版本签发，不声称覆盖公共登录和凭据签发。

前三个生命周期分别验证实物、固定内容卡密和手工虚拟预售；第四个验证非预售的普通会员专属手工虚拟商品。预售目录隐藏匿名/非会员商品，有效永久会员可见；真实商品详情、购物车、确认、订单创建、余额付款、Supplier 人工发货及买家收货均使用 HTTP。订单号 Durable Object 和 Queue 是有限本地桩；实际订单创建、SQL 余额扣款、支付任务与履约事务没有替换为模拟成功。

未开始预售拒绝加入，开始后非会员和过期会员仍拒绝；有效会员按 10.00 元下单，重复创建返回同一订单且只分配一次订单号，重复余额付款不再扣款，余额实际从 100.00 变为 90.00。支付任务消费及重放核对一次性结果。

付款后以当前实际库存关闭商品会员/预售开关，旧订单完整规格快照仍保存原开始/结束时间、7 天发货承诺和会员专属标记。实物和手工虚拟 HTTP 在原结束时间前拒绝发货；固定内容由持久化到期任务在同一边界自动交付，提前处理延期、重复处理不重复交付。所有类型在原结束时点之后实际交付并经买家 HTTP 收货，不因当前商品已关闭预售而提前交付，也不额外等待 7 天。关闭资格限制、重新审核后，真实非会员 HTTP 重新加入成功。

上述卡密全 HTTP 生命周期使用固定内容模式。一次性卡密模式的 Supplier 预售作者在既有卡密商品上验证，实际分配/到期重放和权限回归由原有完整预售套件覆盖；不冒称一条新全 HTTP 链覆盖两种模式。普通商品详情包含既有访问统计后台任务，夹具提供 Worker ExecutionContext 并等待这些任务，不宣称详情 GET 全部零写。

## 前端验收

真实 Vite 页面为 `http://127.0.0.1:41056/products/80/edit`。桌面 1440×1000、移动 390×844，另测缺失 `purchase_selection` 的旧响应。因 `Browser plugin not available`，使用现有 Playwright 1.62.1 和已安装 Chrome；API 为有限 localhost 响应，浏览器登录为合成会话，代理明确指向关闭的本地端口。

流程为启用会员购买限制和预售，填写北京时间区间与 7 天发货承诺，保存并重读；仅修改天数为 8，确认请求不带资格开关、预售开关或起止时间；再单独关闭两开关，保存并确认回显关闭。旧响应的配置禁用且保存省略全部四个新意图字段。逐场景核对 URL、标题、非空内容、覆盖层、控制台、保存请求、回显和截图；浏览器证据与真实后端鉴权证据分开报告。

前期真实交互发现回显数据携带顶层旧作者字段时，通用表单 spread 会再次发送旧时段，已修正表单过滤和预览响应。Playwright 的原生 datetime-local 输入改用浏览器接受的分钟格式，服务端提交仍精确为北京时间对应的整数秒。新增商品详情测试起初缺少 Worker ExecutionContext，导致测试宿主 500；补齐平台上下文并等待真实后台任务后通过，未放宽实际产品错误边界。类型检查另发现外租户夹具键名错误，已改用真实外租户 `other` 账号 JWT，核对拒绝与零写入后重新冻结执行全部最终检查。
