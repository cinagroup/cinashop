# 结算发票申请

PC 与 UniApp 结算页支持选择当前账号的个人/企业普通发票或专用发票抬头、分页、刷新、管理及明确选择不开发票。页面展示申请时完整资料，包括银行账号前导零；选择不写入持久存储，只在未确认订单日志中保存抬头 ID 和修订值。页面隐藏、账号或路由变化、503、错误账号响应都会清除已读私有资料；原来要求开票的选择失效时阻止静默改成不开发票。

结算报价及服务器不可变回执绑定抬头 ID、修订值与普通/专用开关；创建事务在现有库存、优惠、积分和账号核验内重新读取并共享锁定抬头，使用既有快照复制逻辑保存一份未支付申请和数据库 created 证据。事务核对实际证据完整内容、订单、账号、模板、金额和存储保护；失败回滚全部订单资源。未新增 schema、权限或外部 Queue。原始 PHP 的最终 create 才传 invoice_id 的调用继续支持；新版带修订值的选择必须匹配带发票绑定的报价。已存在订单的同键重试先返回既有订单，不读后来删除/修改的抬头，也不补写发票。

支付沿用现有支付迁移，仅把申请标为已支付；实际开票仍由既有商家流程处理。隔离本机余额用例验证一次扣款、26/30 元两个供应商子单的完整专票快照，以及原主单创建证据不变；没有连接支付供应商、发送短信、实际开票或生产部署。取消订单沿用已有软删除行为，发票和不可变证据保留，买家入口继续拒绝已删除订单。
