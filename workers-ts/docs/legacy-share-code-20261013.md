## Provider, cache and callback behavior

Network destinations are fixed: `https://api.weixin.qq.com` token/create/unlimited-code APIs and `https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=...`. Redirects fail closed. Every fetch has a real overall 10-second deadline covering headers and streamed bytes, explicit abort/cancel, cancellation of a late body even when an injected fetch ignores its signal, a 64 KiB JSON limit and a 1 MiB actual PNG/JPEG/GIF limit. Website encoding uses the existing QR library, not an external QR website.

New generic mini/official methods take the expected AppID from the authoritative SQL descriptor. A stale `CONFIG_KV` AppID is rejected before provider access. Official access-token refresh repeats this check; mini generation retains the same validated AppID/secret through its bounded refresh. A committed SQL AppID change during image generation prevents artifact publication at the final descriptor recheck. Existing product/channel methods retain their inherited signatures and behavior.

The cache uses the already migrated `cache(key,result,expire_time,add_time)` table. The only changed keys are module-owned `lsc:<HMAC28>` indexes and `lshare:<opaque24>` artifacts, both within the inherited 32-character key limit. Documents bind descriptor, scene, images, known ticket, TTL, lease and state with purpose-separated HMAC. Temporary targets expire after 30 days; configured `spread_share_forever=1` uses an actual permanent `QR_LIMIT_STR_SCENE` request only for authenticated type -1, with no provider expiry field. Other official requests use `QR_STR_SCENE`, 30-day expiry and signed `ls:` scenes; naked UID scenes are not restored.

Short advisory-lock transactions claim a bounded pending lease, checkpoint known ticket/images, and publish one complete artifact with a lease fence. All snapshots finish before provider I/O; rechecks precede publication and response. A retry after an unknown provider result retains the exact opaque scene. A checkpointed known ticket is reused without a second create call. The provider itself offers no request idempotency key, so an unobserved successful ticket-create response cannot be claimed as exactly-once externally. Both resulting tickets would still reference the same controlled opaque target.

Images are delivered by `GET /api/share/code/image/:token/:channel?expires&signature`, with a maximum 900-second capability. Signature validation happens before quota. Every read repeats current target/config checks and returns genuine raster bytes with private/no-store and nosniff. Current account, owner-domain or target changes invalidate old artifacts, including permanent targets; a fresh generation is required.

The controller fails closed without actual `TOKEN_BUCKET`. It consumes 30/minute per HMAC Cloudflare source-address key and 300/minute globally; raw address and forwarding headers do not enter durable keys. Arguments, mandatory identity and image signature validation happen before consuming quota. Quota denial prevents provider calls.

Authenticated official callback resolution recognizes only MAC-valid, unexpired stored scenes whose actual ticket matches the cache document. It serves a controlled landing news reply, never raw private code. The signed public referral adapter verifies that same ticket/scene and current descriptor, resolves the actual subscriber via existing openid mapping, and invokes existing `UserFinanceService.bindSpread`. Its mature cycle checks, permanent binding, friendship audit, referral-lottery and agent-level registration effects remain in force; callback retries do not overwrite an established relationship.
