# H5 社区作者主页与原帖编辑

恢复 PHP `discoverUser` 的作者资料、本人作品／赞过、关键词与分页、50 字简介编辑、关注和计数入口，并接通 `discoverCreate?id=` 的原帖编辑。作者能查看审核状态及拒绝原因，对自己的图文或视频原帖修改、移除关联、取消或确认删除。

新增非底部标签路由 `/pages/discover/workspace`，复用社区页面组件。UniApp 不允许 `navigateTo` 进入底部标签页，因此作者、旧创建／编辑／详情链接及商品晒单入口统一进入该路由。前后端共享旧作者与编辑链接解析，区分作者编号和帖子编号，拒绝重复或非法编号，丢弃无关参数。当前注册页面为 133 个；历史账本的 132 个页面及哈希仍按当时快照验证，旧链接的 `partial_replacement` 状态保留。

编辑先重新读取原帖并核对本人身份，恢复原始附件引用、图集、视频封面、话题及商品。预览使用签名地址，保存使用规范引用；移除时显式提交空值或空数组。当前不可用的历史关联保留为可移除占位项，避免编辑时静默丢失。提交修改沿用现有审核规则；失败或迟到的原帖读取不能变成新增帖子，结果未确认时锁住提交，通过主动刷新读回结果。

后端作者筛选增加类型约束，避免相同数字编号的管理员私有帖子进入普通用户的本人作品。平台作者编号 0 可以精确筛选，旧的未指定类型查询合同保持。编辑和删除继续使用现有服务的归属检查、事务与锁后重验。删除确认和取消关注使用页面内操作，未增加浏览器验收确认请求。

验证包括 518 项单元、71 项 H5 运行时、15 项原生 PostgreSQL 16、1 项后台浏览器测试。扣除 6 项 API／路由用例的原生重复执行，共 599 项独立用例，其中 25 项新增。两套 Worker 类型项目及 H5 完整类型检查和构建通过；首次 H5 检查发现提取后的提交参数接口不满足请求层字典类型，改为等价的对象类型别名后复检通过，失败记录保留。完整命令记录见[机器验收记录](../audit/php-ts-community-author-20261020.json)。

后台浏览器实际运行十二阶段，共 41 次应用请求、5 次写入：简介、图集修改、视频修改、精确删除、另一账号关注。视频修改已提交数据库后，测试外壳只将浏览器回执替换为 503；页面锁定并主动刷新恢复，编辑 POST 仅一次。取消删除未发送 DELETE，确认仅软删除指定帖子及其评论；另一账号看不到待审核作品和作者编辑控件。390 像素框架内无横向溢出，有滚动条时内容宽度为 375 像素。控制台收集到两条既有 vue-router 导入警告，没有应用错误。

浏览器验收使用合成账号、来源历史、隔离原生 PG16、内存 R2 和导航外壳，社区业务请求通过实际应用、JWT、ORM。切换合成账号前重载外壳，以重新建立应用会话；直接给相同 iframe 地址赋值不会重载。此流程不代表真实登录 UI、生产存储、完整购买流程、小程序或 App 真机验收。全页截图后定位恢复按钮遇到浏览器自动滚动偏差，重新观察并点击可见按钮完成，没有代调业务接口。

内置浏览器连接正常，外部 Chrome 扩展未出现在连接列表，不据此推断安装状态。额外验收确认请求为 0，临时标签页已关闭，两座自有 PG16 均确认停止，数据和日志保留。已恢复的 `/api/get_script` 行为和历史审计正文保持，整体 PHP → TypeScript 迁移继续。
