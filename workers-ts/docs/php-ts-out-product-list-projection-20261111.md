# Out 商品列表旧版投影

固定来源为 PHP 提交 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 `Product::productList`、`StoreProductServices::searchList/getProductList`、商品模型的字段访问器与关联，及分类名称方法。旧列表取商品原始行，并预载类型0规格、绑定类型0描述，再转换金额、分类名称和平台商品标签名称。本批在上一批筛选基础上恢复这些字段：价格、会员价、市场价、邮费、成本和赠送积分转换为旧列表数字；销量为真实销量、会员价为原存储值；模型的轮播图、自定义表单、商品参数、用户及商品标签、保障和配送方式使用对应旧格式。SKU 的金额保留数据库字符串，`attrValue` 包含当前类型0规格，TS 特有的退役规格放入 `retired_attr_value` 并保留退役状态，避免旧客户端把历史身份当成可购买规格。原有卡片销量、会员价和标签保留为 `card_sales`、`card_vip_price` 和 `store_label_cards`。

列表、数量及所有扩展读取处于同一 REPEATABLE READ 只读事务，预先在数据库聚合估算原始行和字段大小，完整读取或明确拒绝；不截断结果。最大原始读取及响应各4 MiB，关联集合最多10000条。商品图片和 SKU 图片继续按既有所属方验证并签名，描述复用商品详情的附件引用规范化规则；不读取虚拟卡号或卡密。列表响应设置 `private, no-store`。保留现有 Out 令牌与接口授权、筛选和分页，不修改商城前台查询。

这批没有部署、上传旧 PHP 或调用实际外部服务。整体 PHP 到 TypeScript 迁移仍未完成；远端 Worker CI 仍需以实际运行结果为准。

固定源码验收：113项单元测试和55项真实 PostgreSQL 测试通过，均无跳过；原生测试包括44项购买与 Out 列表、8项商城分类和3项商城促销，隔离数据库均零残留并停止。运行时类型检查通过。单次完整项目类型检查两次达到既定8 GiB堆上限而中止；保持同样编译选项，将原配置全部4,337个根文件分为两组，源码和脚本两组均完整包含，2,439个测试根文件分布在两组，校验并集与原配置完全一致，两组均通过。初次分组的配置位置导致依赖解析失败、随后发现并修正的类型错误及最终结果均保留在本地验收记录中。
