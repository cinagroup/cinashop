# 付费会员功能两键配置合同（2026-09-28，本地候选）

旧 `/admin/user/setup_user` 的“付费会员”tab 只有 `member_card_status`（付费会员启用）和 `svip_price_status`（旧文案“付费会员价展示”）两个可编辑开关，关闭前者时旧页隐藏后者但保存仍保留原值。本批独立 `/config/paid-membership` 承接这两个键，不编辑套餐、权益、卡批次、会员资格、期限、订单或支付流水。`member_price_status` 在旧页面无启用控件且当前 Worker 无消费者，不能为了凑齐同页字段而增加无效开关。

| 合同 | 行为 |
| --- | --- |
| `GET /config/paid-membership` | `/adminapi` 与 `/api/admin` 双前缀；须 `config.view`。只读 REPEATABLE READ 快照，按全局 `is_store=0, sort DESC, id DESC` 选每键胜出行。返回两个 `0/1/null` 草稿值、原始值、缺失项、诊断及版本；缺失、空值和非规范历史值为 `null`，不在 GET 补写。 |
| `POST /config/paid-membership` | 两前缀须 `config.manage`。仅接收两个整数 `0/1`、读取版本及 UUID 请求标识；有界 JSON、重复键拒绝。先锁 `system_config` 全表协调缺行/优先级变更，再核版本，仅更新两个胜出行或补缺行。请求身份、版本和内容由事务内短审计摘要约束；审计晚失败使配置整体回滚。 |
| 写入回执 | 数据库和审计提交后逐键删除 `cfg_member_card_status`、`cfg_svip_price_status`，回报 `cleared/pending`；缓存结果不能反推事务是否已提交，也不保证并发旧读回填后的全局瞬时一致。未知 HTTP 结果只 GET 核对，不自动换 UUID 重发。 |
| 旧通用保存入口 | 已注册的 `POST /api/admin/config/save` 仍可保存其它通用键，但预校验整批拒绝本域两键与普通等级激活九键；混合批次不写 SQL/KV。该兼容入口没有专用域的 revision、UUID 或审计，不能用它保存这 11 键。`/adminapi/config/save` 并未注册。 |

页面在保存前列明两个开关从已读值到草稿值的变化；只读身份没有保存入口。遇到原值缺失或损坏时必须明确选 `0/1` 才能保存，保留原文供判断。总开关关闭时价格值仍可配置与保存，当前付费会员价不会因此生效。价格开关不只是视觉显示：新读取价格的业务还要求总开关、有效付费会员资格和已启用的 `vip_price` 权益；普通等级优惠另由普通等级策略决定。

现有消费者的缺失/空/坏值历史解释不完全一致，因此只读响应不虚构一个跨全站统一的“有效默认值”。购卡、卡密兑换、会员页和收货结算赠积分的付费会员倍数已改为 SQL 胜出行权威；商品和结算定价原已读 SQL，仍保留各自校验。关闭开关不阻断收货或核销，仅使之后读取的赠积分不应用付费会员倍数；已结算订单不追改。个人中心的付费会员标志和菜单入口展示也按 SQL 全局胜出行读取，两处各自保留旧版对缺失、空值及非规范值的解释；同屏其它配置仍遵循既有 KV 读取方式。已开始的操作可能按其先前读到的配置完成，提交后的缓存回执也不是全站瞬时一致承诺。保存影响之后读取配置的业务操作；不追改已有会员期限与历史订单金额，也不在已有支付义务的回调入账前增加新开关门禁。生产真实角色/配置、设备、渠道、Linux 和发布仍需单独验收。

本批属于旧 `setup_user` 一个完整子域，该旧整页仍有基础资料定义和经验策略等开放项，整体逐屏状态继续 `partial`。旧营销优惠券动态系统配置是另一条缺失路由，不计入本批。

本机验证按完整文件记录：新 Admin 输入/SQL 17 项，前端运行时 37 项，已覆盖的业务消费者轻量测试 7 文件 63 项；展示投影另有 3 文件 28 项实际 PGlite SQL/静态回归，包含 SQL 与 KV 互相矛盾、胜出行、匿名菜单、历史坏值和 SQL 故障；通用保存保护另有轻量 15 项。展示范围不冒称原生 LOGIN、HTTP 或浏览器验收。原生 PostgreSQL 16 的最终完整绿文件分批验收专用 Admin 12 项、会员定价/购卡/收货 55 项、结算配置权威/会员节省账本 36 项、通用保存双建库模式 50 项，共 **153 个不同原生用例**，不能称为单次 153/153。原生 Admin 文件组装双前缀真实 JWT/ACL，用独立受限 Admin/App LOGIN 核权限、胜出行、跨配置域锁、版本/重放、审计晚失败、KV 待清理；通用保存文件验证超级管理员和 `config.manage` 均无法绕过 11 键专用入口，其他键照常保存。消费者原生文件证明实际 SQL 与交易效果，不冒称另一次 HTTP 权限审计。Worker unit/runtime 类型与 Admin 生产构建通过。普通轻量定价文件的 3 个下单断言因夹具未安装 `store_order_purchase_origin` 原生协议而失败；同一完整文件在原生 PG **26/26** 通过，未修改业务断言或把轻量失败计作通过。首次通用保存/专用联跑中的一项测试把未注册别名误期望为 HTTP 404，实际兜底为 HTTP 200／业务 501；修正测试期望后的专用完整文件 **12/12** 通过，不把初次失败计入。四座最终计入的原生测试集群夹具归零、独立停机。本机合成浏览器核对侧栏、双键草稿、关闭总开关保留价格值、保存确认、单次 POST/GET 读回与只读身份；最终文案构建另行确认奖励影响及 SQL 展示说明均已渲染。
