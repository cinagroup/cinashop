# 迁移后续改动的审计追溯

积分中心恢复了十个财务路由中 `stationOpenMiddleware()` 的实际调用；套餐管理随后为现有 API 增加取消信号、全状态预览和返回类型。当前 API 审计的路径、方法、处理器和数量保持一致，但路由文件及套餐 API 文件的源码散列与九个请求行号发生变化。旧 Admin 筛选审计入口尚未还原这些后续增量，导致 13 个历史套件的 37 项断言失败。

新增 `migration-audit-followup-source-binding-20261026.json` 和对应测试 helper，逐字节绑定两份生产源的改动及最新测试 helper 的三处接线。生产源依然保留真实中间件调用和取消信号；还原只在测试内用于进入旧审计链。旧夹具、旧报告和原始验证记录保留原字节。

完整 API 报告的历史 SHA256 为 `a99c42f5be30da197bc127a2489a67a3c13cc226246de3279160aa3f18362ab8`，当前报告为 `0d9bc7d912efd02d8ff5efdafc8bb4b7d7a79962905684d861724d7273d6ea7f`，均为 644215 字节。桥接恰好十一处标量：一个根路由源码散列、一个套餐 API 源码散列，以及九个请求行号各加四。两端保持 706 个调用、744 个路径变体、107 份前端源码与 1677 个注册路由，所有路径、方法和处理器相等。

历史 Admin 筛选 helper 的正向应用继续产生历史报告；进入其反向入口前，先验证并还原当前增量。另设测试 harness 的独立还原入口，使其原先锁定的 helper 字节也可完整重建，避免递归或修改原夹具。

验证覆盖两份完整生产源、最新 helper 的完整字节、83 份旧证明、实际源码的十个中间件调用 AST 和 API 合同。变异控制拒绝多余源码、重复或缺失编辑、换行变化、同长度替换、伪造路径/散列/长度/行号/操作顺序，以及报告其他字段变化。

该修复属于测试审计衔接。PR #179 的原生子进程诊断全部正常退出，失败位于上述历史绑定断言。历史 Browser 结果仍仅证明原运行时的源码闭包；PR #180 的套餐 Browser 证据仍绑定其已发布提交。本批不将旧 Browser 记录重新标记成当前分支的全树验收。
