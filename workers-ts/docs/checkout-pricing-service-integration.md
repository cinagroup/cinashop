## 已接入的业务路径

`StoreOrderCreateService` 原事务末端仍调用 `protectCheckoutPricingSources`，随后重读同一份 SQL 计价投影并验证确认凭据。保护函数现改为调用已注册的固定锁能力，不再直接锁表，也不在失败时增加配置 DML、安装函数或回退旧路径。

保护之前同时核验 READ COMMITTED、当前 schema，以及两个未限定表名实际解析的对象是否正是该 schema 中的计价表。这样可支持明确隔离的 schema，同时拒绝“读取临时/回退来源却锁住另一套表”。随后执行相同 schema 的 advisory gate、完整协议目录校验和固定零参数函数；55P03 仍转为原来的“配置正在更新”提示。

只修改锁能力接线，不改11个计价键、会员权益优先级、价格公式、库存/积分/优惠券语义或事务提交顺序。已经存在的幂等订单仍直接重放，不因后来的配置变化或组件维护重新定价。type=3 线下收银继续保持 PHP 范围，暂不新增退款，应付至少0.01元的规则不变。
