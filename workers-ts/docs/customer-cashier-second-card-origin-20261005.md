# 真实次卡收银来源（2026-10-05，验证进行中）

六个独立UserJWT接口位于`/api/mobile/work/cashier/second-card`：POST drafts、quote、orders、orders/:id/cash，以及GET creations/:key、payments/:key。当前仅建立真实业务和不可变来源基础，完整五个代客页面尚未完成。

服务端先持有本人独立购物车草稿，真实报价生成短期KV凭证，内部WeakMap能力进入成熟创建事务。JSON字段、staff_id巧合或历史store_id=0不能获得该能力。事务在锁后再次校验购买人、当前经营资格及唯一商品规格／数量，写入真实订单、库存扣减、购买快照、创建审计和来源台账；同UUID原意图只重放已提交结果。

现金支付复用成熟支付事务，先核真实订单、原创建者、实体订单号与金额，并拒绝既有支付渠道claim及UNKNOWN／PENDING。同事务写真实paid状态、付款审计、原order.paid outbox和不可变支付回执。有效期必须由原支付outbox真实消费激活；缺失或被改动的快照／窗口／支付事件均不能核销。游客购买人UID保持0，经营操作人仍是实际正UID；0.00支付仍需完整来源证明。

退款剩余实体来源只沿实际成熟申请、退款完成记录、sourceSnapshot和partitions回溯，核对每代真实商品、购买数量、次数和金额快照，最终绑定原收银来源及原支付回执。不会重写旧origin，也不会为历史数据补造来源。

零元现金次卡的内部数量退回使用另一种不可JSON伪造的WeakMap能力，绑定原收银经营人、当前scope、真实会员、订单／来源和完整购物行。成熟申请在锁后重新授权；完成阶段重新核对来源，按退回数量判断是否全部完成，不能以0>=0提前结束整单。该入口未挂HTTP；普通现金资金退款、游客退款及一般公开退款金额规则保持既有边界。核销完整32项已实际验证真实创建／零元支付／两代数量退回／剩余实体分次核销，以及伪造能力、非来源订单和游客退款反例。
