# Admin 商品目录四维筛选与旧供应商选择器（2026-10-15）

本批将既有主商品目录的分类、供应商、品牌、商品标签查询接入实际 Admin 页面，并新增真正旧接口 `GET /adminapi/supplier/list`。旧主目录 GET、八状态计数和既有现代商品选择器仍各有自己的合同；本批新增的旧后端接口只有供应商选择器一条。基线为 `5acbc71cf83971149d9b7c39978dee8ae92d0c2e`。

## 来源与行为

24 个只读 PHP、旧 JS 与 installer 输入的 SHA256 留在本批验证账本。没有执行 PHP 或密文继承逻辑。

| 维度 | 实际候选请求 | 查询语义 |
| --- | --- | --- |
| 分类 | `product/category/cascader_list/1` | 严格多选节点，`emitPath=false`，保留显式 ID，不自动展开后代 |
| 供应商 | `supplier/list` | 裸 `id/supplier_name` 数组，仅 `is_del=0`，包括停用供应商，按 ID 倒序 |
| 品牌 | `product/brand/cascader_list/2` | 单选完整祖先路径，可选父级，后端同时保留主品牌列与 type2 关系谓词 |
| 商品标签 | `product/product_label` | 实际旧分组树中的标签，显示组名；不使用会额外包含孤儿标签的 `all_label` |

供应商 PHP 控制器忽略全部查询参数，目标在 16384 编码字节、320 个参数、单键/值 256 个码点以内继续忽略值，重复分页或状态参数也不改变候选。完整列表最多 10000 项，10001 项明确拒绝而不截断；服务层保留 503，旧 HTTP 控制器将已分类的 409/503 转为 HTTP200、`status:400`、原消息及 `data:null`。真正旧 Axios 会拒绝并保留这些消息，现代请求层也会拒绝。鉴权错误保留既有代码，未知异常继续进入全局 `status:500` 信封；不宣称修复旧 Axios 对未知 500 的既有吞值行为。

来源没有 `supplier/list` 数字权限种子，供应商目录 `supplier/supplier` 的种子不挪用。目标要求 `product.view`，既有 `product.manage` 到读取的扩展保留；伪造 API、页面路径或 `unique_auth` 的菜单不能从新选择器取得商品读写权限。读取复用实时平台管理员、密码版本、角色与历史引用检查，以及 REPEATABLE READ / READ ONLY 快照和末端数据库墙钟过期检查。并发撤权在下一次快照生效，不宣称中途即时撤销已开始的只读快照。

页面将四维数组/ID复制后同时送到主列表和状态计数，保持 Axios 括号数组格式。更换筛选回到第一页；分页及状态切换保留筛选，重置清空四维和名称。非空分类的 PHP 计数分支仍忽略名称、归属、品牌和标签等条件，故保留其计数与当前行数不一致的行为。预览夹具也消费四维并保留这个计数例外。

候选源各自失败不会清空其它源或伪造计数；重试保留已选 ID。独立的候选代次、AbortController 与身份/Token/持久会话校验拒绝迟到结果。筛选变化关闭旧弹窗并清空旧行和选择，既有批请求在有效或非法筛选变化后仍保持忙碌锁直到自己的请求结束；迟到完成不覆盖新目录。
