## 修复合同

`AdminMobileProductService` 的上下架、规格库存编辑和批量运营取商品行时使用有序／单行 `FOR UPDATE NOWAIT`。规格编辑取活跃 SKU 同样使用 NOWAIT。这样，已取得前一个商品或其它管理锁后，不会继续等待下单所持的后一个商品／SKU。

上下架仍在原事务内更新商品、购物车、分类关系并回读、写日志。购物车改为一条 `WITH locked_carts AS MATERIALIZED (...) UPDATE ... FROM locked_carts`：数据库按 ID 以 NOWAIT 取得原来同样的未支付／未删除购物车集合，更新严格使用该集合。没有把不限量购物车 ID 拉入 Worker 内存，没有跳过忙行，也没有在独立后续 UPDATE 重新发现未经锁定的新行。并发新插入购物车的整体业务政策不在此证明范围，原回读校验仍保留。

仅上述显式锁操作中的嵌套55P03转换为“商品或购物车正在变化，请刷新后重试”，异常退出原事务，先前商品／购物车／SKU写入、建议锁和行锁一起回滚；没有自动重放旧库存。其它SQL错误继续传播。原2秒锁／5秒语句时限、价格汇总、库存和sumStock语义、退役SKU排除、归属／引用验证、购物车过滤、九类批量字段／关联及日志政策均不改变。

这两个批量处理器同时被后台与嵌入式移动管理路由引用；规格编辑挂在移动管理路由。本轮测试真实处理器，不运行正式身份中间件，不能外推为登录／ACL验收。
