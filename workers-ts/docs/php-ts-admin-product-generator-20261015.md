# Admin 商品规格生成增量（2026-10-15）

接通真正的 POST `/adminapi/product/generate_attr/:id/:type`，返回旧 `data.info` 中的 `attr / value / header / product_type`。它与已推送的商品详情和完整保存接口形成后端链路；完整六步 Vue 编辑／复制界面仍开放。

## 实际生成合同

路径 type 是生成模式，不是商品履约类型或受信复制标志。正商品ID的模式0只返回实际命中的组合；模式1／2补出缺失组合的零价格／零库存模板。ID0始终生成新模板，不读孤儿SKU、不分配ID／unique。输出保持旧 `value1..N / values / detail / pic` 等字段，不新增身份字段。客户端提交的 items、价格、owner 与关系值不成为生成种子。

正ID的 owner 和 product_type 来自主表；源允许的删除商品保持可读。只匹配有效的普通SKU，不复活退役或活动行；重复 suk／unique 拒绝。返回实际价格、库存、条码等，供应商归属增加结算价列并保留总后台售价／成本／划线价。只有产生行时才生成维度表头，最后保留操作列；空 attrs 返回空组合与固定表头，兼容旧单规格加载时的自动调用。

卡密模式0返回空 `virtual_list`、真实可用／总数聚合和既有固定交付内容；不 SELECT 卡号、密码或旧快照凭据。模式1／2省略固定内容和卡密列表，仍不代表完整复制流程。次卡读取实际核销次数／有效期与上海日期；这修正了 PHP 输出代码引用字段却在 SELECT 漏选、导致默认值覆盖的缺陷。新次卡日期模板保持源有效输出 `['','']`。

支持的履约类型为0／1／3／4；优惠券履约2继续拒绝，路径模式2不等于支持该类型。次卡维持当前单SKU规则。

## 权限、快照与容量

精确安装种子191只授予内部的规格生成读取准入，不能获得 product.view 或 product.manage；现代 product.manage 可生成，view／620不可。该内部准入不是可直接保存的角色字符串。191元数据改写成保存接口、复制相同路径到其他ID、伪造 canonical token 均不回落到宽泛权限。现有真实角色解析、委派和不透明旧菜单保留规则共同约束它。

请求实际 UTF-8 限64 KiB，拒绝重复JSON键、不规范ID／模式及所有查询参数。维度最多三项，每维50值、名称32字符／值64字符、组合200，乘积在展开前检查。逗号、控制字符、保留名称、重复值及无效维度拒绝。

全部读取在 REPEATABLE READ / READ ONLY 事务内，复用当前管理员／密码／角色授权和结束前数据库时钟检查。主表只投影四个定长字段；SKU实际投影先在 SQL 统计字节，累计预算1 MiB、最多10000行，响应限1 MiB。私有SKU图按实际owner验证后签名。生成服务没有商品修复、身份分配、业务DML、审计／outbox或业务provider调用，通用鉴权沿用既有会话验证路径。源HTTP路由另有异步日志中间件，本批的纯读取是明确目标选择，不能反称旧HTTP全链无副作用。
