# Out 卡密和固定内容商品

固定 PHP 来源为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 `Product::productSave`、`StoreProductServices::saveData`、`StoreProductAttrServices::validateProductAttr` 与 `StoreProductVirtualServices::saveProductVirtual`。本批接通平台 `product_type=1` 作者，支持多规格的固定虚拟内容及一次性卡密，沿用 Out 身份、接口权限、请求幂等、商品关联和 SKU 身份规则。非物流交付固定为空配送方式、`freight=2`、零邮费和零模板；当前预售作者仍只支持实物。

一次性卡密复用现有 `VirtualProductInventoryService`，接受旧编辑器的 `key/value` 和当前 `card_no/card_pwd`，在请求内和历史记录间去重。单次最多提交1000条卡密。新建一次性卡密 SKU 以零库存开始，实际导入数量增加可售库存和累计库存；编辑保留现有库存、累计库存和销量，再增加本次真实插入数量。固定内容继续使用普通库存，可通过现有 Out 条码同步调整；一次性卡密不能用数值同步增减库存。两种模式只可在库存及卡密历史均满足条件时转换，有卡密历史不能改成固定内容，有固定内容库存须先清零再转卡库。

保存前核对一次性 SKU 可售库存与未分配卡密数。待交付预占或历史漂移导致两者不一致时，完整作者明确拒绝，避免覆盖已有库存。每商品卡密和库存流水的完整校验容量各10000项，超出时明确拒绝。作者以非阻塞库存锁和实际卡密表屏障协调导入、购买、交付；导入后校验全部已知卡密身份及内容摘要、SKU、商品、流水、规格快照和回执，强制执行延迟约束后再次核对。完整性校验仅读取已有卡密的身份和数据库内计算的摘要；底层导入器沿用现有匹配凭据去重逻辑；普通 Out 详情继续返回统计和空 `virtual_list`，敏感导出沿用现有受控接口。

真实隔离 PostgreSQL 验证覆盖：创建及重放、旧格式去重、Unicode 卡密、关联字段、实际购物车和未支付订单、明确设置测试付款状态后的真实自动交付、固定内容从订单快照交付、交付后追加卡密、空库存模式转换、数值库存边界、导入锁与结算行锁竞争、延迟篡改回滚和现有受限应用登录。付款状态由测试夹具明确设置，这些场景不证明支付提供方流程。生产错误边界验证了包含凭据的数据库错误只返回通用错误。未部署、未上传旧 PHP、未调用实际支付或外部提供方。优惠券商品 `product_type=2` 的 Out 作者仍待迁移。
