# Supplier 普通订单购买品与赠品身份核对

PHP 实际 Supplier 订单列表以 formType1 挂载普通详情，商品页签和拆单发货记录都会显示“赠品”。这项标识由订单商品行的 `is_gift` 覆盖快照 JSON 后交给页面。本批接通 TS 普通详情、历史发货包裹和分批发货选择器的同一流程。

## 读取合同

三个实际 GET 读面分别新增 `review.items[].is_gift`（`order/info/:id`）、`[].cart_info[].is_gift`（`order/split_order/:id`）和 `[].is_gift`（`order/split_cart_info/:id`）。当前服务始终返回数字 0 或 1，只取受保护商品行；0 显示“购买商品”，1 显示“赠品”。JSON 中相反的 `is_gift/isGift`、当前商品名称或价格都不能覆盖该事实，真实零售价或零结算的购买品也不会被误标为赠品。

前端为旧服务滚动兼容保留缺字段分支，明确显示“商品性质未返回”。字段一旦存在，只接受数字 0/1；undefined、null、布尔、字符串及其他非法值均拒绝展示并可明确重读，不能把非法值当作旧接口缺字段。关闭弹窗、离开路由和账号变化后，迟到详情或待发商品不能恢复旧资料。

后端沿用各读面已有的实际 Supplier、会话、权限、完整商品归属、父子关系和有界只读快照。非法受保护行标识按现有校验错误拒绝整次读取；待发选择器先检查完整商品集合，再过滤已发或无剩余数量的行。SQL权限错误真实失败，不伪装空记录。历史子单不借用平台根或其他供应商的商品。

共享配货读取现在也会校验完整商品行标识，但打印配货单 DTO 没有新增字段，本批不声称打印件已显示赠品。原有商品、数量、金额、库存、退款、核销及履约作者不改。

## 验证与边界

最终 **802 项不同用例、18 文件通过，86 项新增**；前端/runner、配货纯函数、专属原生、共享读回归和核心订单回归分别绑定各自成功阶段，重复运行不追加计数。Supplier完整类型/生产构建和Worker两套完整类型均通过，结果见账本，16 份执行源按实际相关输入核对指纹。早期专属原生执行期间仅无关 Browser 桥发生断言修正时，限定相关后端、夹具、测试与runner逐项不变，不冒称整个捕获集合未变。

真实作者链调用成熟 `AdminFullGiftService` 创建 type4 活动，使用同属 Supplier 的购买商品和赠品，再执行注册的真实下单、赠品库存与活动配额预留、Supplier 分配、付款记账及履约拆单。随后以真实 App/JWT 和独立 SELECT-only LOGIN 读取三个界面，逐次比较全部 public 表与序列。Admin作者运行在本机自有维护连接，不冒称独立Admin HTTP/权限验收；付款准入明确为合成边界，不宣称支付回调或provider。专用写角色仅在自有夹具增加促销辅助表 SELECT 和实际预留所需 `UPDATE(surplus_num)`，没有辅助表 INSERT/DELETE 或生产角色授权，也不声称赠券、赠积分已发放。

专属原生初轮38项中33通过、5失败，失败与全部原始指纹保留且不计最终通过数。三项RR测试在事务持有单连接时又借用根连接池，修为使用当前事务 session；一项真实履约夹具漏掉成熟付款记账前提，改为实际调用 `recordSupplierPayment`；一项测试订单号超过数据库32字符，改为短稳定标识。这轮原生修正仅涉及专属测试文件，完整38项随后重验通过。

初轮连接等待导致3个夹具库及3个独立角色未能自动删除。该私有集群停止后，以离线 single-user SQL 精确清理已列出的本批库与角色；身份检查前后及清理日志保留，`pg_hba` 指纹不变，没有开启网络监听或改变生产认证。最终共 7 座自有PG的实际空库、PID和独立停止检查见清理回执，不把这次离线修复写成初轮自动清零。

生产构建 Browser 使用真实 Supplier App/JWT、独立只读PG和合成展示记录，完成普通详情、历史包裹、现代零购买、旧赠品、反向JSON及真实读取后503重试。管理账号在分批选择器中选中赠品后取消，没有提交发货。35 次业务GET对 29 表/28 序列逐次零写，provider调用为 0，自有内存表单图片R2读取为 4。1200×844和390×844同源iframe的布局、实际选择与页脚检查均通过，控制台warn/error采样为空；不称真实设备验收，也不把本机控制POST算作业务作者。

首次Browser命令多带原生专用verbose参数，在数据库启动前被准入拒绝。随后实际布局验收发现长赠品使桌面页脚底部879.525超出844像素视口，保留失败截图与尺寸后，将唯一发货弹窗限制为视口高度，完整内容在主体滚动，头部和页脚保持可见。重新完成612项前端/runner、Supplier类型/构建与完整Browser；最终桌面页脚底部797.725、手机812，手机主体692/799像素可滚动。原生失败、布局失败和重复前端运行均不重复计数。

23 份PHP/TS源文件由实际基线和当前PHP字节核对SHA与引用范围，根88/404复选行保持。保留用户选定的已恢复PHP `get_script` 及修订后的退役审计，整体迁移继续active。完整命令、指纹、初轮失败、离线清理及最终验收见[验证账本](../audit/php-ts-supplier-order-gift-identity-20261019.json)。

本批不修改赠品资格、赠送权益、发货或资金写入协议。普通卡密/固定内容交付核对仍是下一候选，会员细分的普通PHP界面尚未证实；生产角色/部署、真实设备、provider与整体迁移验收仍开放。
