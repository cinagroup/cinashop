# 基础商品单次限购与累计模式准入

此批以 `4cecfd3a9588f2e33143e63d4a809857330e789e` 为基线，分支 `codex/product-purchase-admission`。目标是补上基础商品已配置限购却在普通购物车、报价及创建作者被忽略的问题；整体 PHP→TS 迁移仍 active。

## 行为

启用 `is_limit=1/limit_type=1` 时，按基础商品 ID 汇总本次所选 SKU/购物车行，使用正整数 `limit_num` 为上限。关闭限购时忽略旧 type/num 残留；启用但配置异常明确拒绝。累计模式 `limit_type=2` 因历史尚不完整而统一拒绝，不再静默放行；没有将累计能力记为完成。

普通可复用篮子的加量包含同买家、代客人员/游客、商品与类型的现有有效件数，改量按替换计算，排除已付、已删、停用、门店及直接购买意图。普通作者在读取数量前共用商品/篮子事务锁。普通查询和合并也限定对应归属，避免排除在数量之外的代客记录被误合并。停用行保留不可用投影。

实际报价/确认及统一建单逐商品核对选择总量，确认指纹包含归一化生效规则，扣基础库存的 SQL 同时比较当前规则。Worker 独立积分直兑作者也核对基础规则并使用同样库存比较条件。套餐准备在替换旧意图前核对；自动实物赠品按全部赠品跨活动聚合，并独立核对及比较当前规则。商品与赠品分组分别对应 PHP 购买检查及赠品 `new=true` 语义，不把两者之和冒充终身累计。

旧确认接口改为仅读取本次选择的 ID；未选择的旧直接购买意图不占用这次额度。内部 checkout 范围保留旧接口 200 行和混合 isNew 兼容，公开 buy/compute 仍限制 100 行。选中商品限购失败透传业务原因，购物车列表保留不可用行。

## 保留的缺口

- 累计限购仍缺可信账户起始覆盖、导入/删除旧数据覆盖、赠品的原购和付款数量完整投影以及全退款作者的完成凭据。`PurchaseQuotaHistory.incomplete` 未改。
- PHP 原始历史 SUM 没有完整子单/旧 cart/赠品去重；申请时的 refund_num 不是完成退款，不能照抄为可信额度。
- 购物车规则读取后仍可能被并发 Admin 编辑；购物车不是规则预留，最终报价重算与建单库存比较才是权威。
- 普通及工作收银部分草稿直接作者仍能暂存超额数量，实际统一报价/建单拒绝。不宣称所有草稿作者已接检查。
- H5 SKU 选择器本批仍按库存限制数量，未新增基础限购提示或提前禁用；超过上限由实际 API 拒绝。
- 没有证明全部活动、库存补偿和管理操作之间的锁序都无死锁；保留成熟活动协议。
- 实物赠品专项退款用例的付款头是显式合成余额 fixture，后续 outbox/受保护赠品凭据/物化退款为实际服务；不是支付渠道或生产权限验收。
