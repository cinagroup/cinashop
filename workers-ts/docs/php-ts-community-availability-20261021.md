# 社区统一关闭与显式恢复

为 PHP 社区路由组补齐统一门禁：24 个原始业务端点、TS 的 3 个短别名及只读 state 共 28 条注册按站点、社区、原有鉴权、业务处理器的顺序准入。关闭返回 HTTP 200／业务 410010，沿用“站点升级中，请稍候访问”或“社区暂未开放”；TS 保留 data:null 并禁用响应缓存。公开 config 仍可读取，维持原有三个字段。

社区总开关和 config 的总开关字段直接读取平台配置原始值，按 sort、id 倒序确定唯一优先记录，不清理重复记录。沿用既有 PHP JSON 真值转换，包括字符串“0”、空数组／对象与缺失记录的区分；反向陈旧 KV 值、旧读取在配置提交后回填缓存均不能重新开放社区。评论的两个局部配置字段保持既有处理。真实 Admin 六键保存及 system_log 收据、提交后缓存失效失败、数据库错误都有独立原生验证。

这里是请求准入语义：请求已通过门禁后，即使管理员稍后关闭社区，原有事务仍可能提交。三条真实 PG 连接和行锁验证这一边界；没有新增跨配置／业务的全局提交锁，也不会将此类成功或未知回执替换成“未执行”。数据库故障继续报错，不能伪装成确定拒绝。

前端主社区、作者、关系页、话题、搜索、视频、发布器及详情／评论／互动共享关闭状态。观察到关闭配置或确定的 410010 后清空内容与旧个性化状态，停止后续选择器链，显示“重新检查社区”；恢复只从显式操作发起。已有未知互动／评论标记在同 auth store 的内存注册表保留，恢复后还要主动核对，不自动重发。发布器局部未知保护不宣称跨页面销毁、重载或进程持久化。普通 Error 和 5xx 中的 410010 不算确定拒绝，不清除登录。所有者含 UID、token 和会话版本；迟到读取、旧关闭回执和恢复失败不能覆盖新的账号、帖子或恢复代次。

原始／canonical 参数先纯解析，再做社区配置或业务 I/O。首次未知状态的合法游客发布／编辑先检查公开配置；已知关闭则直接停用且不跳登录；非法或重复参数没有社区业务 I/O，应用仍可执行既有 get_script 读取。关闭详情恢复采用只读 state，不重复增加浏览数；用户新点开的详情依旧执行一次正常浏览。

PHP 证据来自只读兄弟仓库的 13 份当前源码。中间件声明与默认参数有静态依据，但未运行 PHP 或调用不透明的 Swoole 配置 helper，也未证明缺失配置在该运行时的实际返回。ThinkPHP 的 middleware.priority 可覆盖声明顺序；本次只声明默认优先级下的源码顺序兼容，实际 TS 顺序有测试。缺失记录继续沿用 TS 的开放默认。PHP hasUser 在读取时可能建立资料，TS 保留既有纯读取，不复制此副作用。商品聚合停用属于单独 TS 一致性建议，不冒称 PHP 要求。

本轮 Admin 严格生成器实际执行，报告与独立推导完全逐字节相同：只改变根路由源哈希和 716 个注册行号，各增加一行，732 条调用路径仍可执行。新证明记录 import 和 28 条完整注册的精确修改，可逆还原 availability→state→video 的完整前序源码与报告。四个历史审计文件逐字保留；恢复的 get_script 路由、处理器、共享加载器和三客户端行为保持。篡改额外源码、鉴权、门禁顺序、处理器或证明字段都会被拒绝。

定向 **1,013 项独立用例通过**：Worker／运行器 659、原生 PG16 的 172、H5 社区运行时 181 和真实浏览器 1。181 项包含于完整工具链 1,501 项，不重复累计。Worker 的有效 659 项由 18 份未变且完整通过的文件／652 例，加上最后整份 7 例绑定文件构成；旧失败候选的部分通过不另计。两套完整 Worker 类型配置与独立浏览器配置通过后，仅该绑定测试的负例定位发生修改，最终文件另外通过等同严格参数的独立 tsc；其余最终输入无漂移。UniApp 13 步完整合同、最终类型与 H5／MP／App 干净构建和实际产物检查通过。

后台浏览器 22 阶段完成 51 次实际 API 请求，逐次核对 14 表／14 序列；只出现一次真实点赞写入（提交成功后故意返回 503）和一次正常详情浏览，8 次配置切换另列且序列零变。未知状态关闭／重开后仍锁定，主动核对才解除；站点优先、全部入口停用、游客不跳登录、重复参数拒绝、只读详情恢复与跨账号通过。375 像素无横向溢出，应用 error 0，有 12 条既有路由警告。364 个最终 H5 文件在验收前后逐字节一致。内存 R2 的两次夹具播种 put 保持，验收新增 put／delete 均为 0，第三方调用 0；没有冒称存储从未写入。4 个自有 PG 实例经独立 pg_ctl 状态确认均已停止。实际生产构建、createApp、JWT、自有 PG16 和真实 DOM 为证据，只有路由／会话、视口尺寸、配置切换及检查点为合成控制。

失败候选保留：早期旧社交 AST 绑定需恢复实际直接解构；新增运行时测试漏了已有严格 DTO 字段且错误地将新账号请求也配置成关闭；修正测试夹具后回归通过，未放宽生产校验。最终 Worker 首轮唯一失败来自负例误改了新发布初始化的同名调用，改为 SFC／AST 精确定位恢复调用后整份 7 例及严格类型复验通过。初次 80／92 原生批次与 177 项运行时候选均由最终结果覆盖，不重复计数。
