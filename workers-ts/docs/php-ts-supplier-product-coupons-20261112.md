# Supplier 商品付款赠券

本批补齐供应商商品的 `coupon_ids` 作者入口、版本化详情回显、只读发行实例目录及现代选择器，覆盖既有实物、卡密/固定内容和手工虚拟三类商品（0、1、3）。不扩展 Supplier 优惠券型/次卡型商品创建，不改变实际付款赠券消费者。

## 旧版依据及配置语义

固定 PHP 提交为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。Supplier `StoreProduct::save` 接收 `coupon_ids`；通用保存与 `ProductCouponJob::setProductCoupon` 更新 `store_product_coupon.issue_coupon_id`。付款监听调度 `ProductCouponJob::doJob`，`StoreProductCouponServices::giveOrderProductCoupon` 按订单商品读取任务处理时的当前关联，再调用发行服务赠券。不是下单积分快照，也不是优惠券模板 ID。五份实际读取的旧文件均与固定提交完整字节一致，身份见审计清单。

发行表没有可用的商家所有权列，本批沿用既有实际规则：作者只要求发行实例存在且未删除，不臆造 Supplier 自有券范围，不把停用、时间或余量限制提前变成保存准入。付款处理仍按原服务核对启用状态、领取窗口、使用窗口、剩余数量和永久/无限规则。相同订单跨商品、跨数量对同一发行实例只赠送一次。

## 后端作者与读取

- 普通保存明确 `coupon_ids` 才替换，接受既有数组/CSV ID 规范化、去重升序和最多100项规则。省略及内部 undefined 保留原行及行版本，空数组/空 CSV 明确清空，越界或无效输入拒绝。
- 复用字节未变的 `OutProductCouponBindings` 实际捕获、替换及最终证明函数，不另开嵌套关联事务。商品主行、既有产品写锁和商品券 NOWAIT 事务锁协调其他遵循协议的作者；发行实例使用 SHARE NOWAIT，保存全过程核对关联行版本和发行完整行。
- 当前 Supplier 管理权限在事务入口及所有作者、延迟约束结束后重新检查。券写入前记录已经完成所有合法作者的商品全行，最终再次核对实际归属、履约类型、待审核/下架状态及完整商品行。券触发器不能在最后一步悄悄修改积分、目录或当前角色。原关联在其它作者期间被动改变也会在替换前拒绝。
- 详情增加 `coupon_selection` v1，包含选中 ID、标题、存在/未删除状态及一致性/截断标志。历史缺失、删除、重复和超量关联可读、可省略保留、可明确清空；读取不会变成写入，也不会掩盖实际 SELECT 拒绝。
- 新增 `GET /supplierapi/product/coupon/catalog`，只允许精确商品查看权限。严格分页、标题/编号搜索、字面转义 `%/_`，只返回未删除发行实例的有限展示字段；只读事务、首尾权限核对、私有不缓存、限时和响应上限。其它方法、路径或查询参数不扩大权限。

生产架构、迁移、权限计划、Out 绑定函数、结算、付款、赠券消费者和复制协议均保持原字节。普通省略保存不增加券 DML。最小隔离只读夹具为新详情投影增加两个券表的 SELECT；专用券作者夹具仅添加 INSERT/DELETE、序列 USAGE 和发行 ID 列 UPDATE 锁权限，券关联表 UPDATE 与发行标题编辑仍未授权。真实完整架构 APP/ADMIN 使用既有正式 commissioning 与支付安装器，未用临时授予来绕过缺失权限。
