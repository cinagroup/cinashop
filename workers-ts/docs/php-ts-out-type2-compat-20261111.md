# Out 历史类型 2：作者、通用赠券与人工整单交付

本批恢复固定 PHP 基线实际支持的 Out `product_type=2` API，并让 Admin、Supplier、PC、UniApp 买家详情及手机商家/经营工作台正确处理这种历史订单。商品仍保留类型 2；没有把已存商品改写成类型 3，也没有新增 SKU 专属优惠券字段。

## 旧版依据与范围修正

固定旧 PHP 提交为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。`app/controller/out/Product.php::productSave` 接收商品类型和通用 `coupon_ids`；`StoreProductServices::saveData` 将 `[1,2,3]` 设为非物流商品并持久化规格类型。Admin 编辑器隐藏类型 2（可选 ID 为 `[0,1,3,4]`），不足以证明历史 Out API 不支持它。

`app/listener/order/Pay.php` 对已登录买家的已付款订单调用通用 `ProductCouponJob`，独立于商品类型；`OrderPayHandelJob` 自动交付分支只有卡密类型 1 和次卡类型 4。`StoreOrderDeliveryServices::orderVirtualDelivery` 提供通用人工虚拟交付。这些代码共同支持“通用商品赠券 + 人工虚拟交付”的历史类型 2 解释。旧 SKU 作者持久化映射及 SQL 表没有 `coupon_id` 字段，不能据显示层的占位值制造专属券映射。

本批据此修正上一批将类型 2 整体保留为未决的结论。仍不启用 Admin/Supplier 商品编辑器中的类型 2 选项；本批作者入口为历史 Out API。

旧 Out `Order::orderDelivery` 强制快递方式，其 TS HTTP 规范化保持不变。本批没有新增 Out 虚拟发货 HTTP 能力；隔离验收使用 Out 商品 JWT HTTP、实际余额支付/支付任务和受信任履约领域服务。买家控制器的 UID 由显式测试中间件设置，不能视为公共买家 JWT 认证验收。

## 实现与边界

- 类型 2 共用既有手工虚拟输入规范化，但写入、校验、规格快照及回执保留类型 2。支持完整多规格作者、品牌/分类/保障/标签/参数/表单/调度关系、通用赠券、编辑库存保留和精确条码库存同步。
- 禁止修改已创建商品履约类型、外来 SKU 标识、非平台商品所有权，以及类型 2 的预售、卡密导入或固定密钥内容。商品、SKU、关系、赠券、属性快照、说明、库存记录和回执在篡改时一并回滚。
- 类型 2 只允许人工整单虚拟交付；禁止拆单、快递、同城及电子面单。复用现有所有权、付款、售后、权限和回执检查，未放宽卡密或次卡规则。
- 付款后通用赠券按原合同只执行一次；不自动将类型 2 标记为已交付。交付内容只有在已付款、已交付且属于该买家的详情中可见。
- 六个页面补齐类型 2 的交付方式、按钮可用性和内容文案；不变更后台商品类型菜单。

## 验收方法

原生测试继续使用未改动的 `run-local-finance-postgres.mjs`、显式允许文件和既定 600 秒预算。新增用例附加于现有库存边界文件，完整保留前身文件字节作为前缀。支付用例从 185 项迁移和 283 张表的隔离架构开始，经实际受限 APP/ADMIN 独立 LOGIN 和既有权限安装后执行；模拟账号余额从 100 元实际扣为 90 元，重复付款不再扣款，重复消费支付任务不重复赠券。全局外部请求禁止，队列发送断言为零。

浏览器采用现有 Playwright/Chrome；原因是 `Browser plugin not available`。运行真实 Vite/UniApp 页面并拦截为 localhost HTTP 受控响应，API 代理明确指向关闭的本地端口。买家详情使用隔离 PostgreSQL 链路产生的真实响应结构；页面认证为合成会话。页面证据不冒充数据库授权证据。统计脚本及通知 WebSocket 使用有限本地桩，不连接外部提供方。

页面流程为：Admin/Supplier 打开发货 → 默认虚拟整单 → 填写交付说明 → 提交并刷新订单状态；PC/UniApp 买家详情 → 展示人工交付内容 → 点击复制；UniApp 门店与经营工作台 → 类型 2 虚拟模式可用、拆单禁用 → 填写内容 → 打开确认框并取消，不发送写入。

每页记录 URL、标题、视口、非空正文、覆盖层、控制台、交互、请求和截图；桌面为 1440×1000，移动端为 390×844。截图、脚本和运行日志保存在仓库外的 `/tmp/php-ts-out-type2-compat-20261111`。仅将本仓库既有格式的验收说明和审计清单提交。

## 限制

本批没有部署、上传旧 PHP、调用真实支付/SMS/物流或实际券提供方。隔离 SQL 余额扣款不代表外部支付验收。后台新建类型 2 的可视入口、SKU 专属优惠券、类型 2 自动发券即自动交付均不在本批合同中。完整 PHP→TS 迁移仍未完成；既有累计限购历史证明和其他未决功能继续保留边界。
