# Supplier 多 SKU 批量填写迁移（2026-10-18）

本批恢复 PHP 实物商品的七项批量填写：图片、结算价、库存、SKU 条码、SKU 编号、重量和体积。先选择规格并应用到本地表格，核对后仍通过原商品保存／复制接口提交。完整商品编辑器与整体 PHP→TS 迁移继续开放。

## 实际 PHP 合同

权威来源是 `cinashop-php/view/supplier/src/pages/product/components/productDetails.vue`：469–603 为实际批量表格；1602–1674 为启用列；2308–2417 为规格选择；2790–2811 为清空；2854–2899 为应用。`attrList.vue:7–14,37–54` 提供规格值切换与确认。普通保存仍为 `api/product.js:269–274` 的原商品接口，Supplier 控制器 `StoreProduct.php:174–245` 复核归属并下架待审。

- 空规格选择代表全部；同一维度内多个值为“或”，不同维度之间为“且”。TS 使用完整结构值相等，修正 PHP 2407 附近拼接字符串的子串误命中（例如“红／深红”“S／SM”）。
- 正数与非空文字／图片才覆盖，0 和空白保留原值。清空只重置本区草稿及筛选，已应用的商品行保持原样。
- PHP 结算价之外的售价、成本、原价列已注释；会员价、佣金也不属于启用的七字段批量动作。PHP `StoreProductAttrServices.php:181–182` 的非零结算价镜像成本行为未移植，保留成熟 TS 独立成本合同。
- PHP 2035–2041 针对卡密／虚拟商品的旧 splice 会替换／删除当前操作列，实际完整可操作合同为实物 type0。本批界面仅开放实物多规格；卡密库存、秘密导入和独立交付流程保留原有权威。

## 实现与一致性

新 `SupplierSkuBatchEditor` 只产生当前商品入口、SKU 图签名、筛选和七字段意图；父表单以单调路由代次防止商品入口 ABA，再重新核对身份、权限、入口、规格图及加载／保存状态后，先验证所有字段与目标，再一次应用。入口切换、SKU 数组替换、身份／权限 ABA 和迟到图片回执均撤销旧草稿。媒体复用现有图片选择器，私有图片只提交稳定引用，签名仅用于预览；从素材库选择后将通过校验的本地预览传到匹配 SKU，保存前可直接核对表格图片。

规格生成复用已有有界模板预检，先验证 1–3 维、每维不超过 50 值和总数不超过 200，再展开；拒绝时保持现有定价行。数字规格名也按声明维度顺序生成 SKU，重新生成保留原定价行。结构筛选不会误用相似字串，历史 SKU ID／unique 保持原值，复制继续使用原 UUID／HMAC 协议。

同时补齐成熟 `ProductSkuEditorService` 回读遗漏的 image、barCode、code、weight、volume：实际 SQL 行与编辑快照均核对五列，普通保存继续兼容空 SKU 图片回退到商品主图。实际 SQL 触发器篡改、跳过 UPDATE 和快照破坏必须让事务回滚。此改动保留现有锁序、定价、库存与生命周期语义。
