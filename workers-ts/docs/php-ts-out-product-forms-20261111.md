# Out 商品表单快照和下单模板

固定 PHP Out 商品保存接口接收 `custom_form`，保存服务将其编码为商品主表的历史快照；商品详情和实际下单另从 `system_form_id` 选中的系统表单读取定义。原 Out 控制器没有接收 `system_form_id`，本批提供的该字段是与现有 TS 商品管理合同一致的扩展，不冒称它是固定 PHP Out 控制器的输入。

两个字段分别独立保存：遗漏保持原始数据库值，显式空数组或空对象清除快照，显式 `system_form_id: 0` 清除模板选择。原请求摘要包含有无字段和规范化后的值，升级前忽略空字段的回执不能执行新的清除意图。快照只接受有界 JSON 数组或对象，保留内容本身但规范对象键顺序；限定顶层100项、24层、30000节点和256 KiB，拒绝无法安全编码的输入。

模板选择复用现有下单表单的有效、未删除和组件定义准入，在商品保存事务内 SHARE NOWAIT 锁定模板。商品字段、其他关联、SKU、券关联和幂等回执共同提交；最终延迟约束执行后复核字段、完整可读定义与数据库行版本。遗漏模板时不访问目录，但仍保护商品原有模板 ID 与历史快照。详情在原只读快照内增加系统表单选择的可用状态；旧 `productInfo.custom_form` 仍展示系统表单定义，`editor.stored_custom_form` 单独展示历史快照。坏历史数据不会被读请求修复。

本地验收使用合成 Out 身份、独立 PG16 和实际商品／下单服务；受限 App LOGIN 只沿用现有权限。测试覆盖真实订单提交拒绝与成功、模板锁竞争、重复请求、创建、清空与延迟触发器回滚。该证据不表示真实账号、生产角色安装或外部支付已验收。未部署、未上传旧 PHP，整体迁移仍未完成。

最终验证：139项相关单测、两套完整Worker类型检查、71项完整库存并发表单PG16、69项完整Out详情PG16及41项完整供应商表单PG16通过；均无跳过。首次缺失新测试文件的单测启动和首次创建断言错误均保留，不计入最终结果。完整文件秘密扫描可能报告父提交既有合成幂等键，精确提交扫描见本地完成记录。
