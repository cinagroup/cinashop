# PC 首页轮播合同（2026-10-01，本地候选，未发布）

旧页面 `/admin/setting/system_group_data/pc/:id` 使用通用行编辑器，但 PC 首页实际按 `pc_home_banner` 配置名读取。安装默认组为 66，字段为标题、图片和跳转地址；组 ID 不是跨环境权威。新版 `/setting/pc-banner` 固定读取这个配置名，恢复新增、编辑、排序、显隐筛选、分页、删除及素材选择。管理条数没有 10 条上限；旧 PC 模板的 `index < 10` 仅限制公开展示窗口。

## 动态字段与历史数据

表单由已有组的 `fields` 定义生成，支持 input、textarea、radio、checkbox、select、upload、uploads；未知类型按旧规则回退 input，提示不阻止正常编辑。选项按换行的 `key=>label` 解析；多图最多 5 张。普通输入保留字符串，文本区保留换行和 tab；每个定义字段均须填写。既有字段元数据只读，HTTP 不修改名称或字段定义。

普通 JSON 更新保留未定义根键及已定义字段包装中的附加属性。单图历史数组取首项，不能以第二项替代不可用首图；多图历史字符串按旧规则转为单项数组。标题、主图和跳转三个核心键始终遵循 PC 消费语义，动态类型不能绕过图片归属或安全地址检查；不兼容核心标量值的数组字段元数据明确诊断并阻止写入。JSON 损坏或不是对象的记录禁用编辑，可隐藏或删除后重新新增；不会无声覆盖。元数据损坏阻止全部写入，明确留待维护。读取缺失组不创建数据，首次新增在同一事务中创建默认组及首行。

请求正文上限 256 KiB；元数据最多 100 字段、每个选择字段最多 100 选项；单图引用 255 字符、普通输入 4096 字符、文本区 10000 字符。合并历史 JSON 上限 1 MiB，分页偏移上限 100000，全集版本索引最多 100000 行。这些是明确容量边界，不是生产规模验收。

## 权限、版本与恢复

双 Admin 前缀各 7 个接口：列表、详情、新增、编辑、显隐、删除、UUID 回执。独立 `pc_home_banner.view/manage` 排在通用 setting 权限前；旧 numeric 菜单仅在精确 PC 轮播路径及 `setting-system-group_data-pc` 成对匹配时映射查看。没有安装的独立菜单 ID 不凭空补造，PC商城菜单 1036 不借用来授权。

集合版本涵盖完整组及所有行的 id/xmin，包含隐藏或当前页外行；行版本涵盖组与完整目标行。写入先明确 READ COMMITTED，设置不放宽既有值的 5 秒语句、2 秒锁和 5 秒空闲事务期限。固定 advisory 锁保护请求回执，锁定组行，再以数据表 SHARE ROW EXCLUSIVE 防止直接写入产生遗漏，最后校验新快照与素材归属。当前锁会串行其他 group_data 写入，未来写入锁顺序及大规模性能仍需验收。

审计日志保存 actor、operation、id、UUID 和 canonical payload 摘要，业务变更与回执一起提交；同 UUID 同内容重试回放原回执，其他账号或不同内容不得复用。明确 CAS 拒绝在事务回滚后返回实际 HTTP 409，附专用 code、operation、UUID 和摘要。前端只有完整匹配的拒绝证明才能清除未确认请求；网络错误或其他响应保留原请求，页面重载后按账号恢复，可读取回执或主动重试原请求。

## 真实 PC 消费与素材

`/api/pc/get_banner` 读取启用行，按 sort DESC、id DESC 在 SQL 中取前 10 条，再过滤损坏数据；第 11 条不会补位。核心键优先解析，公开最多 100 个扩展字段，每个扩展独立限制字符串 100000 个 UTF-16 单元、深度 16 和节点 10000。超限 opaque 扩展省略该键，仍保留合法核心轮播，管理端完整 JSON 保留不受此公开投影影响。PC Home 实际展示轮播、切换、标题及跳转。安全站内地址和旧 HTTP/HTTPS 外链保留；旧商品详情路径适配新版。拒绝可执行方案、用户信息、协议相对路径、控制字符、反斜线及多层编码绕过，也检查归一化后的路径；正常 `%20` 文件名或查询值保持兼容。

新素材保存稳定 `/api/assets/:id`，不保存临时签名。平台归属、模块、文件类型、R2 图片类型、对象目录、扩展名及 MIME 必须与现有附件读取协议一致；写入时锁定真实附件行，读事务结束后才签名。静态 HTTPS 或站内历史图片不触发远程请求。公开图片最终由实际 signed-asset 路由读取，供应商私有、客服模块及非图片引用不可转成公开签名。

## 验收边界

后端最终4文件44/44通过：10项Admin输入与7项公开解码纯测试，14项Admin原生SQL、9项Admin JWT/HTTP及4项公开原生测试。两端新纯测试20/20、旧PC构建必需回归295/295及路由/权限静态13/13通过，合计372项唯一通过；22未选中排除，早期通过及重复尝试不累加。Worker双类型、Admin与PC类型/构建通过。前序公开解码测试有1项失败，涉及历史单图数组的首项合同修正；没有完整冻结旧源码的红基线，不将该过渡尝试冒充业务回归证明。具体浏览器、失败修正、源码摘要和清理记录见[本批冻结验收](../audit/admin-pc-home-banner-acceptance-20261001.json)。

Admin HTTP通过实际createApp、adminAuth及JWT，注入数据库连接后用app.request验证真实响应，不是网络HTTP服务器。Admin使用独立app/Admin LOGIN、真实ORM八表及既有生产ACL交集和lock-only保护；公开三项owner权限SQL夹具与一项独立app LOGIN三表SELECT切片分开记录。公开签名GET由专用Hono挂实际getBanner/asset controller，R2只返回本地字节，不包括完整createApp中间件/路由及生产网络。浏览器服务实际dist，但API与账号数据为合成夹具；不能替代真实后端业务验证。独立三表或八表权限切片不能称为完整282表运行角色验收；本批没有DDL、扩大grant、生产写入或部署。

浏览器首轮31组24通过/7失败：五项为ElementPlus实际包装层或分页文案定位差异，一项为弹窗关闭动画等待；手机轮播长标题切换按钮覆盖主图是真实显示缺陷，已改紧凑默认指示器并重验PC类型/构建。标题展示和跳转保留，复验在自然初始位置核对指示器边界、header下方及elementFromPoint命中，再普通点击切换，不靠强制点击通过。首轮日志、脚本备份、截图和served bundle摘要保留，不累计为最终通过。

第二轮完整31/31后，root截图复核发现默认紧凑指示器仍8+2行，与标题重叠。进一步将十个按钮单行居中，并给标题底部预留32px；轮播高度不变。最终浏览器增加十按钮同排及标题真实文字Range边界分离断言，所有前序证据和执行脚本保留，重复通过不增加计数。

最终实际构建产物在桌面1440×1000/手机390×844的31组及6项基础检查全部通过，未解释console error/warning、pageerror和等待超时均为0。root查看最终手机轮播、编辑弹层及桌面页面，served JS原始摘要与当前dist吻合。三个原生PG均独立核对status=3、真实端口无监听后移除data；最终复查3个PG和三轮静态服务共9端口无监听，自有Chrome/预览全部关闭。既有组行锁保护还与2026-09-30营销配置验收规范化摘要一致。具体哈希及数量以冻结验收及[独立复核](../../.cache/pc-banner-independent-verification-20261001.json)为准。

该单独轮播页完整承接后可列为候选；PC商城父页的其他设置与整体功能、真实渠道、生产规模和发布项继续开放。
