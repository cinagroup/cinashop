# 供应商商品口令与视频开关

基线 `b3399d0a1c1f8aaa89f86d5c419fb1dfb7ef2fa7`。本批补齐固定 PHP Supplier 商品编辑器已启用的 `command_word`、`video_open` 配置，并通过真实公开详情验证视频显隐。完整 PHP → TypeScript 迁移仍在进行；没有部署、上传旧 PHP 或调用真实提供方。

## 编辑契约

普通创建和编辑仅支持当前供应商的 0/1/3 履约商品。口令和开关复用未修改的 `outProductSettingsInput` 解析规则；不会接入 Out 平台专用 `mer_use`。口令去除首尾空白，最多255个 Unicode 字符，拒绝控制字符、换行和损坏代理项；省略或 undefined 不写 `command_word`，显式空字符串清除。开关接受 0/1、字符串0/1和布尔回显；明确开启须有可用视频地址。

`video_open` 省略且地址未变时保留原开关，修复“保留视频地址、修改其他字段会重新开启”的问题。创建或实际更换地址时，旧客户端仍使用非空地址默认开启、空地址默认关闭的既有行为；地址本身仍按完整商品编辑协议提交。关闭不会清除地址，管理员仍可预览已保存素材；公开详情在关闭时不返回视频地址。

详情增加 `settings_selection` v1，包含 `command_word` 和 `video_open`。前端分开记录口令与视频开关的修改意图；不重发读元数据或旧顶层回显。明确使用已上传视频会同时开启已读的新开关，移除视频会关闭；与口令改动互不影响。旧响应缺少新 selection 时，新输入与开关禁改并省略写入，已有上传、移除和预览操作继续使用原协议。复制保留现有来源字段与受控隐藏继承，不新增复制请求字段。

口令本批覆盖管理配置和读回；没有新增公开口令字段、口令检索或复制接口。公开详情仍使用未修改的产品字段白名单。

## 事务与素材边界

明确作者字段会重新核对实际 Supplier 登录、绑定和管理权限。所有保存仍下架并重新待审核。普通规范化器保持原字节；新增设置在既有事务与商品/SKU锁中保存，核对完整主记录，并在所有元数据作者完成、延迟约束结算后，再核对完整主记录、设置和私有附件元数据。

沿用既有视频稳定引用与素材策略：仅接受正确 MP4 元数据的平台共享素材或当前有效供应商素材，关闭时也不能绑定外部或错误媒体。私有视频使用现有非阻塞附件表屏障协调删除/回收，并比较完整元数据，拒绝同事务后续作者或延迟触发器篡改。新地址和明确开启须重新验证；历史无效公共地址可在未修改时保留以编辑其他字段，也可关闭或清除。公开详情读取仍隐藏无效视频。

没有修改 schema、生产 App/Admin 权限计划、Out 设置实现、公开视频策略或上传/GC存储流程。最小测试作者为执行既有 PG16 视频表锁而增加附件表 DELETE 权限，该权限已在真实 App 计划中；不增加附件名称 UPDATE，独立 LOGIN 的实际权限有 SQL 断言。真实 HTTP 场景另用完整正式 App/Admin 角色安装与审计。

## 实际公开 HTTP 验收

每种履约类型执行 Supplier 创建 → Supplier 详情读回 → Admin 审核 → 匿名公开详情。关闭时公开 `video_link` 及旧 `storeInfo.video_link` 都为空，但数据库保留稳定素材引用。未改开关的普通保存保持关闭并重新待审核；明确开启后，待审核期间仍不可公开访问，重新审核后才返回签名视频地址。之后关闭、清空口令、再次开启均通过真实接口验证。附件 MIME 在数据库中失效后，下一次公开详情立即隐藏视频，恢复正确元数据后重新可见，不复用旧拼装缓存。

测试使用完整迁移数据库、真实独立 App/Admin LOGIN、当前 JWT 和真实服务；单独授予的最小作者没有附件元数据修改权限。认证令牌仅在受控本机签发，未声称覆盖公共登录流程；未调用真实支付、R2、短信或外部提供方。新增 HTTP 场景无需制造订单或付费事实。
