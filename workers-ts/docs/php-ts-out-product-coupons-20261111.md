# Out 商品赠券关联

Out 平台实物商品保存接通 `coupon_ids`。固定 PHP 控制器接收该字段，商品保存服务将其交给商品关系监听器；原实现异步替换 `store_product_coupon.issue_coupon_id`，付款后按订单商品读取发行实例赠券。本批只读取固定旧对象的相关本地业务文件，不上传旧 PHP。

遗漏或内部 `undefined` 保留原关联；显式空数组或空 CSV 清空。数组和 CSV 沿用商品赠券服务的最多100项、去重及升序规则，并限制数据库 ID 范围。遗漏和显式清空具有不同请求摘要，升级前忽略空字段的回执不能被用于执行清空。已提交的相同请求先回放，发行实例之后被删除也不会使原请求重新执行。

选择的是 `store_coupon_issue` 发行实例而非模板：沿用现有商品赠券服务的未删除检查，不臆造发行实例的商家归属，也不把停用状态作为保存准入。付款后是否发放仍由既有付款赠券链按状态、时间窗口和库存判断。Out 商品详情继续从原有一致性读事务返回发行实例标题。

商品主行锁与既有商品券事务锁协调商品编辑入口；发行实例使用 SHARE NOWAIT 锁。主行、券关联、其他受保护关系、SKU 和幂等回执在同一事务内写入。保留关联的原行版本，在最终回执和延迟约束后回读；被选择的关联和发行实例也复核，触发器造成的变化会回滚整笔保存。锁冲突提示刷新。此方案使用现有 App 权限，不增加商品券表 UPDATE 权限，也不单独开启关联事务；并发保证依赖商品券作者遵守现有商品主行锁协议，绕过该协议的直接数据库写入不受该锁协调。

付款集成使用隔离 PostgreSQL 16、真实商品保存、余额付款与 paid-outbox 服务，网络调用被禁止；验证只覆盖本地合成账号和数据。付款套件原先缺少当前付款记录准入所需的运行时存储，原有付款用例同样复现缺口；测试夹具现使用既有正式安装器为两个独立受限 LOGIN 安装并审计付款运行时，既有断言与准入没有放宽。失败过程及最终完整验证结果保留在本批审计和本地记录中。未部署，旧 PHP 未上传，完整迁移尚未完成。

最终验证：130项定向单测、64项完整库存并发PG16、69项完整Out元数据PG16、20项完整付款赠券PG16及两套完整Worker类型检查通过。创建夹具序列、受限角色锁权限、付款存储前置和未完成权限安装的诊断失败均保留；最终重跑没有跳过。完整文件和精确提交秘密扫描见本地完成记录。

完整文件秘密扫描命中一处原测试中的合成 UUID 幂等键；经与父提交逐字核对确认为既有测试标识，非凭据，原始脱敏报告保留。精确提交扫描结果见本地完成记录。
