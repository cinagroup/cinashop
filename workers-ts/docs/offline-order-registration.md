## ORM 不是已经完成保护的数据库

完整 ORM 建库只有表、约束与索引，没有本协议的十函数及保护触发器。
目录检查将精确匹配的结构识别为 `orm-pending`；普通编号迁移和 `install` 均拒绝自动补装。

仅显式 `runOfflineOrderSchema(db, true)` 或维护入口 `complete-orm` 可补装：

```text
node node_modules/tsx/dist/cli.mjs scripts/offline-order-maintenance.ts complete-orm <expected-database> <runtime-role> --confirm-install
```

连接仍必须由独立的 `OFFLINE_ORDER_MAINTENANCE_DATABASE_URL` 提供，精确数据库身份、
远程 TLS、独立 LOGIN 和凭据脱敏规则与[受控安装](offline-order-installation.md)相同。
此命令说明不代表已执行生产操作或取得新的生产授权。

补装沿用固定顺序的十依赖表及七台账 ACCESS EXCLUSIVE NOWAIT 锁，在锁内重新核验目录，
并要求七张未受保护的台账全部为空。任何一表有记录即拒绝，不认证、补造或修复历史凭据。
只创建缺少的协议函数和触发器，不重建已有表、索引、约束，不自动修复 ACL。
最终完整指纹或函数默认权限不合格则整个事务回滚。普通 `v1` 重复核验仍允许已有可信流程记录。

九路径审计新增独立协议检查：外部及内嵌路径必须已经是 `v1`，不能靠审计器补装掩盖漏注册；
七条 ORM 路径必须精确为 `orm-pending` 才显式补装。补装和两次重复执行检查所有既有 public
关系/索引/序列和函数的 OID、存储文件保持不变。该检查不宣称全应用触发器或权限均已认证。
