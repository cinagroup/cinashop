# Supplier 查看物流（2026-10-19）

恢复 PHP 订单详情与发货子单的“查询物流”操作：真实 `orderList/components/orderDetails.vue` 调用 `GET /order/express/:id`，公共 Order trait 返回 `delivery_name`、`delivery_id` 和 `result[{time,status}]`。本批保持逐个具体包裹的查询语义；不把拆单根聚合为一个运单，也不使用原“订单轨迹”中的支付／发货日志生成承运商节点。

新增 Supplier GET 路由保留上述字段，并复用 ExpressService 的 `packages`、真实承运商／缓存来源与明确服务状态。数字 ID 必须属于当前供应商；平台分配根只可由已归属子单内部核对，不能直接查询或暴露其余供应商的包裹。子单同时校验买家、门店和父单归属。系统删除不可查询，客户删除保留已有员工历史读取合同。查询不接受额外参数、客户 UID、供应商请求头或外部服务地址作为权威输入；鉴权及错误响应均为 private/no-store。

读取运输事实后先提交短 REPEATABLE READ / READ ONLY 事务，再访问既有固定 Aliyun 服务或 KV 缓存；返回前在全新短事务重新检查实际 JWT 身份、到期、密码、供应商、角色／菜单以及所选单与父单运输事实。角色和管理员事实版本同时约束权限撤回／恢复，不承诺检测运输字段在两次快照之间同值往返的所有历史。继承调用方事务会被拒绝，避免旧快照跨越网络等待。未配置、暂不可用或无轨迹分别明示；SQL 运行环境缺失不会伪装成承运商未配置。缓存允许填充，数据库行与序列保持只读。

Supplier 详情抽屉的单单和每张已填运单的快递包裹卡片均提供独立“查看物流”。弹窗明确显示包裹订单号、公司、运单、来源和承运商时间线，可主动重读；严格解码单包裹身份及 PHP 兼容投影。关闭、换单、抽屉重读／关闭、离开路由、账号或权限变化和卸载会取消并清空，单调请求代次阻止 A→B→A 的迟到响应恢复内容。预览模式明确提示登录后查询真实物流。

执行命令、去重计数、源码指纹、真实 PG16 / Browser 结果与限制以[本批账本](../audit/php-ts-supplier-order-tracking-20261019.json)为准。Browser 使用实际 Supplier 生产构建、Hono / JWT 和独立 SELECT-only LOGIN，承运商响应受控；这些证据不代表真实 Aliyun 账号、Chrome 扩展连接、真实设备或线上发布验收。实际 Supplier 发货闭环复用成熟 checkout／allocation，测试付款标记仍为夹具 SQL，不能冒充真实支付或 Customer HTTP 验收。整体迁移和发布门禁保持开放，保留用户裁定的 get_script 恢复合同及其已修订退役审计。
