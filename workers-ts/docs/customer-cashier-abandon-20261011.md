# 普通客户次卡收银原意图耐久放弃（2026-10-11）

本批补齐普通 UserJWT 次卡现金收银中“原创建或付款结果未知，但经营资格、选品、表单或实际金额已经变化”的恢复出口。完整 PHP 到 TypeScript 迁移仍在推进；本批不能代替完整旧五页、多商品、多支付渠道、退款或生产验收。

## 状态与接口合同

`GET creations/:key` 或 `payments/:key` 的 `receipt:null` 只表示读取快照中没有已提交成功凭据，不证明迟到请求不会执行。新增相同原路径下的 `POST .../:key/abandon`，正文为 `{version:'customer-cashier-abandon-v1',kind:'creation'|'payment',intent:完整原正文}`，路径与 `Idempotency-Key` 都使用本机原 UUID。

放弃和最终业务事务共享原 actor／UUID 锁。放弃先提交，则持久化完整原正文、SHA256、身份和时间，后续原编号写入必须拒绝；真实创建或付款先提交，则返回原实际成功凭据，不写放弃记录。出现无法核对的订单、付款或来源事实时拒绝证明放弃，保留原编号继续核对。创建放弃不删除订单，付款放弃不取消订单、不退现金、不撤销 UNKNOWN 渠道受理。

回复保持 `customer-cashier-receipt-v1`，增加 `abandonment`。`receipt` 与 `abandonment` 都为空是未知；成功凭据或完整放弃证明最多存在一个。放弃证明使用 `customer-cashier-abandon-v1`，包含原 actor、UUID、kind、request_hash、scope_key、完整 intent 和数据库 UTC created_at。原有效登录会话可在经营资格撤回后查询或放弃；失效会话、密码失效或另一账号不能据此取得原结果。

前端在发送放弃前，必须持久化并回读核对“已选择放弃”的决定。回复丢失后只能查原编号或重试同一放弃，不能重新开放创建、付款或恢复。成功回包只是传输反馈，前端另查原编号，严格核对完整原意图与持久化证明后，才允许关闭本机记录。已消费订单图片和来源保持实际事实；未创建的冻结图片可随放弃证明关闭本机准备记录，重新选品必须使用新的 UUID。原私有对象及数据库准备事实保留，不将放弃伪造为图片取消或自动删除。
