## Old PHP contract

`route/api.php:341` declares authenticated `GET /api/user/routine_code` under station-open and required AuthToken middleware. `app/controller/api/v1/user/UserBill.php::getRoutineCode` returns exactly `{url}`. Its `is_promoter` value is part of the attachment name `<uid>_<is_promoter>_user_routine.jpg`; this endpoint does not require promoter privileges, inspect an agent level, register a user or mutate financial balances.

When it needs a new image, the old controller obtains `qrCodeForever(uid, 'spread-'+uid)`, then calls `QrcodeServices::getRoutineQrcodePath(qrcodeRowId, uid, 99, name)`. `QrcodeServices.php` maps type99 to `pages/index/index` and builds `id=<physical qrcode row>&spid=<publisher UID>`. The old UniApp home/App entry consumes `spid` for its recommendation intent. The physical qrcode row ID is not an employee or agent identity. The old API's persisted attachment is a downloadable absolute URL; local upload paths are prefixed by configured `site_url`.

The type99 mini request uses the unlimited mini API and a persisted forever spread record. It does not read `spread_share_forever` to decide its lifetime and does not request an official-account ticket. That setting belongs to the separate official poster branch in `UserBill::getSpreadInfo`. The legacy metadata row called “forever” must therefore not be mistaken for an official permanent provider ticket.

## Accepted source alias

The controller preserves the one-field `{url:string}` response. It constructs the real current UserJWT actor from UID, password version and token expiry, rejects query parameters and applies private/no-store response headers and the existing bounded share budget. It delegates to `UserProfileService.routineCode(actor)` and `LegacyShareCodeService.routineCode(actor)`; it does not accept caller-supplied UID, agent identity or a target override.

The alias invokes the existing controlled distribution target `-1`, official-browser false, with a narrowly scoped `requireMini` option. After its RR READ ONLY authoritative SQL account/config snapshot, an absent or blank SQL mini AppID returns 503 before cache mutation or provider access. A stale cached AppID cannot substitute for that SQL identity. Enabled mini configuration with missing credentials or a failed image returns an error without publishing a website-only ready artifact; a bounded pending cache checkpoint may remain for recovery. The non-official generic `get_qrcode(-1,false)` mode keeps its inherited empty `routineUrl` when mini is disabled and its existing temporary lifetime.

Mini content is `scene=q=<24 lowercase hex>`, `page=pages/share/landing`, `check_path=true`, `env_version=release`. The registered landing reads the authoritative scene and receives `type:-1`, `id:0`, `spid:<publisher UID>`, the configured `h5_origin` and the controlled home destination. The existing referral intent owns the recommendation transfer; no client identity hint determines the publisher. Current output is a genuine PNG from the controlled mini provider transport, not a substitute website QR.

`url` is made absolute against the actual API request URL. Its download host, port and protocol remain those of the API request origin; `PUBLIC_H5_ORIGIN` is the landing-site authority, not the image download origin. The alias does not silently force HTTPS or return a relative URL to an inherited native downloader. The test verifies an absolute API-origin signed download distinct from the configured H5 origin. Deployment must expose that actual API origin to the existing download client.

## Permanent target, short download capability

The alias alone selects a permanent mini descriptor with `official:false`, `permanent:true` and an empty inactive `officialApp`. Its HMAC-derived index differs from the normal non-official generic `-1` descriptor. The index `lsc:<HMAC28>` and artifact `lshare:<opaque24>` both have `expireTime=0`, with signed document `expires=0`. The normal non-official generic `-1` still has a separate token and 30-day expiry. The new test checks both permanent rows and advances Date by 31 days: the alias reuses its opaque target, refreshes the download signature and makes zero provider calls.

Changing unrelated `wechat_appid`, `share_qrcode` or `spread_share_forever` does not change this permanent mini descriptor or invalidate its target. This independence is covered by the seventeenth case. Generic/official share behavior retains its existing rules and signatures. No existing Mini product, activity, employee-invite or other shared method is rewritten by this alias.

Each image download capability still expires after at most 900 seconds. Signature validation, current artifact/account/config checks, actual raster validation and no-store apply to download reads. A permanent printed mini target is not an indefinitely reusable signed image URL. The old signed URL expires; an authenticated generation refresh returns a fresh URL for the same valid target.

Permanent zero expiry is compatible with the existing database-cache contract: `DatabaseCacheService.get` reads expiry 0 or an unexpired timestamp. The old PHP cache purge predicate is `expire_time <> 0 AND expire_time < now`, excluding zero. The module does not add read-triggered cache cleanup, new production grants or business-table mutations. Production permission to read authority and mutate only this module's cache keys still requires separate runtime acceptance.

“Permanent” describes target lifetime, not an irrevocable capability. Current owner deactivation/deletion, mini AppID rotation or H5 origin change invalidates the artifact through fresh authority/config checks. Generation authenticates the current password version and repeats that check after provider work; password rotation before publication prevents publishing. The persisted public descriptor does not bind the publisher's password version, so password change alone does not immediately revoke already issued public images or public scene tokens. This migration makes no stronger revocation claim.

The current registered landing uses the existing TS `ShareReferralIntent` and authenticated `/api/user/spread` path. The existing `UserFinanceService.bindSpread` preserves an established relationship, checks active accounts and cycles, writes its existing relationship/friend audit, grants the existing referral lottery effect and evaluates existing agent levels. This alias adds no registration, commission, balance, experience or writeoff mutation.

The complete PHP recommendation policy is broader than this URL adapter. PHP `UserServices::spread` has permanent, temporary and time-limited rebinding configuration, and invitation-experience effects. PHP registration listeners also dispatch invitation experience, signup promotion commission and AgentJob; promotion commission has its own promoter/config/day-limit rules. The existing TS relationship chain is not proven fully equivalent to all those PHP policies by this alias. Such financial behavior remains an independently scoped migration concern. The frontend intent attempts binding once and reports failures; it does not promise eventual binding after a network failure. QR generation, navigation and recommendation UID correspondence are the acceptance claims here.
