## 实际承接

旧 PHP 的 `kefu` 要求当前 UID 对应有效客服且 `status=1/account_status=1`。`work` 使用 `customer=1`，该字段表示手机订单管理，不能推成店长。个人中心只发布明确配置的 `PUBLIC_KEFU_ORIGIN`：必须是 canonical HTTPS origin，且同时列入两份现有 allowlist；未配置、无效配置或无当前角色时隐藏旧相对入口和已知客服 origin 的绝对入口。登录独立，不携带 UserJWT／AdminJWT，不从其他 allowlist 或 API origin 猜测正式站点。

注册客户与游客按 `(uid,is_tourist)` 分域；当前有效账号、唯一归属记录、游客指派及其期限共同约束列表、历史、发送、上下文与通知。历史记录的 `type` 是客户端来源，不能作为客服身份。跨域通知保留脱敏摘要；实际正文仅投递给当前正在查看同一客户及域的有效客服。列表返回、离页和退出清除查看状态；在线状态由 `store_service.online` 的服务端确认提交。

转接和客户标签／分组修改复用相同 transfer→chat 锁与同一事务，原生普通 LOGIN 会话验证真实互斥。迟到的旧归属通知、旧 transfer-in 及旧消息不能恢复已移出会话，重新指派后的新会话也不会被旧 transfer-out 清除。私人商品购买／浏览／热门记录复核当前客服归属与客户软删除；公开商品搜索保留原有边界。既有订单读取维持其原授权历史语义，不把本批商品上下文的新增软删除条件冒称为所有订单合同变化。

前端按账号会话 revision 拒绝旧 HTTP、上传、上下文和 WebSocket 回调；过期连接不自动重连。实际消息 ID 用于同秒摘要排序和迟到通知拒绝，会话行 ID 不作消息版本。当前已读确认继续使用真实服务端计数。商品／订单／退款的 5/6/7 消息消费真实详情接口，无效数据明确不可用。手机三域按钮、列表／聊天模式及桌面布局经过实际编译浏览器验证。
