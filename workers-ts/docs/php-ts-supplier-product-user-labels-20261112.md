# 供应商购买用户标签配置与付款任务验收

基线 `ec39001cb043737a3108e073c0da39e2beb1ad8a`。本批补齐供应商商品 `label_id` 的编辑、只读平台目录、版本化读回和实际付款后的标签任务验收。商品展示标签仍使用独立的 `store_label_id`；不会复现旧 Supplier 页面把展示标签编号写入用户标签的错误。完整 PHP → TypeScript 迁移仍未完成。

## 契约与归属

- `POST /supplierapi/product/product/0` 和 `POST /supplierapi/product/product/:id` 接受显式 `label_id` 数组，包括旧版 `{ id, ... }` 回显行；仅编号参与目录准入。复用未修改的 `outProductLabelIds` 和 `lockOutProductLabels`，拒绝重复、非法编号和超过实际 varchar(64) 的 CSV。省略或 undefined 不操作 type4 关联；`[]` 明确清空。
- `GET /supplierapi/product/user-label/catalog` 仅映射 `supplier.product.view`，分页最多50、搜索最多128字符、按字面值处理 `%`/`_`，拒绝重复与越权范围参数；响应 private/no-store。目录只提供有效的 type0/relation0 平台用户标签。
- Supplier 普通订单的财务 `store_id=0`；履约 Supplier 或门店不提供用户标签归属。既有 type2、外部门店、停用或缺失标签可安全读回和移除，外部名称不会泄露；不能重新绑定。
- 详情新增 `user_label_selection` v1，保留 ID 顺序、可用性及异常关联诊断。坏 CSV 可读、未修改保留，显式清空可修复。前端独立 dirty 状态，不回传读元数据或旧的顶层 `label_id`。
- 当前配置声明通过 `runtime_configured` 单独投影。缺少可信声明时页面明确提示“当前仅保存配置，不会自动给用户打标签”；声明存在也只表明配置，并不把它冒充 SQL 就绪证明或成功回执。HTTP 保存不能启用任务。

## 写入边界

仍仅支持当前供应商拥有的 0/1/3 履约商品，保存后下架、重新待审核。请求前后重新核对当前登录、供应商绑定和真实管理权限。目录行使用 SHARE NOWAIT，主记录采用完整预期行核对。现有品牌、保障、参数作者仍保持原来的关联保护规则；用户标签关联在这些作者完成后单独替换，并保护所有非 type4 关联。最终结算延迟约束，再核对完整主记录、完整目录行、准确 type4 行及非 type4 行，干扰则整体回滚。

没有修改 schema、生产权限计划、付款消费者、标签任务/回执实现、Out 平台商品替换器或复制协议。现有 App 权限已覆盖目录读取和共享锁。受控测试只为新详情投影增加 `user_label SELECT`，专用测试作者增加锁所需的 `UPDATE(id)`；不授予标签名称编辑权限。

## 实际业务验收

三个履约类型均执行真实 Supplier 创建 → Admin 审核 → 买家加购、报价、订单创建 → 余额付款 → `order.paid` 消费 → 独立购买用户标签任务。所有 SQL 来自完整迁移数据库，并使用真实独立 App/Admin/Financial/Manager/Cashier LOGIN；可信维护安装器显式建立五角色声明，业务请求不运行 DDL 或切换角色。JWT 在受控本机签发，未声称覆盖公共登录流程。

每种商品数量3、单价10.00，余额100.00→70.00；重复创建只分配一次单号，重复付款不重复扣款。付款任务创建后、标签执行前，通过真实 Supplier HTTP 修改当前标签，源商品已隐藏并待审核，任务仍读取最新绑定；订单商品行保持不变。已有标签记 `added:false`，停用标签写 `retired` 跳过回执，缺少的准确平台关系追加一次。财务范围保持 type0/relation0，其他用户及外部门店关系不变。清空当前绑定和重复 paid/task 消费不改原成功回执；人为移除关系后重放不会补回。

新增 Supplier 场景直接调用真实 paid 消费者与标签任务服务；既有购买标签完整原生文件另外验证实际 Worker Queue 路由和角色边界。Queue、单号服务、KV、R2 仅使用有限本地适配；所有场景禁止外部 fetch。未部署、未上传旧 PHP、未调用真实支付或通知服务。
