# Supplier 订单列表筛选与原订单号发现

## 实际 PHP 入口

PHP Supplier `order/orderList/index.vue` 实际挂载时间、订单类型、业务状态、支付方式与搜索字段；`api/order.js` 的列表请求经 `route/supplier.php` 进入实际 Supplier `Order::lst`，再到共用 `StoreOrderServices::getOrderList` 和 `StoreOrderDao::search`。本批按这条可达链迁移筛选，不能把一个存在的路由或原始 status 相等当成完整列表合同。

`type` 是订单活动类型0普通、1秒杀、2砍价、3拼团、4积分、5套餐、6预售、7新人、8抽奖，不是商品 product_type。PHP UI 的业务状态0/1/2/3/4/-4分别表示未支付、未发货、待收货、待评价、交易完成、用户已删除；后台还支持其余共享业务选择器。沿用 `OrderReadStatusPredicate` 的全部14种真实规则：未发货含 paid1/raw0或4/refund0或3/shipping1或3；待收货字面为 shipping1/raw1或5，或 shipping2/raw0或5，不自行扩大到 shipping3。查询资格不授予供应商核销能力，PHP 对应核销路由仍被注释。

UID、订单号、收货人姓名、电话、件数是精确相等；商品名称查当前 `store_product.store_name/keyword` 经实际商品行关联，不能改成成交快照标题。全部搜索另查当前用户、地址联系人及三类活动。活动按订单 type 选择实际 ORM 表与名称字段，避免 PHP 未区分活动类型时同数字ID的错误命中。目录、用户和地址只用于 SQL EXISTS，不将其私有字段投影到列表。详情继续返回不可变商品快照。

## 现代接口与界面

GET `/supplierapi/order/list` 保留无 field_key 时既有的 real_name 优先于 order、三字段模糊搜索、通配符及 raw status0..5。显式 field_key 才启用扩展字段搜索；扩展模糊搜索将百分号、下划线和反斜线当作文字。business_status 独立表示 PHP 业务选择器，与非空 raw status 互斥；活动 type 与原导出 type0/1 各有自己的合同。支付方式继续接受有界名称，并把 PHP 数字1..5映射到微信、余额、线下、支付宝、积分；不通过继承属性解析支付名。

start_time/end_time 各自可选，都是0至2147483647的明确 epoch 秒，使用闭区间。页面的日期时间输入按查看者本地时区转换，并标明本地时间；不复刻 PHP 服务器上海时区的模糊字符串解析及午夜自动扩日。无效日期、反向区间、重复参数、未知枚举、无效数字和过长文本均明确失败。

界面提供全部七种搜索字段、九种订单类型、六个原 UI 业务状态、支付状态/方式与起止时间。查询回到第一页，重置清除全部条件；更换查询清空已选导出和旧详情。分页、错误后重查、路由离开、会话/权限变化与 A→B→A 仍受真实请求代次约束。用户已删除、退款完成及部分履约按事实展示：raw5在shipping2表示部分核销，在shipping1/3表示部分收货。refund_status3表示部分退款，不能误当refund_type3的拒绝；页面同时展示部分退款与当前履约阶段。

既有现代列表保持 pid>=0 的本店实际行、原 ID 倒序和 list/count/page/limit，不把 PHP 可能列出的审计根混入订单金额。显式订单号或全部搜索的编号分支新增原订单号发现：仅在父买家及门店/供应商关系一致，或实际平台根已完成供应商分配时，返回本店叶子包裹；根私有资料和其他供应商子包裹不返回。这是对现代平铺列表的补充，不能声称 PHP 原本有相同独立解析器。

列表与 count 沿用同一短 REPEATABLE READ/READ ONLY 事务和不放宽会话的5秒语句预算。无写入、外部请求、新 DDL、生产授权或发布。真实额外目录权限由自有夹具独立 SELECT-only LOGIN 验证；本地辅助表的最小 ORM 列定义不代表完整生产迁移目录安装。
