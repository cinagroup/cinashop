# 商品页内新增规格模板（2026-10-18）

本批接通多规格商品编辑页中的“添加规格模板”，商品表单保持挂载。模板创建后只刷新目录；用户明确选择并确认“套用模板”后，才替换商品草稿的规格结构与新 SKU 行。整体 PHP→TS 迁移继续推进。

## PHP 实际合同与实现

启用的 PHP `view/supplier/src/pages/product/productEdit/index.vue:298–317` 提供模板选择、明确确认和添加按钮，1075 行挂载 `add-attr`。2570–2576 行的 `getList` 只重读 `productGetRule`；`components/addAttr.vue:164–182` 成功创建后只关闭并清空模板弹窗、通知父页刷新目录。模板不保存当前商品，也不自动选中新模板。

共享 `useSupplierProductRuleEditor` 和 `SupplierProductRuleEditor.vue` 复用既有独立模板库的作者、版本校验与恢复规则。商品页包装组件延迟读取完整目录快照，在核对实际创建结果后刷新 `get_rule`，仅替换商品页模板目录。新旧目录的 `rule_value` 表示在此边界显式转换，维持已有商品接口约定。

模板名称、1–3 个维度和每维 1–50 个值沿用成熟校验。模板库可保存超过 200 种组合的结构；商品套用先完整校验最多 200 个 SKU 和逗号歧义，失败时不改草稿。套用会生成价格、库存为零的新 SKU，需用户补全并独立保存商品；已有 SKU 的删除或改名仍由成熟服务拒绝。

## 写入、恢复与身份边界

创建捕获完整当前供应商目录版本和已有 ID，冻结本次请求。服务回执必须经过完整 GET 核对 ID、名称、规格和行版本后才算确认。响应丢失时保留当前挂载窗口的不可变请求，阻止重复 POST 和关闭；“核对执行结果”只 GET。无回执 ID 时仅接受原快照中没有的新 ID 且内容恰好匹配的唯一结果，不能将预先存在的相同模板当作本次成功。

实际拒绝才允许用户修改后再次提交；已经收到成功回执后读取失败不能转为可重试写入。模板已确认但商品目录读取失败时，显示独立错误并允许只重读目录。未能确认事实时，必须先实际读取，再由用户明确结束当前操作。

恢复限于当前挂载窗口的事实核对，不提供跨刷新持久请求、UUID 或服务端精确操作归因。路由、身份或权限变化会中止旧请求并拒绝迟到回填；商品页既有身份变化清空旧草稿的规则保持。共享弹窗使用 append-to-body、居中及受限滚动区域。

## 验证边界

最终去重919项：606项相关前端（含共享弹窗40项最终复跑，重复不加总）、272项runner、40项真实PG16及1项浏览器。新增10项原生包含受限模板作者和真实SKU下单；类型修正后单独重跑下单用例仍通过。最终命令、用例数、指纹、真实浏览器截图及自有数据库清理结果见[验证账本](../audit/php-ts-supplier-product-rule-inline-20261018.json)。受限 Supplier LOGIN 的模板作者、真实 App/JWT 商品创建与 Admin 审核、Customer 报价下单分别验证；Customer SQL 沿用自有 finance_test maintenance 连接，不称为独立 Buyer LOGIN。

浏览器只验证 Supplier 生产包。实际创建id400的响应在服务提交成功后丢失，GET恢复后仅1次创建、商品POST为零。48张表、47个序列逐GET比较，23次GET全部零写。取消、恢复和明确选择3个检查点各比较103个商品DOM输入值保持一致；确认套用后才出现4个新规格行。桌面 1200×844 和手机 390×844 同源 iframe 检查弹窗及按钮命中。实际设备、Chrome 扩展连接、生产环境与部署不在该证明范围。

继续保留用户裁定的 `/api/get_script` PHP 兼容行为及已修订退役审计。父迁移项与原复选行保持开放；本批通过独立分支及基于 PR110 的草稿 PR 推送，新提交 CI 状态须以 GitHub 实读为准。

该轮桌面、手机三维度弹窗的输入和页脚中心命中均未被遮挡，手机表单实际可滚动；两个页面的error/warn采样均为空。3座自有PG16均夹具清零、无postmaster.pid，独立pg_ctl status为3。首轮复制夹具携带原SKU身份、目录DTO类型差异和原生测试类型诊断均在账本保留，不计作成功验证。
