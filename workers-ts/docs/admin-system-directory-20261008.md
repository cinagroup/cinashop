# Admin 管理员与角色目录增量

基线为 `d5c31e87513df2ff57defa809f3f8b986c364643`，实现位于本地分支 `codex/admin-system-workflow-20261008`。旧列表最多返回 100 个管理员、50 个角色，页面没有完整分页、筛选、管理按钮门禁或读取失败状态。本批新增独立目录接口和对应页面交互，原列表数组接口及原写入接口保持兼容。

## 查询合同

`GET /adminapi/system_admin/directory` 与 `GET /adminapi/system_role/directory` 同时注册 `/api/admin/` 前缀，均由 `adminAuth` 验证实时 `system.view`。响应为 `{ list, total, page, limit }`。

参数仅允许 `page`、`limit`、`keyword`、`status`，重复或未知参数拒绝。默认第 1 页、每页 20 条；页码 1–500、每页 1–100 条、偏移最多 10000。关键词最多 64 个字符，不接受控制字符，按字面子串匹配，转义 `%`、`_` 和反斜杠；状态为空或 0/1。管理员匹配账号、姓名、手机号，角色匹配名称，均按 ID 降序。

管理员限定 `admin_type=1`、`is_del=0`；角色限定 `relation_id=0`、平台类型 0 和历史平台类型 1。两个目录排除已删除状态。管理员只返回八个页面字段，角色只返回五个目录字段及已解析的权限键，不返回密码。总数、当前页及旧权限解析使用同一 `REPEATABLE READ, READ ONLY` 事务，设置本地语句、锁等待和空闲事务上限。响应禁止缓存。

## 页面行为

两张列表各自拥有关键词、状态、页码、总数、加载和错误状态。查询或重置从第一页读取；失败保留上次读取的列表并暂停编辑，不把失败伪装为零条记录。表格内部滚动，筛选和分页使用中文文案。

只读账号不显示新增、编辑、删除操作。重复提交由共享操作锁阻止；删除确认取消与实际 API 失败分别处理。权限目录必须成功加载后才能保存角色，旧数字或未登记规则只可查看。权限树重读关闭旧编辑器，重新打开时重建原勾选，避免意外保存为空权限。

请求绑定当前账号和单调递增会话代次，取消旧读取并丢弃迟到响应。退出、撤权、账号变化和卸载清空个人资料、密码及草稿。仅 Pinia 中的权限变化不会从旧 localStorage 恢复原权限；真正的登录状态事件才同步持久状态。
