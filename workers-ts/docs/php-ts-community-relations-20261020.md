# H5 社区发布话题与商品关联

补齐 PHP 社区发布页已有的最多 5 个话题和最多 5 件商品选择。来源为 `cinashop-php/view/uniapp/pages/discover/discoverCreate/index.vue` 的 `changeTopic`、`selectItem`、商品来源标签和查询分页，以及 `app/controller/api/v1/community/Community.php` 的 `getProductList`。H5 使用已迁移的 `/api/community/topic`、`/api/community/product_list` 与 `/api/community_save`，保持 `pay`、`collect`、`visit` 和 `topic_id`、`product_id` 合同。

商品选择器按当前账号查询已购日志、商品收藏及未清除的浏览日志。关键词匹配商品名称或关键词，每页 10 件；分页重试保持原搜索词及页码，重复条目去重，切换来源保留已选商品。话题支持本地搜索。选择数量限制沿用 PHP 页面，服务端原有 ID 数组兼容规则保持。这里的已购来源是现有 `pay` 日志，不将合成日志当作真实购买历史迁移证据。

候选商品必须当前已审核、上架且未删除。发布事务按 ID 顺序锁定话题和商品，对停用、下架、未审核或不存在的关联重新校验；失败时帖子与关联一起回滚。详情展示当前有效话题、商品及当前价格，停用后不再显示对应卡片，历史关联 ID 保留。商品导航进入既有商品详情路由，话题导航进入既有话题列表。

选择器请求受账号、页面生命周期和查询代次约束，迟到响应不会覆盖新查询或另一账号的草稿。发布期间与结果未知时不能修改关联。旧话题入口必须先解析当前话题目录；原话题已停用时，用户需要重试解析或明确放弃原话题，才能继续发布。图片、视频、文字发布及已恢复的 `/api/get_script` 行为继续兼容。

## 验证边界

运行时测试加载真实 Vue、Pinia、请求层、API 适配器、发布组合函数及页面脚本，只替换原生生命周期和 I/O。后端测试通过真实应用路由、JWT 与 ORM，另用原生 PG16 的独立连接验证锁等待及提交后重验。后台浏览器使用实际 H5 构建和实际应用请求；账号、来源日志和数据库为本任务合成数据，导航外壳为测试替身。商品详情路由由实际页面运行时测试核对，浏览器覆盖相关商品展示和话题跳转，不代表完整购买流程或真机验收。

本轮仅覆盖发布关联选择和详情展示，未将编辑页、小程序或 App 声称为已验收。整体 PHP → TypeScript 迁移继续推进。

最终验证：488 项单元、35 项 H5、11 项原生 PG16、1 项后台浏览器测试通过，扣除 4 项重复的关联 API 原生重验，共 531 项独立用例，其中 20 项新增；类型标注修正后的 4 项定向重验另行记录、不重复计数。两套完整 Worker 类型项目与 H5 类型检查/构建通过。首次 Worker 类型检查发现新测试中 5 处可空标注错误，修正后完整复检通过，失败候选保留在审计记录。

后台浏览器十阶段使用 18 次真实应用请求，仅 1 次发布 POST，落库 1 条待审核帖子及 5 条关联；详情显示两话题、三商品，话题跳转后待审核帖子未泄漏到公共列表。390 像素页面无横向溢出，控制台无应用错误，有一条既有 vue-router 导入告警。额外验收确认请求为 0，临时标签页已关闭，两座自有 PG16 均确认停止，数据和日志保留。内置浏览器已连接；外部 Chrome 扩展未出现在连接列表，不据此推断安装状态。完整命令、哈希、截图路径与边界见[验收记录](../audit/php-ts-community-relations-20261020.json)。
