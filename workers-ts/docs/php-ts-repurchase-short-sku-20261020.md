# 普通短 SKU 订单再次购买

基于 `3a99e893b15c94a9f5e5661048a30b9df8960c28`，分支 `codex/repurchase-short-sku`。普通短 SKU 的新订单已冻结规范身份，但再次购买将历史 `short7` 与 PostgreSQL `char(8)` 返回的 `short7  ` 直接比较，把合法订单误报为规格失效。本批闭合实际原订单→再次购买→当前价格结算的缺口，整体 PHP→TS 迁移保持 active。

## 合同

仅对数据库已按基础商品、普通类型及未退役条件选出的 SKU 去尾空格比较。历史各别名、商品归属和数量继续严格核对，历史空格或冲突不会被修补为有效数据；同一规范身份命中两条当前规格仍拒绝。源码中 SKU→商品的锁顺序、等锁后重读、库存汇总、限购、会员和预售分派保持，DAO、模型、迁移 SQL、订单创建作者和受保护凭据均未修改。

再次购买仍只接受买家自己的订单号，从物理商品行取得件数，准备独立的 `isNew=1` 结算选择。明确再次准备产生新的独立 ID，已确认选择、旧购物车及原订单保持。当前价格重新核算；历史价格和赠品权益不复制。该接口不创建订单、不付款、不预留库存。未付款来源的 API 兼容保留，实际页面入口仍遵循已收货/已完成的 PHP 条件。

新增夹具在实际创建前设置短 SKU，显式调用真实作者捕获收费原购与最终实物原购，再沿成熟同 key 幂等路径得到来源。收到状态与付款准入仅为本机合成状态，Supplier 分派使用实际服务；成功来源没有改写已创建快照或凭据。旧夹具默认仍使用原 8 位规格和原创建方式，新增选项只用于明确的新场景。

## 验证

9 项新增原生 PostgreSQL16 用例通过：实际未付款与已收货来源、严格历史别名、当前错商品/错活动类型/已退役规格、真实重复规范身份及实际 SKU 锁等待。成功路径按当前 SKU 18.88 元算出两件 37.76，另行 30 元；商品基准价特设 17 元，防止遗漏真实规格。新选择之外全 283 表、229 序列、原订单/财务/库存/积分保持；本机夹具中该接口未写 CONFIG_KV；后续旧报价允许成熟短期预览键。

完整 runner 单元回归 381 项通过，其中 8 项新增边界核对固定文件和单一维护浏览器别名，拒绝混用、错误拼写和过滤方式。双端 Browser 2 项、14 阶段通过，完整成熟订单回归 52 项通过。合计 444 项独立通过（381 单元、61 原生 PG、2 Browser），其中 19 项新增；两套完整 Worker 类型项目均通过。最终去重计数和命令终态记录于[审计账本](../audit/php-ts-repurchase-short-sku-20261020.json)。所有重型验证共用串行锁，Vitest 单 worker。

Browser 使用后台 Cua 内置浏览器和固定 `127.0.0.1:40751`，PC/H5 各使用独立来源订单号及实际生产构建。真实 App/JWT 完成原订单→再次购买→精确直接购买选择→当前报价；商品小计 67.76，运费 6 元另计，应付 73.76。随后真实准备成功后注入一次响应丢失，页面禁止重复准备；生产「重新读取原订单」保持结果未知，原订单读取失败清空旧详情，生产「重新加载订单」恢复后仍保留禁用。此处重读为同一页面内读取，未声称跨整页重建持久化结果未知。H5 在第二次明确准备之前建立新文档上下文，既有已确认 ID 在仅切换 hash 时仍正确保留。

33 次业务请求中，29 次读取/报价逐次核对全 283 表、229 序列不变，4 次实际准备只新增各自两条选择及购物车序列。R2/provider 为 0；新订单创建和付款未通过浏览器执行。447 份既有构建逐字保持，PC 控制台无 error/warning，H5 仅两条既有 router 导入弃用 warning。合成会话、收货/付款准入和维护价格编辑明确标注，不代表生产权限、支付渠道或真实设备。临时标签已关闭、用户标签保留，确认请求 0，全局浏览器安全配置未改。

初次调用仅因参数顺序在 runner 校验退出，没有启动 PG；第二轮发现旧夹具未启用新原购捕获，修正明确选项并保留双凭据断言。第三轮实际到达再次购买 400，复现本次生产缺口。首次 Browser 中操作员在未知结果场景误用了整页导航，主动结束聚合并清理，未计通过；相同源按生产重读流程重验后完整通过。各失败、未选择用例、源指纹限定及自有 PG 清理见账本。

## 仍待迁移

本批限普通商品当前 SKU 身份匹配，不声称预售或全部活动短 SKU 整链已完成。旧 8 位规格的当前预售转换继续使用既有规则；预售目录/选购/快照的短键限制仍需另行核对。累计历史保持 `incomplete`，可信账户历史覆盖、无界终身计量及统一并发额度占用/释放仍开放，不把统一拒绝记为累计限购迁完。
