本批接通实际启用的供应商单位选择与客户端数量单位消费。完整商品编辑器与 PHP→TS 迁移尚未完成，未扩大履约类型或单位管理范围。

## 实际合同与消费者纠正

PHP 证据根目录为 `/home/cina/cinagroup/cinashop-php`。实际 standalone 商品编辑路由与商品列表编辑入口挂载 `productEdit/index.vue`；其74–91行启用按名称选择的可搜索单位目录，created/getAllUnit 实际调用 `product/get_all_unit`。新增单位入口是注释，不作为新增 CRUD 合同；异步目录缺项便清空旧值的 watcher 也不复制为新的破坏行为。

TS 后端现有 `productUnits` 已从认证身份取得供应商，以平台 type0/relation0 和当前供应商 type2 范围筛选启用、未删除单位，按 sort/id 倒序读取。PHP 注释掉的归属谓词不恢复。商品已有 `unit_name` 文本作者、完整保存回读、复制安全字段及公开投影，本批没有新增字段或单位行外键。完整保存的32 UTF-16单位长度、空值／省略／null归一为“件”的既有规则不改；这与推荐图的省略意图合同不同。

## 实现

`SupplierProductUnitPicker` 保留独立的32字符手填框，并通过现有只读 API 提供可搜索目录和刷新。目录行完整解析，不截断为假完整列表；重复名称按原有排序首个折叠，普通保存只发送名称。目录表能保留50 Unicode字符的历史名称，弹层按输入框宽度展示，长名称视觉省略但数据完整；超过商品32 UTF-16单位作者边界的选项显示但禁用，仍可选择其他单位或手填。

加载、空目录、503、目录名称删除／改名或迟到响应都不覆盖手填与历史值，也不阻止合法普通保存。选择仅改当前草稿；真正写入仍走原完整商品保存。路由代次及实际身份／权限 ABA 中止旧请求，旧表单永久失效。复制继续在原 UUID/HMAC／安全字段协议中允许单位文本编辑。

普通详情的实际已售和选中规格库存、首页备用商品网格、商品列表网格及 DIY goodList 销量显示单位文本，保持数量、SKU身份、价格和购买动作。DIY 未提供旧销量配置时沿用已有 TS fallback；明确提供配置则遵守实际 PHP 数字3开关。文本由 Vue 转义，单位不是 HTML。供应商既有只读详情已经显示单位，本批不将它重复记为新功能。

## 真实读取副作用

单位目录、分类和商品列表等请求逐次比较完整夹具表与序列，证明零写。公开商品详情 GET 原本通过 `executionCtx.waitUntil` 写 `store_product_log/store_visit`；本批实际等待这些任务，逐次核对匿名 uid0、商品80、成熟 legacy cate_id80 及节流聚合，业务表保持不变，不声称全部 GET 零写。

专用公开账号仅对真实 ORM INSERT 的统计列和两表序列追加夹具权限；DEFAULT 列也属于 PostgreSQL INSERT 目标。访问聚合仅允许既有 count/cate_id/add_time 更新，不允许改身份、删除统计或编辑商品／订单／答案。独立平台分类与审核复用既有成熟作者，与 Supplier 保存分别计数；相关 PG16 表锁需要的成熟审核 SQL 权限不描述为 SELECT-only。
