# Out 商品保障服务迁移

本批接通平台实物商品既有 Out 保存和详情入口的 `ensure_id`，并与品牌编辑组合。固定 PHP `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 Out 控制器接受保障数组，商品服务写入 CSV，创建监听器派发 type=5 关系；商品模型的 `getEnsureIdAttr` 将详情恢复为整数数组。五份源文件的 Git blob、SHA256 和行号保存在同名审计 JSON，旧 PHP 原文只留在本地。

保存仍使用完整普通实物商品正文和原有 UUID-v4 `Idempotency-Key`：

| 输入 | 行为 |
| --- | --- |
| 省略 `ensure_id` 或传入 `undefined` | 保留当前保障字段、关系及旧归一化摘要形状，不读取保障目录。 |
| 保障编号数组，最多200项 | 规范整数或十进制字符串；拒绝重复、空值、标量、非规范编号和越界编号。 |
| `ensure_id: []` | 显式清除保障字段及 type=5 关系，作为独立写入意图绑定幂等键。 |
| 停用的保障 | 仅允许保留当前商品已经一致存储、且仍属于平台的保障；不可新绑定停用项。 |

省略保留沿用既有 TS/Supplier 的兼容规则；固定 PHP 控制器将省略默认化为空数组。升级前曾被忽略的显式空数组与现在的清除意图摘要不同，不能借旧键取得成功回执。相同已提交意图先重放原回执，不因目录后来停用或隐藏而重新执行准入。

新绑定只接受 type=0、relation_id=0 的平台保障。所选实际目录行按数字 ID 顺序 SHARE NOWAIT 锁定，与现有 Admin 保障状态及删除操作锁定同一行。商品归属、SKU 身份、已扣库存、销量、订单及账单保持原有约束，没有扩大 Out 写入范围。

普通保存拥有分类关系；显式品牌拥有 type=2；显式保障拥有 type=5。协调器按字段存在性构造共用保护范围，不接受请求提供关系类型。其它关系的值和 xmin，以及省略的品牌/保障字段，在普通作者执行前捕获，并在各元数据作者及最终回执之后验证。品牌和保障同时修改不会把对方的合法写入当作干扰；晚执行的保障作者或成功回执触发器破坏品牌、目录或其它历史关系仍会整笔回滚。

详情沿用单个 REPEATABLE READ、READ ONLY 事务。`ensure_id` 返回存储的整数数组；`ensure_selection` 包含原 CSV、`consistent`、`available`、`retained_ids` 及 `truncated`。一致性接受既有 Out 上下架形成的合法关系状态0/1；可选性仍检查当前平台目录。坏历史只报告，不推断修复。

验收结果见同名机器审计和本轮完成记录。原生测试保留此前所有 Out/checkout 用例，并覆盖真实下单、品牌/保障组合、同键创建、锁竞争、成功/失败回执干扰、坏历史、可重复读及真实受限 LOGIN。HTTP 身份为合成 Out 账号，SQL 会话和数据库为真实独立 PG16；权限来自原 App 计划在测试库现存对象上的投影，不作为完整生产角色安装证明。未增加 schema、迁移、权限、路由或认证规则，未部署、未调用实际提供方，整体迁移和远端固定旧 PHP 检出问题仍未完成。
