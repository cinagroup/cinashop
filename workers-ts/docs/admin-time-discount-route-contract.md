# 限时折扣路由与交易合同

2026-09-30，本地候选，未提交或发布。本批承接旧 `/admin/marketing/discount/list` 和 `/admin/marketing/discount/add/:id?`，新页面为 `/marketing/time-discounts` 和 `/marketing/time-discounts/create/:id?`。优惠套餐 `discounts` 是另一业务。

## 管理入口

同一控制器在 `/adminapi/marketing/time-discounts` 与 `/api/admin/marketing/time-discounts` 下提供十个接口：GET 根列表、`/:id` 详情、`/products`、`/brands`、`/labels`、`/user-labels`；POST 根创建、PUT `/:id` 更新、PATCH `/:id/status` 启停、DELETE `/:id` 删除。静态选项路由在动态 ID 前挂载。

权限为独立 `time_discount.view/manage`，不从套餐或通用活动权限推导。旧数字权限仅接受菜单路径与 uniqueAuth 的真实配对：1394 `marketing-discount-list` + `/admin/marketing/discount/list`，1398 `marketing-discount-add` + `/admin/marketing/discount/add`；伪造或混合配对拒绝。

服务固定平台 `type=1, store_id=0, pid=0, promotions_type=1`。范围支持全商品、指定商品的 SKU 子集、排除商品的 SKU 子集、品牌、商品标签；排除范围是旧表单隐藏功能的受控扩展。商品必须为可见、审核通过、未删除的平台根商品，SKU 未退役且身份唯一。失效或缺失的选中身份显示问题并阻止保存；启用时重新验证，新增 SKU 不得意外继承此前“全规格”的范围。

上海时区的起止时间精确到秒，结束不得早于开始或服务器当前时间。折扣是整数 0..100 的成交百分比，90 表示九折。每人每商品限购数量在开启时为正整数。用户标签是支付后的打标动作，始终不作为买家资格。叠加只接受 2（第 N 件）、3（满减折）、5（优惠券）；开关关闭时清空对应数组。状态、排序为新增明确字段。

写入带 UUID `request_id`，更新、启停、删除另带服务端摘要 `revision`。事务内校验独立请求键和 system_log 回执；同请求同内容可重放，不同内容或旧 revision 返回 409。删除仅软删自身和同促销类型的一层派生记录，保留历史订单、促销账本、辅助关系和其他类型记录。

列表保留商品数、订单实付、活动让利、支付订单数、成交用户数、重复成交用户数、新成交用户数。统计以有效已支付的原始支付根及其活动账本去重；拆单父 `pid=-1` 也只计算一次。旧 PHP 名为支付订单但未筛 paid，本批明确收紧为实际已支付。

## 报价、建单与支付

普通订单 type0 的购物车、确认、计算、创建和代客路径使用 `OrderPromotionQuoteService` 的相同规则。首单优惠资格优先并排斥活动、优惠券，即使首单优惠金额为零。活动与会员价比较；未享受活动的剩余件保留会员优惠。其他秒杀、砍价、拼团、积分、套餐、预售订单保持各自价格入口。

PHP 的整数折扣先截断每件节省，再减原价：19.99 元九折付 18.00 元。金额以整数分处理。部分限购保留分段、精确行总额和每活动分配，禁止使用平均展示单价乘数量结算。两件九折加一件原价的示例总额为 55.99 元。优惠券只按允许叠加的段和券本身范围计算门槛与分配；未允许叠加的活动段不会分到券优惠。

限购以实际购买数量占额，按用户、活动、实际商品跨 SKU 累计，原始根 `pid=0/-1` 计一次；未支付取消释放，已支付退款不重置累计额度。没有用户身份的游客不享受需要按人累计的限购折扣，非限购活动仍可报价。

确认绑定规则、商品/SKU 价格与资格、参与范围、历史限购和精确结果的摘要，排除库存、销量等不改变报价的字段。管理写目录 exclusive advisory 锁，下单先取同目录 shared 锁，再按用户/商品串行化额度并锁促销材料与商品/SKU。锁后重新报价；规则、限额或资格变化要求重新确认。最后在数据库 wall clock 校验活动时间，全部资源和账本在同事务提交或回滚。未来 type2/3 管理写必须沿用目录锁协议才能防新增活动的 phantom。

创建写订单 `promotions_price`、每商品/活动 `store_order_promotions` 和 cart 行的 `order-promotion-quote-v1` 证据，包含精确商品金额、活动/会员节省、限购件数、分段及分配。`promotions_give` 仅保存严格 `order-promotion-labels-v1` 标签意图。付款 outbox 对原始支付根赋予仍有效的平台标签；按用户串行化，重复消费不重复关系，报价和未支付建单不打标。

供应商分配、履约拆单和原子退款按相同分段保存金额、限购数量与子单促销账本，原始支付根历史保留。退款报价逐次回放同一分段拆法，避免按整行平均导致报价和实体拆单不符。旧无版本促销订单不能凭当前规则伪造分段证据；有历史让利但缺完整证据的拆单拒绝，需要另行迁移适配。旧赠品/赠券权益仍保留原退款门禁。

客服/移动订单明细、供应商导出和配货单先校验版本化金额与数量，再读取精确行额和会员节省。部分限购的会员节省 0.15 元不会因展示单价 0.07 元乘两件而丢失一分；配货单保留单位展示价，但小计读取精确金额。损坏或未知版本失败关闭，旧未版本化行仍使用其历史算法。
