# 现代积分直兑原购凭据（2026-10-19）

既有 Worker `POST /api/store_integral/exchange/:id` 的现代零现金、零运费虚拟商品路径，现在在同一真实 SQL 事务中保留原购凭据，再完成支付。新根暂为 `paid=0`；真实商品明细的正数物理 ID 同时成为明细选择器、快照 ID 和根 `cart_id`；注册的 `0163` 协议从锁定根和明细捕获原始数量，再条件转换为 `paid=1`。事务提交后仍是一张已付 `type=4` 订单、一笔积分扣减和一个 `order.paid` outbox；不存在外部可见的中间待付状态。

例如购买两件各需10积分的商品，`pay_integral=20`，`use_integral=0`，原购凭据只记录数量2和普通积分抵扣0。这两种积分不能混算。选择器可能与无关 `store_cart.id` 数值相同，但此路径不创建、认领或修改购物车。缺协议、捕获失败、支付转换失败或后续账单失败均回滚业务行；序列缺口不属于事务回滚保证。已提交请求重放只读原订单，不补写历史凭据；旧式无现代 SKU 快照的兼容分支继续已付、无原购凭据，历史不能据此被认作零。

PC 已付积分订单的支付方式改为“积分支付”，双端订单详情增加“已付积分”。已付订单不出现待付收银区，也不向活动订单开放普通“再次购买”。

## PHP 依据与保留边界

当前 PHP 路由与积分控制器没有挂载直接 `exchange` 作者；PHP 的积分商品通过统一 `order/create`、支付和退款链处理。本批补强 Worker 已有的兼容作者，不声称恢复不存在的 PHP 直兑入口。PHP 根据选中活动 SKU 计算 `pay_integral`，与普通 `use_integral` 分开；Worker 保留该数值语义。积分加现金、运费或需要配送的类型仍进入统一结算。

原购凭据不是历史覆盖证书、支付渠道凭据或可用限额。默认旧退款完成没有受保护的数量物化凭据时，历史读取继续拒绝计算；测试没有放宽此保护。另两例通过显式的内部 `applyOrderRefundWithMaterialization`、实际商品选择和同一 finalizer 产生真实退款凭据，完成退款数量2后仍 `incomplete=true`。该内部通路不代表公共默认退款入口已升级。

累计限购仍开放：激活前历史、被删除历史与导入覆盖无法由任务 `COMPLETED` 证明；所有建单作者和赠品来源、父子订单去重、退款 lineage、统一并发额度与预留/释放还需接入。既有直兑 `once_num/num` 的0与PHP负1无限语义、原累计查询遗漏 `pid` 及隐藏已付历史差异均未在本批修正。不得据此勾选累计限购或整体迁移。
