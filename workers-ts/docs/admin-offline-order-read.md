## 收银码接口与海报增量（2026-09-20，本地未部署）

对照 PHP `app/controller/admin/v1/order/OtherOrder.php::offline_scan`，恢复

新实现返回内存 data URL，不创建公开上传文件，不下载任意背景图，不修改业务数据库。

参数只允许单个 `type=0`（原始码）或 `type=1`（海报，默认）；查询串最多32字符，

`/#/pages/annex/offline_pay/index`，复用已批准的严格 HTTPS origin 合同；

最多四次微信 HTTP（含一次令牌刷新），不把单次8秒当成整个请求8秒；SQL及缓存另有耗时。

沿用平台 Admin JWT 与 order.view；在独立只读事务里重验账户、密码版本、角色和有效期，
外发之前与返回之前各一次，不跨外部 I/O 持有 SQL 事务。等待期间撤权后不返回迟到码。
成功、参数、鉴权和能力错误均 private/no-store。失败仅写低基数错误类型日志。

## 新版合同（需要配套新页面）

仅接入实际 `/adminapi` 路由；不是旧 PHP 页面无改动兼容层，也没有增加 `/api/admin` 别名。

| GET 接口 | 响应 data |
| --- | --- |
| `/adminapi/order/scan_list` | `{version,list,limit,next_cursor}` |
| `/adminapi/order/scan_detail/:id` | `{version,record}` |

`version` 固定 `admin-offline-read-v1`。详情使用数据库数字 ID，不是消费订单号；
详情禁止查询参数覆盖。列表只接受以下参数，未知、重复或总 URL 查询串超过 1200 字符拒绝：

- `limit`：默认 20，规范整数 1～20。
- `before`：上一页 `next_cursor`，规范正 int32 ID，查询 `id < before`。
- `order_id`：完整精确订单号，最多 32 字符，无空白／控制字符；允许发现旧格式记录。
- `uid`：规范正 int32 用户 ID。
- `name`：最多 64 字符的非空用户昵称或电话子串，去掉首尾空格；`%`、`_`、`\` 按字面匹配。
- `from`、`to`：必须同时给出正 int32 Unix 秒，`from < to`，按创建时间 `[from,to)` 查询。
- `recorded_paid`：仅 `0` 或 `1`，只筛选**原订单标记**，不是“已核验付款”筛选。

没有 `page`、旧字符串 `add_time`、偏移分页、总金额或总数。默认显示全部 type=3，
不是仅显示原标记已付；隐藏记录也不剔除。按 ID 倒序每页最多 20 行，多取一行决定
`next_cursor`，末页为空串。后续新插入不挤入旧游标后的页面；跨页不宣称同一数据库快照，
切换筛选条件必须重置游标，刷新首页才能看到新记录。

每行显式字段为 `id/order_id/uid/nickname/phone/account_available`、
`money/pay_price/true_price/add_time/hidden/recorded_paid/channel` 及
`paid/pay_type/paid_at/state/reason`。`money`、`pay_price` 是**记录金额**，无效则 null；
`true_price` 是有效且非负的原价减应付差额，不是已核实到账金额。
`account_available` 只是当前客户账号可用性，不影响后台查看历史凭据。

| state | paid | 解释 |
| --- | --- | --- |
| `UNPAID` | false | 已准入且未选择付款路径，没有本地收款凭据 |
| `PENDING` | false | 原付款入口或恢复流程待核对；不能据此重新付款／确认关闭 |
| `UNAVAILABLE` | false | 隐藏或历史零元记录，不可付款；不代表上游已关闭 |
| `PAID` | true | 原选择、订单、不可变收款来源与资金账本一致 |
| `REVIEW_REQUIRED` | true 或 false | 存在需人工核对的恢复状态；true 仍只来自已验证的本地收款事实 |
| `UNVERIFIED` | null | 无准入、缺客户或凭据不一致；不宣称已付，也不宣称一定未付 |

`UNVERIFIED` 的 reason 为 `MISSING_ADMISSION/ACCOUNT_MISSING/EVIDENCE_MISMATCH`，
且 `pay_type/paid_at` 置 null；其它状态 reason 为 null。未选路径的 `pay_type` 为空串。
正常准入外键会阻止其客户被物理删除，`ACCOUNT_MISSING` 只是损坏结构下的防御分支。
来源表缺失、列缺失或权限不足不能伪装为 `UNVERIFIED`：遇到这些 SQL 错误返回整页 503。
无记录的空列表不是数据库安装／权限健康检查，不能替代独立目录与权限审计。

## 权限、事务及凭据边界

路由保留实际 Admin JWT／密码版本／角色鉴权，仅平台 `adminType=1`，要求 `order.view`
（既有超级管理员 level=0 语义保留）。服务在自己的 REPEATABLE READ、READ ONLY
事务中重新读取管理员，严格要求 status=1/isDel=0，恒定时间比较密码摘要并重算角色；
不相信 URL 中的身份或先前的权限快照。开始和返回前均检查令牌期限。
权限与记录使用同一次事务快照，不承诺在快照开始后的角色修改立即撤销正在返回的响应。

提取并复用客户详情的 `readOfflineOrderEvidenceTx`，不复制较弱的“已付”判断。
客户包装层仍要求有效自有账号；后台可读禁用／软删除客户的历史，不冒充该客户。
余额核验真实扣款、赠分、节省及不可变收据；外部核验回调绑定或查询签名证据摘要、
身份、金额、时间和财务关联。仅数据完整性异常转为 `UNVERIFIED`，数据库能力故障继续失败。

后台 DTO 不返回付款 ticket、付款人标识、交易号、request/selection/case 键、
密码、余额、原始回调或商户配置。读取不调用 provider、KV、队列或写数据库，不拿行级锁。
成功及鉴权／参数／能力故障均为 private/no-store；调用方不能把空结果或失败当成未付款。

SQL statement_timeout 使用已有更严格值或最多 5 秒。列表每行之间及末尾检查 8 秒协作式
核验预算；这**不是硬性整事务 8 秒超时**，单行多条 SQL 仍各受 statement_timeout 约束。
分页上限与超时限制工作量，不构成大规模生产性能验收。SQL 超时／锁等待失败返回整页
503，不返回混合已核验／未核验的半页成功。
