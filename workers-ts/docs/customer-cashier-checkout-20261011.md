# 普通 customer 次卡收银写链（2026-10-11）

本批继续 PHP 到 TypeScript 的迁移，接通普通 UserJWT 的真实次卡选品、会员／游客、系统表单、报价、创建、现金／零金额付款和本人原编号恢复。工作台新增 `customer-work/cashier` 页面，与此前本人收银记录和凭据页相连。它承接真实单商品／单规格次卡收银；完整旧五页代客下单和整个 PHP 迁移仍未完成。

## 实际合同

新增 `GET /api/mobile/work/cashier/second-card/catalog` 和 `catalog/:id`。只读当前已审核、上架、非预售、原商品的有效次卡规格，包含真实库存、次数、有效期和当前系统表单；可选数量受主商品与规格库存共同约束。目录标价用于选品，成熟报价和创建事务决定实际金额。目录响应绑定当前普通用户经营资格；失效、重复或客服聊天资格不授予收银。

页面复用既有六条独立 UserJWT 合同：真实 drafts、quote、orders、orders/:id/cash，以及 creations/:key、payments/:key。每个草稿／创建使用同一个 UUID 和完整冻结内容；付款使用另一原 UUID，绑定物理订单、业务单号、金额、购买人及原来源。首次写入前保存本机原意图并回读核对，存储失败不发送请求。报价不是订单创建，确认下单和现金已收款分别要求明确确认；零元同样写真实付款事实。

未知结果不自动重发或换编号。先查询原回执，未找到时恢复完整同 UUID 的草稿／报价，页面展示原商品、购买人、联系资料与答案，重新核对后才创建；付款恢复先查原回执并重新读同一真实未付订单，明确确认后只发送原付款 UUID。无回执不是未执行的最终证明，未知请求没有伪造的关闭／放弃入口。尚未付款的原创建记录保留用于付款恢复。

创建回执查询核对实际原订单、不可变来源、购物快照与创建审计；付款回执继续核对实际现金状态、金额、付款审计及原 `order.paid` outbox。本人有效登录会话在撤回当前经营资格后仍可查询原回执；不能据此读全局经营资料或发起新写入。页面观察到 records 的 403 即撤回当前权限并清空订单、表单和报价，保留本次已核对的本人原回执。账号、token／sessionVersion、隐藏、卸载与迟到响应均有独立栅栏。

报价中的 `card` 直接来自成熟报价本次使用的同一份 `orderItems`，包含商品、规格、数量、单件／总次数和有效期。页面与创建确认弹窗显示这些实际权益；若选品后权益改变，明确提示与目录不同。前端拒绝外层投影与核心报价不一致、商品／规格／数量／总次数不匹配的响应。

系统表单的实际模板和规格有效期语义加入次卡确认指纹，报价后修改有效期必须重新报价。创建事务持有表单行锁，并在最终库存更新重新约束商品表单选择、审核、归属及规格次数／有效期；引用 ID 不替代当前模板。固定有效期在来源和审计写入后再次按数据库时钟检查，覆盖最后写入等待跨过到期时间的情况；未来开始生效的有效卡仍可购买。图片上传没有普通 customer 收银专属授权，必填图片商品明确不可创建，可选图片保持空值；页面显示不可用说明，不能借用 Admin／supplier 上传权限。非零表单 ID 但模板容量超限／不可用的商品也明确阻止创建。

本页当前不选择优惠券或积分抵扣，会员价与活动优惠仍由成熟服务器报价计算。多商品购物车、普通／其他商品类型、地址配送、多种支付渠道、旧五页完整角色与手机别名覆盖仍开放。必填图片、当前经营资格／表单／原意图改变后的耐久放弃与重新发起协议也仍需补齐；不能通过修改本机原 UUID 内容解除未知操作。普通现金／游客退款、真实 provider／设备、生产授权、Linux／Hyperdrive、容量及发布验收仍开放。
