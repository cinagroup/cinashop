# Supplier 申请资料与原回执二维码

`/finance/apply` 可以显示当前申请资料对应的私有二维码，`/finance/application-result` 可以显示该次原申请提交时的私有二维码。媒体是独立、可过期的只读投影；原申请、原回执七字段及结果十三字段不增加临时签名，不修改其内容或持久摘要。

## 当前申请资料

只有选中支付宝／微信且该项为可识别私有引用时，页面读取已有 `GET /supplierapi/finance/info?selection=accounts`。该接口沿用现有收款设置合同与当前 `finance.view` 授权，不授予图库或上传能力。前端验证完整闭合设置投影、当前身份，并将全部六项收款资料与页面 seed 逐一比较。设置版本与申请 seed 版本属于不同合同，不能互相替代；只有六值一致，才将对应渠道的预览绑定到该 seed。银行卡未填写的 `0` 按现有设置合同规范为空。

任一收款值已变，清除当前申请资料并提示重新核对，不能借较新图片掩盖旧资料。图片读取失败不重发申请，不自动换 UUID。安全公开引用保持现有字面展示；不安全引用仍占位。此处不改变原申请 HMAC、可用余额、上下限、锁顺序、提交五字段或持久原操作协议。原 seed 仍由已有实际申请服务计算和核对。

## 原申请回执

新增唯一读取为 `GET /supplierapi/finance/supplier_extract/application_operations/:operationId/media?request_hash=...`，要求原小写 UUIDv4 与唯一的64位小写请求摘要。没有附件 ID、引用、租户、当前设置或历史行版本选择参数。精确 GET 权限准入只表示需要进入自己的恢复服务，服务仍检查当前 JWT、口令版本、有效期、实际账号与供应商身份。

在 REPEATABLE READ／READ ONLY 事务内复用原目录检查、原操作验证和实际申请不可变列核对。原账号与供应商必须匹配、操作必须已提交、摘要必须相同；其他账号／租户、未知与未申请终态均404且不签发，原操作摘要不符409，目录或实际证据损坏503。当前有效的原账号即使财务查看和管理能力均已撤销，也能读取自己的原回执二维码；这与原回执恢复合同一致。已经失效的账号、口令或供应商不通过。此读取不查询今天的余额、限额或收款设置，也不要求当前可变审核状态／xmin等于原快照。

响应闭合八字段：`version,operation_id,actor_id,supplier_id,request_hash,extract_id,preview,bounded`；preview闭合四字段：`reference,status,src,expires_at`。只投影原 `result.qrcode_url`，不附带后来登记的转账凭证。银行卡返回空原引用的不可用项。安全公开图片保留字面值；私有图片需实际本供应商 type4／module1／file1／image8、正确图片 MIME、规范 attDir 与 Supplier 对象命名空间。已有历史引用解析器只识别精确 api／kefuapi 私有挂载及格式正确的旧票据；旧票据本身不构成授权。附件已删除或归属／类型改变时返回不可用，不替换原回执引用。

新私有链接有效300秒，使用已有实际附件读取端点。到期前仍是短期 bearer capability，不声称发出后撤权会立即使该链接失效。新接口仅需 auth四表、supplier_extract、system_attachment 与原操作表七表SELECT的独立受限LOGIN，无业务DML、序列或目录维护权限。原0197目录的既有PG16运行前提保持；HTTP不执行DDL／GRANT。

## 页面与恢复边界

提交前、原申请结果各自保存媒体上下文。渠道切换、重新核对、开始提交、原结果变化、路由变化、权限变化、卸载与真实会话 A→B→A 均清除投影并取消请求；Axios 队列中的GET也受同一会话约束。浏览器存储失效会清除敏感资料。图片失败或过期仅隐藏图片，原提交结果保持；到期计时器不自动访问接口，用户可明确重新核对二维码。

媒体失败不保留或重建已正常清除的原申请本机日志，不冒充财务提交失败，也不调用申请或封存端点。未知原结果仍保留其原UUID，未申请终态不请求媒体，原日志清除继续由原合同完成。回执图片恢复成功也不授权新提现、图库、设置读取或后续凭证读取。

## 验收范围

实际SFC／Pinia／Axios测试同时覆盖新预览与原页面协议；原生测试通过真实App／JWT、实际提交的一笔原申请及独立纯SELECT PG16角色验证。生产构建浏览器验收先读取与六值一致的当前私有二维码，再只由本机控制夹具修改当前两项设置并撤去财务能力；原账号仍读取不可变原回执和原QR31。跨窗口会话ABA取消一条已完成数据库读取、尚未送达的媒体回复，刷新并再次读取原结果验证可恢复。控制夹具仅使用本机合成资料；浏览器业务HTTP全部GET，不创建新申请、上传图片或执行银行转账。

精确命令、原始断言、源指纹、浏览器尺寸、夹具清理和提交扫描由本批审计记录。旧财务写方法、原申请Service／Input／Operation、0194—0197、现有运行profiles与用户选定统计脚本保持。真实支付／税务provider和生产发布门禁仍需独立验证，整体迁移goal active。
