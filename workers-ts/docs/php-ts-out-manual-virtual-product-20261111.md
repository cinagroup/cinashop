# Out 手工虚拟商品

固定来源为 PHP `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 `Product::productSave`、`StoreProductServices::saveData/syncStock`；本批仅接通平台商品 `product_type=3` 的手工虚拟商品。创建和编辑沿用 Out 商品现有的请求键、SKU 身份、商品关联和回执保护，禁止实物与虚拟类型互相切换；非物流商品强制 `delivery_type=''`、`freight=2`、`temp_id=0`、`postage=0`。不能将卡密或固定内容当作手工虚拟商品写入，也不能开启目前只支持实物的预售。编辑不覆盖已有 SKU 库存，不增删 SKU；存在退役 SKU 或商品与 SKU 履约类型冲突时明确拒绝。

商品分类、品牌、保障、商品标签、用户标签、参数、优惠券和表单沿用既有目录授权和事务证明，相关证明固定商品的真实履约类型。上架与下架继续通过既有 Out 接口，库存同步按实际 SKU 条码匹配平台实物及手工虚拟商品；跨两种商品的重复条码明确拒绝，不猜测库存归属。手工虚拟商品的库存、SKU、总库存、流水和请求回执在事务末尾强制结算延迟约束并回读，发现改写整笔回滚。

创建后沿用现有普通购物车和结算规则：手工虚拟商品无物流费用，人工虚拟交付继续由既有受权操作执行。本批不创建或读取卡密、不调用实际支付或其他外部提供方、不部署或上传旧 PHP；卡密、优惠券商品和次卡的 Out 商品作者仍待迁移。

固定源码验收：192项单元测试、249项真实 PostgreSQL 测试全部通过，无跳过。原生测试包括16项库存同步、50项商品作者与购买、43项客服履约、71项结算并发和69项商品关联；独立受限 App LOGIN 使用现有权限计划创建并同步库存，隔离数据库均零残留并停止。类型检查按原编译选项将4,338个根文件分为两组，校验并集与原配置完全一致，两组与独立运行时类型检查均通过。单次完整项目检查在上一批两次达到既定8 GiB堆上限，故保留同样上限并采用完整覆盖的分组。
