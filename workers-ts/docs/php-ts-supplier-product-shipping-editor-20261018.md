# 商品页内运费模板编辑（2026-10-18）

本批接通实物商品编辑页的运费模板查看、编辑和新增弹窗。商品表单始终挂载，模板作者与商品保存分别提交；整个 PHP→TS 迁移仍在推进。

## PHP 实际合同

PHP `view/supplier/src/pages/product/productEdit/index.vue:823–839` 的 freight3 区域提供当前模板查看或新增入口，1070–1074 行挂载 `freightTemplate`。2470–2482、2656–2660 行表明，模板保存后仅重读模板目录。实际模板组件 `components/freightTemplate/index.vue:420–435,522–542` 读取并保存完整配送、包邮和禁配规则，关闭弹窗后调用父页目录刷新。这些均为启用代码。

迁移复用既有 Supplier 归属校验、完整规则作者、`shipping-v1` 乐观版本、城市权限、行锁和 UUID 创建回执协议。完整详情需要 shipping.view，更新和创建另外需要 shipping.manage；product.manage 仅允许商品草稿的明确模板选择。

## 实现与恢复

`supplierShippingTemplateEditor.ts` 与 `SupplierShippingTemplateEditor.vue` 提供共享作者，独立运费模板列表页和商品页复用同一弹窗。商品页包装组件只刷新当前模板名称及目录；更新、创建确认、查看和取消均不更改商品 temp_id。新模板通过原分页选择器明确选择。

既有模板更新成功后，必须取得有效完整版本回读才通知目录刷新。POST 成功但回读失败时明确显示“模板已更新”，保留输入并暂停重复保存，允许用户确认后重读。版本冲突也保留输入并要求明确重读。

新建沿用 Web Locks、原 UUID、原始内容散列、持久意图、回执查询与确认协议。关闭和重新打开仍恢复原意图；已提交但丢失响应的创建通过原键查询恢复。创建确认只刷新目录，不能将历史回执当作当前模板访问权限。

路由变更、权限或身份变更会取消旧请求，迟到响应不能回填其他入口。成熟商品页在身份变化时清空旧身份资料，这一行为保持。模板保存会影响所有已绑定它的商品，弹窗中明确说明这一点。
