## 合同与实现

固定 PHP 参考 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的十二份相关文件逐字节核验。PHP `order.create` listener 将 create 任务交给 `OrderStatusJob`，再由 `StoreOrderStatusServices::saveStatus` 保存 `cache_key_create_order / 订单生成`。listener 传入的金额键是 snake_case，而 service 的可选 edit 判断是 camelCase；本批遵从实际创建事件，不推导或伪造额外改价记录。

当前 TypeScript 公共核心在新订单 INSERT 成功后，使用精确新主键写入相同类型和消息，时间采用同一事务内的建单时间 `addTime`。创建记录与库存、购物车、积分、来源凭据和后续资格检查一同提交或回滚。PHP 原异步任务的执行时间可能稍晚；本批声明这一时间／提交边界差异，不声称复刻队列调度顺序。

失败事务允许 PostgreSQL 序列留下正常间隙；无写入报价和既有订单重放另外核对公共序列保持不变。

只读报价及两个既有订单重放出口均在新纪录写入之前返回。同键重试和真实并发请求依靠既有串行复查，只产生一个新单及一条创建记录。代客入口同时保留独立的 `admin_assisted_create` 主体记录。活动取消仍保留单独 cancel 事件，完整建单活动场景现在分别核对创建与取消，不以总数一条代替事件身份。

创建事件仍属于原支付来源。实际退款拆单不会把它复制为子单的新建事件，后台旧数组与现代分页按精确 oid 读取；买家配送时间线也可读取创建日期。没有更改 DDL、默认引导、既有角色权限计划或财务来源协议，缺少 INSERT 权限时不自动修复授权。
