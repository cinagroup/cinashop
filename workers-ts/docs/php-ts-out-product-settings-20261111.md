# Out 商品代理标记、复制口令和视频开关

固定 PHP 来源为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`。`out/Product::productSave` 接收 `mer_use`、`command_word`、`video_open` 和 `video_link`，交由 `StoreProductServices::saveData` 保存；数据库中有对应的前三个设置字段。原 TypeScript Out 保存忽略前两个字段，并以视频地址是否非空推断开关，导致编辑器明确关闭的视频重新开启。本批补齐四种已实现商品类型（实物、卡密、手工虚拟、次卡）的这些设置。

代理标记与视频开关接受 `0/1`、字符串 `0/1` 及布尔回显；复制口令保留 Unicode 文本、去除首尾空白，最多255个字符，拒绝控制字符和损坏的代理项。省略代理标记或复制口令时保留旧值，显式 `0` 或空字符串可清除；新增字段省略时不改变旧规范化结构及幂等哈希。视频开关省略时继续既有的按地址推断行为，明确关闭需传 `video_open=0`，地址可以保留用于再次编辑；前台实际 `readDetailVideo` 策略在关闭时返回空值。

开启视频必须提供地址。保存复用现有 `ProductVideoPolicy`，私有播放票据转为稳定素材引用；平台商品只允许可用的平台 MP4 素材，关闭视频也不能绑定其他归属或错误类型的私有素材。私有素材始终重新校验，保存前使用附件表的非阻塞屏障与删除、回收协调。新建或更换公共视频必须满足现有视频策略；未提交视频开关时，允许原样保留历史无效公共地址以修复其他字段，实际公共读取仍隐藏无效视频。设置、素材和回执在完整事务内校验，并在执行延迟约束后复核；失败整体回滚。

原生 PostgreSQL 验收通过真实 Out JWT 和接口权限执行创建、详情、编辑、同请求重放、冲突请求、保留及清除；同时覆盖所有已实现履约类型、私有素材归属、错误媒体、历史公共值、回执与延迟篡改、独立会话删除竞争、原有受限应用登录。公共视频显隐调用前台现有策略及真实数据库；这些测试不声称实际 R2 播放或真实支付流程。测试禁止实际提供方 HTTP，未部署、未上传旧 PHP、未调用真实支付或短信。

对上一批“类型2优惠券商品待迁移”的分类作补充：固定 PHP 编辑器可选类型实际为 `[0,1,3,4]`，SKU 表和保存映射没有用于发券的 `coupon_id`，类型2仍有预留分支。这些证据不足以证明已存在完整的按SKU发券商品流程。本批没有开放该入口，也不据此宣告整个迁移完成。普通商品支付后赠券使用独立的 `coupon_ids` 关联，已有实现与上述预留类型不同。类型2的历史兼容边界仍需单独核对。
