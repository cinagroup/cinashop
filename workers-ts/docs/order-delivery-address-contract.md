## 请求与权威来源

- 实物配送建单必须传当前用户未删除的地址 ID。支持 `addressId` / `address_id`；同时出现必须一致。只接受 PostgreSQL integer 范围内非负整数或纯数字字符串，0 表示未选择。
- 普通客户端传入的姓名、电话、省份、城市 ID 和拼接地址不能覆盖地址簿。报价和订单落库共用重新读取并验证的地址字段。
- 实物预览允许尚未选择地址，但显式错误地址不能自动替换为默认地址或免运费报价。预览不预留库存、积分或订单；无地址优惠券预选保留。
- 虚拟商品无需物流地址；自提使用独立联系人，姓名最多 32、电话最多 18，自提不以配送地址代替联系人。
- 已建订单的幂等重试先返回原订单，不因后来删除地址而创建第二单或要求重新选择。

## 代客手填

仅服务端授权的代客路径接受 `manualAddress`（别名 `manual_address`），不能同时选择正数地址 ID。游客不能借用用户地址簿。

```json
{
  "manualAddress": {
    "realName": "收货人",
    "phone": "13800000000",
    "province": "省名",
    "city": "市名",
    "district": "区名",
    "street": "",
    "cityId": 123,
    "detail": "街道门牌"
  }
}
```

上例为字段示意，123 不是有效区域承诺。`cityId` 必须对应 `city_area` 的完整实际层级，省市区/可选街道名称必须匹配。旧 `address` 自由文本只有配齐结构化地区信息时才可使用，不猜测地区、不创建地址簿记录。

显式 `manualAddress: null` / `manual_address: null` 属于错误参数，不能视为未提供后回落地址簿。

地址簿/手填电话上限为 16；姓名 32；省、市、区各 64；街道 100；详细地址 256。拼接后还必须满足订单 `user_address varchar(100)` 的 100 字符上限，超出返回校验错误，不能截断后落库。

## 事务与证据边界
