原生并发测试观察 `pg_blocking_pids`，验证等待后商品由预售改普通、购物车被其它事务认领，以及基础 SKU 未变化但锁等待跨过结束秒。最后一个场景刻意保持应用时钟停在有效时段，仍由 PostgreSQL 实时时钟拒绝，且无购物车残留。

- 本地最终10文件：105通过、3项原生连接测试按条件跳过；其中预售通用29项，既有回归76项。
- PostgreSQL16.15 非超级用户复验：预售3文件32项全部通过，包含前述29项，不重复累计。
- 砍价 HTTP/购物车/报价/建单/取消17项在另一个新建维护模式集群安装既有 NOLOGIN 计价协议后全部通过。该套不能在缺少该协议的 PGlite 环境替代验收；未放宽业务权限判断。
- 合计125个不同用例经过相应环境验证，而非把重跑次数累加成更大数量。Worker unit/runtime 两套类型检查通过。
- 首轮扩大回归的4项失败：1项仅 Windows CRLF/LF 输入不同，现只在测试读取处统一换行；3项是 PGlite 缺少真实计价能力的正确拒绝，已在原生协议夹具复验。运行器只加入精确砍价测试文件白名单，没有开放任意维护命令。
- 三个独立临时集群 `finance-postgres-OBoCUN`（首轮）、`finance-postgres-cwpJTZ`（最终预售）、`finance-postgres-UKrHtv`（砍价）：测试库/角色余留0，独立 pg_ctl 退出3，PID/口令文件/监听/所属 PostgreSQL 进程均不存在。沙箱第一次独立检查因目录 ACL 与进程权限不可读，不采用其假零结果；获得只读诊断权限后重新验证。保留已停止的私有诊断目录。

PostgreSQL 技能推动统一锁序、短事务、数据库实时时钟及原生锁等待验证。Workers 技能用于保持现有连接/绑定与事务中无外部 I/O。没有前端改动或本轮浏览器验证，不借用旧截图宣称预售 UI 已验收。
