# 普通 customer 核销路由合同（2026-10-05，验证进行中）

入口均在`/api/mobile/work`下，强制独立UserJWT。当前唯一有效customer服务记录和当前凭据共同授权；聊天、Admin、门店、配送或旧数字auth不能替代该资格。

| 方法与路径 | 合同 |
| --- | --- |
| POST `/writeoff/lookup` | 只读，显式auto／order-code／member-barcode／legacy-order-id命名空间；歧义拒绝；旧实体ID先查真实订单号 |
| GET `/writeoff/orders/:id` | 真实实体主键、原订单号、scope_key共同绑定；回读不可变商品和实际剩余次数 |
| GET `/writeoff/orders/:id/records` | 同一实体归属、完整分页；操作人和购买人分别显示，历史未证明身份保留未知 |
| POST `/writeoff/execute` | 原UUID、完整请求、订单／核销版本、真实cart行和剩余次数；同事务审计、金额与结算回读 |
| GET `/writeoff/operations/:key` | 只查本人原UUID；资格撤销后仅本人原回执恢复，不能派发新业务 |
| POST `/writeoff/operations/:key/abandon` | 只在确认原操作不存在时按原完整意图落放弃回执，不重签成功 |

四个真实页面为scanning、writeoff、writeoffRecords、writeoffResult。旧核销入口无auth时保留既有操作员默认合同；显式auth1进入customer，auth2进入独立配送，auth0／3经当前资格选择且目的页再次授权。旧页面参数只能经真实只读查找解析，不拼造订单号。

成功证明绑定订单、支付根、原购物行、快照／成交价格hash、原后验证码及实际核销行。部分完成只扣实际次数并轮换验证码；全部剩余归零后同事务调用成熟结算。现代促销使用原有顺序及尾差；真实次卡按原购买单位成交价重复计算每次权益，不能拿实付额除总次数，也不能读当前SKU补旧成交价。

同一UUID重放只回原结果；未知结果先查询，不生成新UUID。扫码、页面生命周期、账号／资格变化、ABA回复及旧任务恢复均需通过前端实际运行验证。只读回读最多500个购物行，并保留原快照262144字节容量边界；写入最多200个选择。超过读取、写入或来源容量、缺少完整退款代际证明时拒绝对应读取或关闭操作，不截断后写入。

实际编译浏览器发现同页hash切换复用旧单。共享经营生命周期现监听当前页hash变化：先清空旧数据与可执行草稿、使旧请求失效，再校验原参数并重新读取；跨页监听不触碰新页面请求，卸载移除监听。耐久保存的原UUID及完整意图不因导航删除。当前21源的完整runtime224项、原五类型／构建、125页主题、15项编译语义以及实际浏览器90组与QA6均已通过；16个实际故障、8个迟到场景、3项当前403及11类严格网络异常门槛同时通过，旧失败及缺少请求身份的提前取消记录保留。
