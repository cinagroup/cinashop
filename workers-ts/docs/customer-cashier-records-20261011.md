# 普通 customer 本人次卡收银记录（2026-10-11）

本批接通独立 UserJWT 的本人次卡收银列表和详情，以及手机工作台入口、`cashierRecords`／`cashierRecord` 两页。读取既有真实次卡创建和现金付款来源，不改变创建、付款、核销及退款业务。

## 合同与范围

旧 PHP `app/controller/api/admin/order/CreateOrder.php::lst` 以当前用户 `staff_id` 读取代客订单；旧 `pages/behalf/record/index.vue` 进入通用手机订单详情。本批只承接真实 customer 次卡收银记录子范围，不替代该旧入口的完整五页代客合同，也不改变已有 AdminJWT 代客页面或兼容路由。

新增 `GET /api/mobile/work/cashier/second-card/records` 和 `GET /api/mobile/work/cashier/second-card/records/:id`。每次读取须通过当前有效普通 customer 资格；历史来源的 `actor_uid`／`creator_uid` 必须属于当前本人。当前资格的 service／scope 与历史创建资格分别核对，角色变化不会篡改历史凭据。已有按原 UUID 恢复的单笔创建／付款收据仍保留独立授权语义。

列表只接受 `scope_key`、`limit`、`cursor` 和完整 `order_no` 精确筛选，默认20、最多50条。游标使用来源台账的 `created_at`／`request_key` 排序，保留 PostgreSQL 微秒时间；绑定账号、当前资格和筛选。新记录、相同时间及不同订单 `add_time` 不改变排序依据。详情同时绑定物理订单 ID 和业务单号。重复参数、未知字段、非规范编号、跨账号或过期资格游标均拒绝。

原创建来源须与真实根订单、买方、创建人、渠道、商品类型、创建审计及唯一购物行相符。原购买数量、次数和商品 JSON 摘要逐项核对，读取保存的 TS `product`／`sku` 快照。仅投影所需订单字段；原始商品 JSON 在 SQL 侧限制262144字节，超限拒绝。退款或拆单后的原根订单仍显示原购买事实，不把原购买次数当作当前可核销余额。用户删除历史保留，系统删除订单不发布。

现金已付状态须同时核对不可变付款收据、付款审计、原 `order.paid` outbox 事件及 payload 订单身份／摘要。零元确认使用独立 `zero` 凭据；仅改变 paid 标志不能生成有效现金记录。其它渠道的已付观察不声称存在现金凭据。读取不触发支付、事件消费或核销。

数据查询在限时 REPEATABLE READ／READ ONLY 事务内完成，事务后再次核对当前用户会话及经营资格。两个手机页面在隐藏、卸载、同页参数变更、账号／token／会话版本变化或当前403时清除旧资料，使迟到响应失效。所有页面请求均为 GET。
