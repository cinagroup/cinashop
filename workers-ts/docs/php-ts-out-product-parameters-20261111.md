# Out 商品参数快照与平台模板

Out 平台实物商品保存接通 `specs_id` 和 `specs`，与品牌、保障、商品标签、用户标签及原幂等回执在同一事务提交。固定 PHP `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5` 的 Out 控制器接受这两个字段；保存服务按五字段参数快照编码，CreateSuccess 派发 type=6 关系。来源元数据列在同名机器审计中；旧 PHP 原文不进入本批或远端。

两字段均省略或均为内部 `undefined` 时保留原值，不读取参数模板目录，也不改变归一化请求摘要。只提供一个字段时拒绝。显式 `specs_id: 0, specs: []` 清空参数及 type=6 关系，以不同摘要绑定幂等键，不能复用升级前忽略空字段的回执执行清除。模板 ID 是规范非负 int32；参数为最多100行的数组，按既有 Supplier/PHP 五键合同保留 `id/temp_id/name/value/sort`，忽略目录归属等回显，不把行编号当作目录写入授权。

参数值是商品自己的历史快照，允许自写文字和不带模板的快照，不要求等于模板的当前子项。名称和值保留原始空格，须为非空文本、最多255个 Unicode 字符且不含控制字符或坏代理项；PHP 同样拒绝的字符串 `0` 仍拒绝。行编号非负 int32，排序为有符号 int32。所选模板必须实际属于 `type=0, relation_id=0, owner_id=0, group=3`。沿用既有参数管理的规则，不额外按 `is_show` 禁用模板。

保存锁定实际模板行 SHARE NOWAIT。主表快照、唯一 type=6 关系、完整模板像、每类已提交元数据及未拥有的历史关系在所有后续作者和最终回执后重新核对；递延约束先结算。协调器即使省略元数据也核对保留字段和关系版本，防止同事务触发器改写。并发锁冲突失败并提示刷新；目录、关系、商品、SKU及回执的部分写入整笔回滚。已提交回执先于当前模板准入读取；目录后来变化不会阻止核对原请求。

详情沿原 REPEATABLE READ、READ ONLY 事务增加 `specs_id/specs_selection`。原平铺 `specs` 原文和旧 `productInfo.specs` 投影保留；伴随状态区分坏快照、主表/关系不一致和跨归属模板。Out 上下架形成的关系状态0/1均可一致。只读请求不修复历史、不查询或返回模板子项的私有文字、不写回参数目录。

验证扩展既有完整 Out 元数据 PG16 文件，保留原测试正文和原600秒子预算，不新增运行器入口、历史来源投影、SQL迁移或权限。新增纯合同检查和实际 Hono/Out 服务验收使用合成 Out 身份及独立测试库；提供方 HTTP 被禁止。完整通过数、失败候选、真实受限 LOGIN 与并发证据以同名审计及完成记录为准。尚未部署，旧 PHP 未上传，真实 Out 客户与完整迁移仍待验收。
