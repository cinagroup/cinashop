## 已证实的入口与缺口

前端`view/admin-ts/src/api/config.ts`明确禁用通用编辑器，但`POST /api/admin/config/save`仍注册了真实管理员认证中间件；超级管理员与持有`config.manage`的角色可达，`config.view`和匿名用户不得写入。本轮没有重新启用通用编辑器、增加路由或放宽权限。专用业务域配置API仍优先，凭据管理不属于本轮验收。

旧处理器逐键自动提交，第二项超长或数据库触发器失败会留下首项包邮变更；读取既有记录未限定全局作用域或优先级，可能更新门店记录或低优先级重复项。KV清理发生在循环内，会观察到未完整提交的政策；某次KV失败又会阻止后续数据库写入。错误JSON曾被转换为空对象并返回成功，请求量也没有边界。

## 当前实现

`AdminConfigBatchService`接收扁平字符串值，先完整校验，再进入数据库事务。请求按实际流字节限制128 KiB；最多100键；键不为空且无前后空格，最多255个Unicode字符；值最多5000个Unicode字符，拒绝NUL和未配对代理字符。`cfg_`前缀后的键还受512字节限制，与[Cloudflare KV键上限](https://developers.cloudflare.com/kv/platform/limits/)一致。空对象保留无操作成功，空请求、null、数组及错误JSON拒绝。没有把字符串内容重新解释为金额或开关，既有业务计价规范化不变。

READ COMMITTED事务首先设置2秒锁等待、5秒语句与事务空闲上限，然后取得system_config的SHARE ROW EXCLUSIVE表锁。该锁在任何业务数据写入前取得，允许正在持有SHARE锁的下单先结束；没有持有订单、库存或会员权益锁后反向等待配置。表锁会影响其它配置写方，成本及正式权限仍须独立验收。

保存使用两个参数化批量DML：按is_store=0、sort DESC/id DESC更新每键唯一有效赢家，再插入真正缺失的全局键。不修改门店行、重复输家、显示状态、排序或其它元数据，不删除历史重复记录。最后按相同优先级回读，最多返回100行；任何数据库错误或回读不一致都回滚整批。两条客户端写语句不等于数据库扫描成本恒定。

KV删除在SQL提交后执行并等待全部结果。失败时明确返回“配置已保存，但缓存清理失败，请重试保存”，不伪称SQL回滚，不返回配置值。重试保存相同值可重复执行。本轮没有实现持久化缓存失效重试队列，也不承诺失效立即在全部地区生效；11个结算计价键已有独立SQL权威，其它KV配置组仍须审计。
