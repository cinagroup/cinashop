# 买家发票抬头、订单补开与开票记录

本批在 PC `/user/invoice` 与 UniApp `pages/user/invoice` 交付开票记录及抬头管理。个人/企业、普通/专用抬头支持新增、编辑、按抬头类型和发票种类分组设置默认、确认删除；姓名、税号、手机号、邮箱和专用发票的地址、电话、开户行、账号按既有校验保存。订单详情的“订单发票”入口进入当前订单的抬头选择和补开，随后显示申请时的不可变抬头快照及待开票、已开票、拒绝状态。已有未支付申请显示等待支付，不等同于已开票。历史零金额快照显示未记录，不用退款后的订单金额代填；当前 schema 没有票据文件 URL，因此不构造下载链接。

新增买家合同通过原有 v1/v2 路由的 `view=buyer` 显式选择；旧 camelCase/snake_case 响应保持兼容。新版读写有私有不可缓存响应边界、严格字段/查询校验、最多 8 KiB 的 UTF-8 写入体、每页最多 20 条和账号绑定的游标。完整 UserJWT/旧票据桶核验在服务边界重新执行，同时读取当前 SQL 账号状态、密码版本和过期时间。只读事务使用短暂的只读 repeatable-read 快照和不放宽既有设置的 5 秒语句上限，签名图像后再次核验账号与公共投影；订单全部 TEXT 字段在 SQL 传输前限长，购物车和退款依据限行数及总字节。窗口、账号或路由变化同步清除私有资料，迟到响应与确认框不能作用于新上下文。

抬头写入沿用按 UID 的事务锁并在行锁等待后核对修订值。补开沿用原订单结算主单/履约子单锁、实际退款金额和退款物理代次核对、模板共享锁及快照复制；新合同同时绑定数据库 PK 与公开订单号，消除数字公开号与另一个 PK 的歧义，并在锁等待后重验账号、开票开关、订单及抬头修订。全部公开 HTTP 补开入口也恢复 PHP 的普通/专用开票开关检查；受信内部服务保持原先未支付申请等语义。没有新增 schema 或扩大生产角色权限。

未收到当前账号、操作和记录 ID 一致的写入确认时，只重新读取当前资料；页面说明已核对当前资料，不把读回视为该请求的持久回执。未完成的请求在页面隐藏/显示后仍会阻止第二次写入，直到请求终态并重新读取。抬头、手机号、税号和银行资料不写入持久存储。
