管理员移动订单的绝对改价已接入实时权限、事务末尾完整核对及受保护的改价凭据。改价后的普通商品和次卡收银订单可以继续重放创建、收款、消费付款事件及读取原始购买来源；本批仍属于持续 PHP → TypeScript 迁移的一部分。

本批对照 PHP 固定提交 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`，基于 TypeScript `358e99bac9825f1c762740a3a5df15025a55d141`。PHP 文件保持只读。本批没有部署，也没有向支付、短信或物流供应商发起请求。

`POST /api/admin/order/price` 保留 `order_id` 订单号、`price` 绝对金额及成功返回 `data: null` 的合同。订单号不会回退到主键。匿名、只读、停用及 Supplier 身份不能冒用平台管理员；事务前后均核验真实管理员会话和 `order.manage`。私有、禁止缓存响应在认证之前设置。

只有 `pay_price` 和累计 `change_price` 被写入。再次改价保持 `pay_price + change_price` 的原始金额，支持调高、降低和零金额。当前价格已相同的重复请求不会新增凭据、订单状态、通知或消耗审计序列。已支付、删除、重复编号、已发起扫码支付及竞争中的订单拒绝变更。原有拆单根锁与支付证据锁继续生效。

事务会冲刷延迟约束，再核对完整订单、商品 SQL 内容、全部本订单状态、通知及本次凭据；权限和扫码支付证据也会再次核对。大历史文本用 NULL/字节长度/SHA-256 绑定，不以长度拒绝普通历史订单。测试覆盖超过 256 KiB 的历史内容、无法解析的历史购物快照和未被本次改价编辑的负数小数积分。商品、积分、运费、买家、归属、删除标记及历史内容保持原值。

管理员凭据存放在独立的 `admin_order_price_operation_v1`。其 UUID、真实 actor、来源、原始/最终金额、商品哈希、状态与前序操作，在同一事务内提交。该表只允许追加和读取；更新、删除及清空被不可变触发器拒绝。PG16 物理结构、约束、索引、函数、触发器及 ACL 都有精确检查，约束摘要为 `4627d324f5ec074d72e5238c58cefcb0728ea2690eab811ae284cd3268bedbdd`。

Supplier 与管理员保留各自的凭据表。收银读取端核对完整混合链，并拒绝跨表重复 UUID、缺失凭据或查询权限。管理员改价不改购物 JSON 或积分标记，不伪装成 Supplier，也不要求平台商品具有 Supplier 归属。原始购买来源保持不可变。

改价使用 PHP 的 `order_edit` 状态与现有 `order.price.revision` 通知族。真实消费者从受保护凭据读取当前订单，只落一次短信发送意图和站内信。先前相同金额的旧通知不会重新生效；没有执行真实短信发送。

维护操作是独立、显式的 owner 事务：先完成现有基础运行角色的配置，再通过 `installAdminOrderPriceRuntime` 传入实际 Admin LOGIN 及所有读取改价来源的 App、Customer、Supplier 财务 LOGIN。新安装只向 Admin 授予新表 SELECT/INSERT，向读取角色授予 SELECT；已有 Supplier 凭据表只补本次明确声明的 SELECT。该操作调用既有的、只识别已知前代的改价通知白名单升级。已有授权缺失、未知/部分目录或漂移会失败，HTTP 不执行 DDL、授权或自动修复。该附加功能不改变整店 bootstrap、注册 ORM 群组或默认基础权限计划。基础权限映射文件保持不变，运行审计只在该精确目录存在且角色权限逐项匹配时接纳这个附加能力；App 多授 INSERT、缺少 Supplier 查询权限或目录漂移仍会拒绝；只读缺权检查通过 catalog 完成，不会因试读失败而破坏审计事务。若以后新增读取角色或装入 Supplier 凭据协议，需显式维护相应读取权限。
