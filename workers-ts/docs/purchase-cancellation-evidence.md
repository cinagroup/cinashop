## 事实与信任边界

原购凭据只证明启用后的原始购买数量，不证明订单已取消、积分已返还或额度可用。新候选在数据库内捕获真实的未付款 → 已取消转换，保留与不可变原购凭据一致的买家、类型、商品/SKU 行、数量、积分及数据库转换时间。不会复制商品完整快照、姓名、地址、电话或实时余额。

- `sopc_order_transition` 只响应状态真正变为 `-2` 的 UPDATE；有原购凭据的根单必须从未付款、未删除、未拆分且无退款状态转换。缺少原购凭据的旧单继续走原有取消服务，但不生成可信取消历史。
- 表的 INSERT 保护只允许指定转换触发器的嵌套调用，拒绝直接插入、调用方提供快照和历史补写。已经取消的单据在安装后普通更新不会补写凭据。可信来源来自受控协议的实际启用，不来自日期推测。
- 提交前的延迟约束触发器重验最终根单、无子单、完整且有界的商品行与原购行逐一相等、唯一取消日志及准确的原扣／返还积分账单。任何不一致使整笔交易失败，原服务的库存、购物车、积分、状态和凭据一起回滚。读取开放事务内的凭据不代表已提交成功。
- 凭据表拒绝 UPDATE、DELETE、TRUNCATE；业务身份只需新增精确 SELECT/INSERT，不增加序列或执行私有函数的权限。所有函数 SECURITY INVOKER、固定 `pg_catalog` search_path，触发器中的关系显式使用 public。没有 SECURITY DEFINER、运行时安装、自动补权限或网络调用。
- 数据库维护所有者和既有业务写入者仍是信任边界。此协议核验转换、原购行和账单，**不是独立的库存/优惠券补偿账本**；这些补偿仍由原有同事务服务负责。当前库存、余额、可变日志不能被当成历史独立证明。维护所有者能禁用触发器，业务写入者也有既有业务权限；不能将 `pg_trigger_depth()` 当成抵抗任意 DDL 所有者的认证。
- `cancelled_at` 是状态转换时的数据库墙钟，不是精确提交时间或额度释放时间。凭据没有“可用额度”字段，不自动允许再次购买，也不替代所有者尚未选择的累计额度恢复规则。
