# PC 站内信迁移（2026-11-15）

本批从 main `7f7832674bb6d6dd40399d92e473fbdead4a19f7` 补齐 PC 站内信：导航入口及系统未读数、个人中心入口、`/user/messages` 页面和旧 `/user/messageCenter` 路由别名、每页 7 条完整分页、展开/收起详情及失败重试。PHP 固定输入仍为 `8ed2a5b139f9170dd11b0dff91803f2fd59e40a5`，五份实际源码的逐字节哈希见机器审计。整个 PHP→TypeScript 迁移仍未完成。

PHP 的列表 GET 本身会将本页标为已读，详情 GET 也会消费单条已读状态。本批保留该行为，页面明确说明。「本次打开前未读」来自读取前同一 SQL 快照；当前未读数来自消费后的实际重读，前端不自行减数。并发新通知可使读取后的未读数增加。导航只展示系统站内信数，客服会话仍使用独立的既有客服入口。

现有三个登录 GET 新增两个显式 PC 视图：`/api/user/message?view=pc_message_summary` 仅返回版本、本人 UID 与系统未读数；`/api/user/message_system/list?view=pc_system_messages&page=N&limit=7` 返回版本、本人、查询、读取前标志、完整总量/页数及前后未读数。摘要不读客服历史、不签名头像、无写入。详情复用现有 `system_message_detail` 视图及 nullable 合同。旧默认和 Uni 视图、原 center/list/detail 方法均保留。

PC 页码独立支持正 int32 全范围，按实际总量提供首页、前后页、末页及跳转；没有沿用旧视图 1000 页造成的 7000 条截断。每个分页响应是独立数据库观察，跨请求不承诺快照。前端严格检查 UID、版本、查询、精确字段、行数、顺序和重复 ID；整包容量为 1MiB，超界失败而不截成部分成功。正文按纯文本完整显示换行，HTML 字样不会执行，时间明确按 Asia/Shanghai 显示。

PC 消费和旧入口共用同一 UID advisory lock、账号密码版本 FOR SHARE 和既有安装的私有阅读 capability。App LOGIN 仍无 `user_message` 直接写权限及序列权限，也不会修改全局广播的 look。消费之前校验整包内容；坏历史、容量或能力漂移会回滚，不留下回执或序列分配。本批没有新增 DDL、迁移、生产权限或写入权威。

前端隔离账号、会话代次、路由、隐藏/恢复、卸载和迟到响应。读取下一页失败时保留上次成功页及具体失败目标；若服务端已消费而回执丢失，未读数显示待核对，只读摘要可恢复当前计数，显式重试仍只读取原目标页。较早或并行摘要不能覆盖较新的消费计数。详情失败与不存在有明确状态，收起不发请求，重新读取按钮单独重试对应消息；独立审查发现并修复的错误状态收起行为有实际 SFC 回归。
