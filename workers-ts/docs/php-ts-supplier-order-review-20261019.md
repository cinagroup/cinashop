# Supplier 普通订单详情核对

PHP 实际订单号点击或详情操作，经 Supplier orderList、order API、Supplier/Common Order 的 order_info/tidyOrder，进入已挂载 formType1 的详情面板。本批补齐普通核对流程中的收货地址、买家留言、当前买家最小资料、历史商品/规格/编码/数量、结算参考、客户付款金额与下单表单。既有配货单是独立流程，不能用其存在代替普通详情可核对；售后详情也保留独立入口。

## 详情合同

GET `/supplierapi/order/info/:id` 增加闭合 `review`，原 snake-case 头部及 string/null `cart_info` 保持；地址、买家与表单不进入共用列表头。详情先核对实际 Supplier、系统删除及整组 cart 的 UID/type/relation，再投影；客户自己删除的历史订单仍按成熟员工历史合同可读。每行两项变量文本合计最多64KiB，最多200行，整组8MiB预算在SQL窗口计算且先于LIMIT生效；超限或核心JSON损坏明确失败。可选表单使用成熟只读历史解析器的空降级，不把数据库权限错误伪装成空数据。

收货人、电话、地址与买家留言使用订单记录。买家UID、昵称与绑定电话明确标为当前资料，不用于替换收货信息；游客、缺失或软删资料明确不可用，停用用户的资料事实不授予账户权限。数据库字符数与JavaScript UTF-16长度分开处理，合法60个emoji昵称、15个emoji资料电话及32个emoji原单号不会误阻断详情。

商品名称、SKU和编码来自下单JSON；数量及已退数取实际行，不能使用拆单前JSON中的999件覆盖子单1件。结算单价使用 `store_order_cart_info.settle_price`，以整数分精确计算，客户端只格式化金额字符串。TS的订单cost是采购成本，配货单unit_price是客户零售事实，两者都不能改名为Supplier收入。历史0008迁移曾按当时目录回填结算列，因此统一标为“结算记录参考”，不宣称所有旧值原生成交冻结，也不代表已到账。

正结算记录可以显示；零值需现代checkout/refund财务版本且无legacy来源标记，或明确旧冻结attr零证据。实际checkout的SKU JSON不含settlePrice，现代零以真实行记录与现代来源为准。带legacy来源标记的后续refund版本不能洗成现代零证据。其余旧零或空明细显示未记录，合计不提供；不回退到当前SKU、零售价或采购成本。参考运费遵循既有Supplier财务shipping_type2/4不计运费规则，客户应付运费另列；退款后的实际资金归属仍以成熟账本为准。

客户商品总额、运费、券/积分/促销/首单优惠、改价及累计退款分别显示原记录，付款标签依据paid区别应付与已付，付款时间使用pay_time。拆分前本店付款根明确标为付款汇总，不与子单重复相加。具体子单的原订单号仅返回同买家且同Supplier/门店，或已完成分配的平台根的单个编号；不返回根私有资料和外店包裹。

下单表单复用 `readOrderSystemFormForOrder`，不读取当前表单定义或共享答案表。私有图片仍须实际订单买家/受保护的代客或收银来源证明，签名使用既有Attachment实现；未授权引用被剔除。成熟历史HTTPS图片策略保持独立，不能声称该兼容路径证明任意远程图片归属。前端只渲染文本及已准入图片预览，不执行表单HTML。

所有核对查询仍在同一个短 REPEATABLE READ/READ ONLY 事务内，保留不放宽会话的5秒语句预算；不触发打印、库存、结算、分析或外部物流。旧响应缺少review时页面明确提示重新读取，已有物流/发货/备注操作保持原权限及请求代次约束。
