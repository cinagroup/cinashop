# Supplier 普通订单卡密与固定内容交付记录

PHP Supplier 列表实际挂载 formType1 普通详情，已启用的 `order/info/:id` 将认领卡密或固定内容交给“卡密发货”面板。本批在 TS 普通详情接通这条流程，沿用 `supplier.order.view`，展示该物理订单的历史交付记录。页面以纯文本保留卡号、密码、换行与原有空白；固定内容中的 HTML 和网址不会生成图片、链接或网络请求。没有增加复制、导出、重发、库存认领或付款操作。

## 读取合同

详情新增闭合 `review.virtual_delivery`：当前订单号、状态、来源、原因和条目。状态区分不适用、尚未交付、已记录及无法核对。旧服务缺字段明确提示重新读取，非法的现有字段拒绝展示并可重试。只接受当前订单类型、付款与履约状态一致的数据；付款汇总不汇集子订单秘密，子订单必须具备一致的真实父子归属。

现代条目核对受保护完整商品行与冻结 product/SKU、交付数量及该订单号/买家/order_type1 的认领卡密。卡密按精确多重集合匹配，不假设卡号或密码唯一，支持无卡号的密码卡。固定内容核对冻结 `sku.disk_info` 和记录内的商品、规格与数量；没有当前商品、当前 SKU、卡池、根或兄弟订单回退。后续退款增加退款数量时仍保留真实的交付历史，数量要求处于当前未退数量与原购买数量之间，不冒称当前权益仍有效。

旧 PHP 的裸卡号/密码数组与 `密钥自动发放：` JSON 字符串，必须有真实旧快照来源和精确的认领/冻结关联。现代来源缺少关联标识不能降级为旧格式。PHP 的 null、缺字段和字符串 `0` 属于卡密模式，现代 TS 的字符串 `0` 仍属于固定内容；旧固定内容保留前缀及原始空白。历史活动转基础 SKU 缺少不可变别名证据时返回无法核对，不查今天的活动表猜测。

全部读取在原有 RR/READ ONLY 事务中完成，事务内每条 SQL 的 `statement_timeout` 至多5秒。原完整商品集继续受200行、单行64KiB与整组8MiB限制；`virtual_info` 在 SQL 传输前限1MiB，认领卡密在 SQL 窗口求和后限1MiB、最多2000条加一条哨兵，解码后的秘密总字节也不超过1MiB。错误、缺失或不一致记录不返回部分秘密；真正的 SQL 权限故障继续失败，不伪装空记录。

三个原始快照出口（detail 的 string/null、split_order 和 split_cart_info 的对象）移除已证实的 `sku.disk_info`、`productInfo.attrInfo.disk_info` 和根 `attrInfo.disk_info`。按已授权订单或商品行任一 type1 执行，坏历史行标志不能绕过脱敏。仅复制输出，内部金融与交付核对保留原始快照；真正 type0 订单/type0 商品行的原文保留。没有宣称任意历史 JSON 的其他位置都不含秘密，打印配货 DTO 没有扩展。
