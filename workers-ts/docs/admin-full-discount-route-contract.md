## 管理合同

十个 REST 操作分别挂载 `/adminapi/marketing/full-discounts` 与 `/api/admin/marketing/full-discounts`：GET 列表、详情和商品/品牌/商品标签/用户标签选项，POST 创建、PUT 更新、PATCH 启停、DELETE 软删除。静态选项路由先于动态 ID。独立 `full_discount.view/manage` 仅承接正确配对的旧菜单 1396（`marketing-discount-full_discount` + 列表路径）、1400（`marketing-discount-add_discount` + 创建路径）；通用活动及限时折扣权限不能借用。

目录固定平台 `type=1,store_id=0,pid=0,promotions_type=3`。列表恢复名称、启停、满元/满件条件筛选、15 条分页、商品数、活动规则及支付/用户/金额统计。写入 UUID request_id，变更另带 revision；回执和业务日志隔离于限时折扣，旧版本或同键不同内容返回冲突。截止时间采用上海时区秒级字符串，并在服务器验证。

保存 `threshold_type=1`（元，最多两位小数）或 `2`（正整数件数）；`promotions_cate=1`（阶梯）或 `2`（循环）。`promotions` 的每级为 `{threshold,discount_type,discount}`，最多 100 级，门槛逐级递增，首级写根、余级写同类型平台子行。阶梯每级可 `discount_type=1` 减元或 `2` 打 0..100 的整数百分比；0% 的历史定义可回显，非整数拒绝。循环严格只有一层且只减元，与旧 UI 一致。金额上限 999999 元，金额/件数都按正数校验，循环除数不能为零。

范围为全部、具体父商品和 SKU、品牌、商品标签；排除 SKU 是旧 UI 隐藏功能的明确扩展。选品只能取审核通过、可见未删根商品及未退役身份唯一 SKU，跨页确认保留规格，取消不改原选择。付后 `label_id` 从不作为买家资格；关联与叠加开关关闭清空数组。付后标签最多100个，与支付消费者一致；限时折扣与满减满折的保存、启用及表单对101个均明确拒绝，历史异常选择保留问题提示，不静默截断。叠加只开放旧 UI 的 1（限时折扣）、2（第 N 件）、5（优惠券）。旧页没有暴露的每人限购字段不冒充该页能力。

更新仅替换同型平台阶梯子行，不把门店派生或异类型历史当优惠层级。根删除软删同 type3 一层派生，保留异类型及订单历史。已拆单原始支付根 `pid=-1` 的有效已支付记录按原根计一次，不把子单重复计入。新版快照的精确活动节省不能由平均展示单价乘数量推断；旧未版本化行保留历史回退边界。

## 实际订单消费

普通订单购物车、确认、建单与代客路径复用 `OrderPromotionQuoteService`。金额门槛按实际会员价或允许叠加后的金额聚合，件数门槛按参与件数；阶梯选择最高合格级，循环按门槛倍数减指定金额并封顶当前行额。阶梯满折沿 PHP 语义按每件截断节省，全部分配以整数分保存，不用展示均价结算。首单优惠、会员价竞争、双方叠加和券适用范围继续由同一报价合同决定。

type1 与 type3 管理共同使用已存在的目录 advisory 锁 `time_discount_catalog/platform_type_1`；名称保留，协议覆盖普通促销目录。管理 exclusive、建单 shared，锁后按数据库 wall clock 重报价，绑定变化要求重新确认；新增或启停满减活动也不能绕过目录等待。业务回执命名仍按促销类型隔离。

精确 `order-promotion-quote-v1` 分段、行额、活动分配、会员节省与促销账本进入同事务建单；支付后 outbox 才按严格标签意图赋予仍有效的平台标签。供应商分配、履约拆单与逐次退款复用这些分段保持分币一致。客服订单、供应商导出和配货单使用经校验的精确快照。

真实退款物化补充发现此前补偿历史回放仍均分 `sum_true_price`：三件59.97减4.00后实付55.97，第一件精确应退18.66而旧补偿算18.65，导致合法退款被拒绝。本批让版本化促销净额与报价、实际拆单共同使用 `partitionRefundCartSnapshot`，每次保留剩余分段；三次18.66+18.66+18.65、优惠券后18.33+18.33+18.31均守恒。现金让利仍消耗对应商品额度，末单自动回收保留原合同；冻结佣金、积分、邮费及旧无版本分配不改写，损坏新版快照仍拒绝。
