# Supplier 普通订单发票申请记录

PHP 的实际 Supplier 订单详情以formType1挂载orderDetails，invoice关系按store_order.id读取申请，面板显示发票类型、抬头类型、抬头、税号、邮箱、开户银行、企业地址和企业电话。本批将该核对流程接入TS普通订单详情，复用当前订单查看权限；平台开票、申请作者与税务服务仍由既有独立流程处理。

## 读取与显示合同

GET `/supplierapi/order/info/:id` 的 `review.invoice` 增加闭合 `state/reason/record`。`recorded` 返回唯一可核对申请，`none` 明确该物理订单没有可读申请，`unavailable` 明确重复或关联/数据无法核对且不返回税务字段。缺少该新合同的旧服务响应仍可读，页面诚实提示发票申请信息未返回；已返回但格式错误或order_id不符则拒绝展示详情，允许重新读取。

后端先复用整单的租户、当前会话、系统删除和完整cart归属核对，再在同一个REPEATABLE READ/READ ONLY快照中读取发票。查询显式选择必要列，最多两行以拒绝重复。当前物理订单、买家UID和order类别必须一致；前端再次核对精确order_id。不会读取当前user_invoice模板，也不读取或返回card_number、tell、模板ID、其他客户或兄弟订单的税务字段。税务文本按数据库Unicode字符边界与JS UTF-16容量校验；合法emoji不因代理对长度误拒绝。

优先显示唯一未归档申请；没有活动申请时可显示唯一归档申请并明确标记。归属于本店的付款汇总可核对其自身历史申请，明确金额不能与子单重复相加。子单只显示自身申请，先核对根关系，绝不借用父单发票；若子单没有自己的记录而付款汇总仍有活动申请，仅检查存在性并提示先处理归属，不返回根的税务资料。存在歧义或错误字段时不任意选取一条，也不伪装成未申请。数据库、表和权限故障仍明确失败。

页面按PHP原过滤器显示电子普通/纸质专用发票与个人/企业抬头。金额和开票状态仅展示申请中的记录，不动态修正旧零金额，不宣称税务平台验证、可开票资格或实际到账。邮箱为纯文本，不引入发信或外部跳转；归档、无申请和待核对状态均明确区分。保留普通详情已有地址/商品/表单、筛选、发货和请求代次；关闭、路由离开及账号A→B→A时不复活旧发票资料。
