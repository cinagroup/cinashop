# Supplier 普通订单具名促销分摊

PHP 实际 Supplier 普通订单以 formType1 挂载详情，`promotions_detail` 逐活动显示当前标题和本单分摊金额。本批将这条已启用流程接入 TS 订单详情，保留已恢复的 PHP `get_script` 行为及用户裁定后的退役审计。

## 读取合同

`GET /supplierapi/order/info/:id` 的 `review.promotions` 返回闭合的 `order_id/state/reason/basis/total/items`。每项仅含活动ID、类别、下单冻结名称、当前标题及分摊金额。前端再次绑定当前物理订单，以整数分核对各项之和、分摊合计和订单促销总额。旧服务未返回该字段时明确提示重新读取；返回非法结构、金额或归属时拒绝展示并可重试。

后端复用实际租户、当前会话、权限和完整商品归属核对，在同一 REPEATABLE READ / READ ONLY 事务和5秒语句预算内读取精确物理订单的促销账本。完整商品仍受200行/8MiB界限约束，账本最多600行加哨兵，SQL在传输前限制每行及整组字节。按商品和活动以整数分汇总，合法的多个SKU/账本行可共同属于同一活动；不会把正常重复活动当成重复申请。

现代分摊必须通过实际下单冻结 allocations、segments、数量与金额校验，并和完整账本、UID、商品及订单总额一致。下单冻结的是活动 `name`，PHP原面板显示当前 `title`；页面分别标注来源。当前目录只允许精确引用且 pid=0、type=1、storeId=0、未删除的平台父定义，类别仅展示可识别值。活动过期、停用或当前规则改变不重新计算历史金额；目录缺失、软删除、移店或标题非法时隐藏当前标题，保留已核实的冻结名称和金额。

没有现代证据的真实旧shape，仅在精确账本、买家、商品、合计与订单一致时标为“历史订单账本参考”，不虚构冻结名称。已识别现代财务代际缺促销证明时不得降为旧记录；旧PHP派生标记须符合成熟作者的来源值和允许代际。无账本且总额为零才显示“未记录”；错误关联、过量或证据矛盾显示“无法核对”，不泄露部分活动。SQL表或权限故障仍明确失败。

归属于本店的付款汇总仅显示自身历史记录，明确勿与子单重复相加。子单核对根关系后仍只读取自己的物理订单分摊，绝不借用根、兄弟或平台根。页面没有活动编辑、资格重算或赠品交付操作；记录不代表当前活动资格、赠品已交付或资金到账。关闭、路由离开和账号 A→B→A 后不恢复旧资料。

## 验证与边界

最终 **714项不同用例、14文件通过，88项新增**：9文件565项前端/runner，148项原生PG16及1次生产构建Browser。Supplier完整类型/构建与Worker两套完整类型通过。17份执行源分别绑定相应成功阶段的SHA；前端执行期间其他后端输入变化，仅其实际七份相关输入逐项不变，不宣称当时整个捕获集合不变。

首轮原生145项中143通过、2项真实报价因促销辅助表读取权限缺失失败，完整失败记录保留且不计最终去重数。仅给本机自有写角色补SELECT及FOR SHARE所需UPDATE(id)，并实际断言没有配额更新、INSERT或DELETE权限。独立只读复核另发现空值/未知值/代际不符的旧来源标记可能掩盖现代缺证据，按成熟作者常量收紧并增加三项反例；最终四个完整原生文件148项全部重验。

新原生包括注册的真实非零促销报价/下单、实际履约拆单和混合Supplier/平台分配，再通过独立SELECT-only LOGIN及真实Supplier App/JWT读取。测试写角色只在本机自有夹具追加所需促销目录SELECT、账本SELECT/INSERT、锁定所需UPDATE(id)及序列USAGE，未添加账本DELETE或生产角色权限。付款准入明确为合成边界，不宣称支付回调/provider验收。全部public表/序列读取前后比较，另覆盖真正42501、RR/READONLY/5秒设置、独立提交快照、现代缺证据、真实legacy来源、整数分汇总、长Unicode、过量和租户隔离。

实际Browser使用生产构建、真实App/JWT与独立只读PG16，核对现代100/201、历史301、错误关联110、未记录111及真实读取后注入503的重试恢复。33次业务GET对29表/28序列逐次零写，provider零调用，4次R2读取仅自有内存表单图片。1200×844及390×844同源iframe核对长冻结名称、当前标题、金额换行和关闭按钮；控制台warn/error采样为空。付款汇总由原生和实际编译SFC验证，现有平铺列表Browser访问具体子单，不声称覆盖根入口。3座自有PG包含初轮失败运行均清零，pid不存在且独立pg_ctl status=3确认停止。

27份实际PHP/TS源文件均独立核对基线SHA和引用区间；侦察时的候选状态明确标为历史。本批未发现新增的越末行引用。根88/404复选行逐字保持，整体迁移继续active。完整命令、源码指纹、失败记录及截图路径见[验证账本](../audit/php-ts-supplier-order-promotions-review-20261019.json)。本批通过 `codex/supplier-order-promotions-review` 及基于PR116的草稿PR发布，新提交CI以自身GitHub结果为准。
