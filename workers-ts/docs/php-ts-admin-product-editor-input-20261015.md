# Admin 商品编辑输入合同与限购草稿（2026-10-15）

本批交付完整旧保存请求的纯输入适配器，以及现有草稿接口的限购字段恢复。**商品新增、编辑、复制的完整迁移仍开放**：适配器尚未接入旧 POST，也未接入现代保存事务。新增适配器不执行 SQL、发事件、导入卡密或改变商品归属。

## 来源与合同

真正的旧商品合同是 GET／POST `/adminapi/product/product/:id`，POST 的 `id=0` 表示新增。旧 `productCreateApi`／`productEditApi` 是分类表单，不能作为商品保存依据。当前 TS 仅有该资源的 DELETE，现代新增／编辑路径仍只处理部分字段；本批没有给它们添加会悄悄丢字段的别名。

`StoreProduct::save` 的 `postMore` 有 **59 个有效字段**；`sales` 那行被注释。旧编辑器读取详情后将整个 `formValidate` 回传，所以请求可包含有界的只读／界面回显字段；适配器忽略它们，且不会将 `sales`、`pid`、`relation_id`、审核或删除状态变成写入列。完整字段表、来源 SHA256 和验证回执见[账本](../audit/php-ts-admin-product-editor-input-20261015.json)。未执行 PHP；来源结论来自固定字节的控制器、服务、Vue、模型和 ORM 静态调用链。

适配器返回下列相互独立的数据，供后续**同一已授权事务**处理：

| 输出 | 用途 |
| --- | --- |
| `normalized` | 全部 59 个字段的内部规范表示，包括关联意图；不是可再次提交给适配器的旧 wire DTO |
| `productValues` | 本批支持的主表列；不包含 owner、审核、真实销量等授权字段，也不代替 SKU 汇总或关联写入 |
| `description` | 单独描述表的内容，保留编辑字节；发布时的 HTML／素材策略仍需接入 |
| `skuPayload` | 既有稳定 SKU primitive 的完整规范输入；通过明细匹配规格，不按数组位置改写身份 |
| `cardImports` | 请求提交的卡密导入意图及请求内去重结果；是否已有由事务核对，不会自动写库存 |
| `copyMode`／`localCopy` | 采集方式与受信本地复制上下文分别处理 |

单规格使用“规格／默认”；多规格必须完整覆盖最多三维、200 个组合。金额经规范 decimal 表示；佣金、会员价、ERP 编码、实物配送、运费、预售、定时上下架、限购、参数、自定义表单和次卡核销规则均单独验证。日期沿用现有明确的上海本地时间／UTC 解析；不接受模糊自然语言时间。原服务分别检查预售两端是否早于当前时间，但未比较两端顺序，本批明确保留该差异。

支持范围与现有 SKU primitive 一致，为实物 0、卡密 1、手工虚拟 3、次卡 4。旧六步表单没有提供类型 2 优惠券履约选项；该类型的已有数据编辑仍属未完成合同，不能因字段覆盖完整就将其计作支持。

次卡的旧配送为标量 `2`，但运费仍走 `freight=1/2/3` 分支；原服务只对类型 1/2/3 强制虚拟商品运费。适配器保留该旧输入语义，尚未调用将次卡硬编码为免费自提的现代 writer；后续接入需要先解决这项合同差异。

系统表单可为数组或关联对象；两者均保留键与内容，空数组／对象按源写空文本。用户标签则需要跟到 Think ORM：服务中的 `array_column(...,'id')` 产生非 JSON 数组，`Builder::parseData` 不将其写入 varchar 主列。因此本批省略 `productValues.labelId`，新增保留数据库默认值、编辑保留历史主列；关系意图仍单独返回。`tao_words` 是有效请求字段，但安装库和 TS 主表均无对应列，只保留规范值，不伪造列。

`type` 在旧 POST 中改名为 `is_copy`，不能用它决定商品 owner 或本地复制。owner 解析保留已有非平台归属；平台／新增商品的供应商归属仍须由事务验证真实供应商。本地复制只接受调用端受信的 `localCopy`，清除 SKU 身份、固定交付内容、卡密列表、卡密库存和采集链接；实物库存保留。普通卡密保存返回独立导入意图，调用端必须锁住实际未分配卡库存再计算数量并核对已有卡密，不能直接把提交 stock 或新卡数当作现存库存。旧详情会回显历史秘密，纯适配器不能分辨它们与新输入；后续详情投影必须清除历史／已分配卡密，保存端仍需核对当前数据库。

输入合同有明确容量：实际请求最多 1 MiB UTF-8、对象深度 24、30,000 节点、字段／数组／字符串以及总卡密数量均有界。语法检查后扫描原始 JSON 的逐层解码键，在字段适配前拒绝重复与转义别名覆盖；直接调用也拒绝循环、非 JSON 对象、原型键和非有限数值。较旧缓存接口仍使用自身 512 KiB 合同，两者不混为同一容量。

## 草稿行为

现有 `/adminapi/product/cache` 增加 `is_limit`、`limit_type`、`limit_num` 三个字段。PHP 的缓存白名单也遗漏它们，这是为避免 TS 恢复草稿后丢限购设置而做的明确扩展。草稿继续允许未完成表单；不调用最终商品保存验证。现有管理员独立键、68,400 秒 TTL、UPSERT、只读过期过滤和显式删除保持。

新增测试通过实际 Hono 草稿控制器、正文读取和数据库缓存服务验证：限购各模式及关闭值、对象表单／预售／定时字段、跨管理员隔离、过期读取不删除、显式删除不影响其他管理员、超长正文拒绝保留原草稿。测试管理员上下文由合成中间件提供，不宣称真实 JWT／ACL 验收。
