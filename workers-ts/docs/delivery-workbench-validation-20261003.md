## 已实现的读取与送达合同

当前有效账号、平台配送身份和每个有效门店身份独立展示。多身份必须显式选择；重复同一身份、失效账号、禁用门店、错误范围或跨账号读取均拒绝，身份标记和 URL 参数不能产生权限。

旧 `status=2/9` 是 DAO 选择器，不能直接比较订单原始状态。待配送使用已支付、退款0/3、未删除且分配给当前配送账号的真实订单，分别展开旧配送方式和原始状态组合；已配送读取原始状态2/3。日报保留旧分配口径和上海完整年月日，不凭猜测排除父订单；父订单详情及写入另外明确拒绝。详情读取真实优惠、赠品、赠券、自定义表单、价格和联系方式；缺失坐标返回不可用与诊断，不捏造地图点。

订单12位核销码和会员码查询读取当前分配范围。会员码可返回多张真实待配送订单，不自动核销。次数商品按真实剩余数量、核销窗口和成交价格计算；部分送达保持状态5并换码，最后数量完成后复用成熟状态2与积分／佣金／供应商结算事务。

写入使用服务器锁内账号／身份／门店／订单／商品归属核验、当前版本及严格唯一数量。实际订单锁、换码锁、商品／售后锁及完整升序结算用户集合避免反向等待。业务变更、实际核销记录与原始意图收据同事务提交；结算失败时数量、金额、用户、核销记录和收据整笔回滚。

每次操作保留原始 UUID、完整不可变请求及服务器规范摘要。网络未知时不能以新请求代替旧意图；原账号可在角色撤销后只读恢复原收据，未找到保持未知。放弃、回滚拒绝和送达完成分别表达，回滚拒绝仅在实际业务事务回滚后持久化。收据只包含最小身份、结果与记录证据，无联系方式、地址或新核销码。

旧配送核销别名转入同一严格合同；旧 operator 的配送分支转至新扫码页，店员分支继续原合同。记录操作者来自实际不可变配送证据及真实商品／数量对应，不把订单旧 `delivery_id` 字段当配送人员主键。

预售能力预览使用严格 `REPEATABLE READ, READ ONLY`，与写入共用原64KiB／200行上限、快照版本、商品身份和 SQL 时钟谓词。预览无行锁，写入继续原 `FOR SHARE NOWAIT` 检查。新增已结束、尚未结束和无效快照三项真实普通 LOGIN 回归，修复前全部复现 PostgreSQL `25006`，修复后预览可读且未结束／无效快照仍禁止写入。
