# 抽奖目录、中奖记录与客服反馈旧屏合同续批（2026-09-28）

本批在既有 Worker API 上补齐三个 Admin 旧屏的本地操作合同，不新增旧 PHP URL，也不把接口注册等同于生产验收。旧 `/admin/marketing/lottery/index` 对应 `/marketing/lottery`，旧 `/admin/marketing/lottery/recording_list` 对应独立的 `/marketing/lottery-records`，旧 `/admin/setting/store_service/feedback` 对应 `/kefu/feedback`。抽奖创建页仍为部分承接：微信红包与未明确等级的奖品不能在新表单创建。旧反馈页与抽奖记录页的菜单身份仅在菜单路径和 `uniqueAuth` 同时精确匹配时映射到各自查看权限。

| 屏幕与接口 | 查看 | 管理 |
| --- | --- | --- |
| 抽奖活动 `/lottery/list`、`/lottery/detail/:id` | `lottery.view` | 活动新增、编辑、启停和删除需 `lottery.manage` |
| 中奖记录 `/lottery/record/list[/:id]` | `lottery_record.view` | `/lottery/record/detail/:id` 与发货/备注需 `lottery_record.manage` |
| 反馈 `/feedback[/:id]` | `feedback.view` | PUT 处理与 DELETE 删除需 `feedback.manage` |

这些权限在 `/adminapi` 和 `/api/admin` 两个前缀一致；抽奖活动权限不会代授中奖者记录，客服会话的 `service.view/manage` 不会代授反馈。中奖记录列表只返回 UID、昵称、活动与奖品展示快照、状态和处理备注，不返回用户电话/真实姓名、收货资料或物流号。管理详情仅额外提供已有物流公司与单号供发货弹窗预填，同样不返回收货地址和电话。前端按当前会话再次门禁，后端授权是最终边界。

抽奖目录恢复每页15条、名称或 ID、参与条件、启停及未开始/进行中/已结束筛选。列表与总数在同一个 `REPEATABLE READ READ ONLY` 事务内查询；一批聚合当前页活动的参与次数、去重参与人数及去重中奖人数，避免逐活动查询。阶段按同一秒判定；停用活动视为已结束，不限期 `start_time=end_time=0` 活动只在进行中。旧 PHP 的“已结束”条件把不限期活动也纳入，导致两个筛选重叠，新合同有意修正。旧 `lottery_win` 统计把两个数字键为0的 PHP 数组用 `+` 合并，`type>1` 条件被吞掉，可能把所有参与人算为中奖人；新合同按 `type>1` 去重 UID 计算，不能把两套旧数值说成逐字等价。旧目录的复制按钮所到创建页没有读取 `copy` 参数，这个无效旧操作不计未完成合同。

中奖记录有独立15条分页，按抽奖时间及 ID 倒序，支持活动 ID、参与条件、奖品类型、用户关键词、抽奖时间、领取和处理状态组合过滤。列表与总数使用同一只读快照；孤儿活动、奖品或用户记录不会因左关联消失。参与条件筛选覆盖该条件下所有历史活动；旧服务只定位一条启用活动，可能漏掉下架或更早活动，故这里按历史查询意图修正。时间按 Unix 秒含两端，日期控件按上海自然日转换。用户关键词可在服务端匹配旧手机号，响应仍不透露号码；因此这类搜索只授予单独的中奖记录查看角色。旧页已注释的收货资料弹窗不恢复，发货写入不依赖 Admin 读取地址。

反馈页恢复姓名/电话/内容搜索、状态与上海时间筛选、15条分页、详情、处理备注和确认删除。自定义日期兼容旧页面：结束日加一天后的 `00:00:00` 仍计入；最近7/30天采用滚动秒数。已处理反馈不可改回未处理；匿名或用户已删除的留言仍独立展示。搜索中的 `%`、`_` 和反斜杠按字面处理，避免把输入当成 SQL 通配符。反馈读响应含留言人填写的电话，所以权限与客服会话拆开。旧表具备既有 Admin 数据库 DML 权限，本批在双前缀 HTTP 层核验受限角色；尚未增加数据库级专用函数或行版本写保护。

合并专项与审计14文件83项全通过；抽奖与反馈分别在隔离 PostgreSQL16 的服务/双前缀 HTTP 两文件7项通过，临时夹具均清零并停机。Worker unit/runtime 类型、Admin 类型与生产构建、492请求变体严格 API 审计通过。分类为代码级候选，仍需真实非空配置、受限角色浏览器、历史异常记录、实际发货、生产规模、完整 Linux CI 与发布后验收。日期版逐屏台账及路由分布保留原始基线；Checklist 的开放项不会因本地候选自动勾选。
